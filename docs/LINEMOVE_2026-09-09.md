# 라인 무브먼트 — 야구에 배선하지 않는다 (실측 2026-09-09)

> **결론 먼저: 우리 데이터의 라인 이동은 정보가 아니다.** 갈림길(분기점)에
> 넣으면 유일하게 작동하는 경로에 잡음을 주입한다. 배선하지 않는다.

## 왜 물었나

`odds_snapshots` 는 경기당 20~40개의 h2h 스냅샷을 쌓는데 **야구는 한 번도
읽지 않는다** — `pipeline.py` 의 `_apply_line_moves` 가 `if ... in _BB: continue`
로 야구를 건너뛴다(축구 전용). "시장이 언제 움직였는가"를 알면 딥서치의
검색 창을 그 시각으로 좁힐 수 있다는 것이 가설이었다.

## 재료는 있다

| | |
|---|---|
| `pick_ledger.is_final` 야구 경기 | 157 |
| 그중 h2h 스냅샷 보유 | 150 |
| 시작 전 2점 이상 시계열 구성 가능 | 156/157 |

⚠️ **홈·원정 스냅샷은 `captured_at` 이 다르다**(마이크로초 5개 차이). 정확
   일치로 짝지으면 **0경기**가 나온다. 초 단위로 묶어야 한다 — 이 프로브를
   처음 짤 때 실제로 0이 나왔고, 데이터가 없는 줄 알았다.

## 그러나 정보가 아니다 — 네 가지 측정

### ① 애초에 거의 안 움직인다
```
총이동 %p   중앙 1.18 · 75% 2.77 · 90% 3.97 · 최대 14.64
156경기 중 60경기(38%)가 사실상 무이동(<1%p)
```

### ② 가장 큰 이동은 슬레이트 전체가 함께 뛴 것이다
한 사이클에서 **15~22경기가 동시에** 평균 2.3~3.4%p 이동한 구간이 있다.
정보는 한 경기를 움직이지 슬레이트를 움직이지 않는다. 개장 라인이 자리를
잡는 과정으로 본다.

> ⚠️ **오배치는 아니다 — 확인했다.** 서로 다른 두 KBO 경기가 같은 사이클에
> 같은 배당쌍(1.56/2.38 → 2.00/1.71)을 받은 사례를 보고 수집기가 배당을
> 잘못 붙인다고 의심했으나, 같은 날·같은 provider 경기쌍 **616개**의 사이클
> 동일비율은 **중앙 0.000 · 평균 0.007**, 80% 이상은 1쌍뿐이고 그것도 공유
> 사이클 5개짜리 당일 경기였다. 계통적 오배치의 증거는 없다.

### ③ 절제 실험 — 초반을 빼면 이동이 사라진다
```
전체 (시작 전)          n=212  중앙 0.96%p · >=3%p 38경기 · 방향적중 24/56 = 42.9%
초반 3개 제외           n=197  중앙 0.71%p · >=3%p 21     · 방향적중 11/35 = 31.4%
초반 5개 제외           n=177  중앙 0.71%p · >=3%p 13     · 방향적중  7/24 = 29.2%
T-12h 이후만            n=192  중앙 0.89%p · >=3%p 22     · 방향적중 17/44 = 38.6%
T-6h  이후만            n=191  중앙 0.65%p · >=3%p 11     · 방향적중  6/26 = 23.1%
T-3h  이후만            n=191  중앙 0.36%p · >=3%p  2     · 방향적중  3/13 = 23.1%
T-1h  이후만            n=131  중앙 0.00%p · >=3%p  0     · 방향적중  1/5  = 20.0%
```
🔴 **방향이 한 번도 50%를 넘지 않는다.** 전체 42.9% [29.9, 55.8] — 동전
   던지기와 구분되지 않고, 점추정은 그 아래다. 그리고 **시작에 가까울수록
   나빠진다** — "시장이 정보를 흡수한다"면 정반대여야 한다.

### ④ 괴리를 설명하지 못한다 (이게 물어본 이유였다)
```
괴리 >= 8%p  63경기 — 총이동 평균 1.84%p
괴리 <  8%p  93경기 — 총이동 평균 1.87%p
```
차이가 없다. **시장이 우리와 다르게 보는 이유는 라인이 움직였기 때문이 아니다.**
개장 시점부터 이미 다르게 보고 있었다.

## 그래서 무엇을 하는가

- **배선하지 않는다.** `_apply_line_moves` 의 야구 제외를 그대로 둔다.
- 딥서치의 검색 창은 라인 이동 시각이 아니라 **선발·라인업 공시 시각**으로
  좁힌다(DS-2 가 연 조사 경로에서 이어서 다룬다).
- 이 문서가 재측정을 막는다. 다시 재려면 위 절제 실험을 먼저 재현하라.

## 곁가지로 발견한 것

### LED-1 — `pick_ledger` 에 같은 경기의 `is_final` 행이 둘
업서트 키가 `game_id + date` 라(`pick_ledger.py:217`) **같은 경기가 다른
날짜로 판정되면 이전 행이 강등되지 않는다.**
```
is_final 행 194 · 서로 다른 경기 184 · 2행인 경기 10 (전부 trial=False)
예) g=2888  09-04 p=0.41(claude-sonnet-5) · 09-05 p=0.54(gemini-3.7-flash)
```
동결 카운터 `N/50` 은 `WHERE l.is_final AND l.graded_at IS NOT NULL AND NOT
l.void` 로 **행을 센다**(`daily_summary.py:133`) → 그만큼 부풀어 있다.
`pick_ledger` 행 기준으로 낸 적중률·AUC 도 이 10경기를 두 번 센다.

### ODS-1 — 스냅샷이 경기 시작 뒤에도 쌓인다
`odds_snapshots` 에 라이브 배당이 같은 표에 구분 없이 들어간다. 운영 경로는
`status='scheduled'` 일 때만 읽어 무해하지만, **사후 분석은 `captured_at <
starts_at` 을 직접 걸어야 한다.** 이번 프로브가 그 조건 없이 돌았을 때
"시작 301분 전"이 음수(=시작 후)로 찍혔다.
