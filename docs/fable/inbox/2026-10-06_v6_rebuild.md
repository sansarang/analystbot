4. llm.py 명세  — 호출  함수  하나
def ask(*, provider: Literal["solar","deepseek"], purpose: str,
        messages: list[Message], out: type[T], state: RunState) -> T | 
LlmFail
앱  어디서든  LLM 은  이  함수로만  부른다 . openai  SDK· httpx 로  LLM 을  직접  부르는  코드가  app/ 에
남아  있으면  빌드  실패 (§7 정적  검사 ).
Solar — 구조화  출력 (strict)
response_format={"type":"json_schema","json_schema":{"name":...,
"strict":true, "schema":...}} . Upstage 문서  규칙대로  스키마를  만든다 : 모든  object 에
additionalProperties: false , 모든  속성을  required 에  넣고 , 선택  칸은  타입에  null 을
더해  표현한다 . pydantic 의  model_json_schema()  결과를  이  규칙으로  바꾸는  변환  함수를
llm.py 안에  하나  둔다 .
경기마다  달라지는  enum 은  요청마다  스키마에  박는다 — subject 는  그  경기  두  팀  열쇠만  허용하
는  enum, doc_id 는  그  하위  과제에  넘긴  문서  id 만  허용하는  enum, type 은  그  하위  과제  담당  카
탈로그  유형만 . 모델이  다른  값을  낼  길이  없다 . 이게  " 이름  대신  열쇠 ", " 머리표  대신  도메인 ", " 자유  문
장  방향 " 같은  결함을  구조적으로  막는  자리다 .
추론  강도 : 추출 ( purpose="extract" ) 은  minimal(10-06 실측 : low 는  출력  4,000 을  추론에  다
쓰고  content 0 자 , minimal 은  추론  0·content 3,519 자 ). 다른  용도는  녹화본으로  실측해  정한다 . 값

finish_reason == "length" 이면  실패로  처리 ( 사유  llm_truncated ) — 잘린  JSON 을  고치
려  하지  않는다 .
DeepSeek — 공식  문서를  읽어  지원  모드를  확인하고  결과를  config 에  적는다 . JSON 스키마  강제를

검증 · 재시도 — 응답을  out.model_validate_json() 으로  검증 . 실패하면  검증  오류  문장을  붙여  1 회
