수정 지시서 — 상성을 뿌리로 (코드 흐름도 점검 결과 반영)

━━ 0. 목표 ━━
지금은 "상성이 확률의 유일한 출처"까지 섰다. 이번 목표는 "상성이 뿌리"다:
 - 들어가는 길: 딥서치·라인업·변수가 전부 상성 재료(⑫)와 상성 판정(⑬)으로 모인다.
 - 다시 자라는 길: 확정 XI가 오면 상성부터 다시 계산한다.
 - 나가는 길: 가설·검증·판정·평이 전부 상성 결론에서 뻗어 나가고, 상성 밖 정보는 확률·등급을 몰래 바꾸지 않는다.
판정 계산의 원칙(C1~C12)은 그대로. 순서·연결·이중 계산·옛 경로를 고친다.
단계마다: 계약·테스트 먼저 → 구현 → 초록 → 커밋 → 한 줄 보고. 묻지 말고 끝까지.

━━ 1. 목표 흐름 (이 순서로 코드를 맞추고 흐름도도 실제 줄 번호로 다시 그린다) ━━
 ① 질문 → ② S0 경기 확정
 → ③ S1 딥서치: 구조 사실 · 라인업 사다리 · 새 사실 72시간 · 기사 문서
 → ④ 깃발(turnover: 오늘 경기 명단 기준·r)
 → ⑤ 추출·사실 검증 → 변수(VariableSet)
 → ⑥ 배치(routing): axis0~3 · lambda_const · V1~V6 · hypo
 → ⑦ 전략 판정(오늘 XI ↔ 평소 XI, 배치된 축 변수·깃발 입력)
 → ⑧ 상성 재료(골 내용·스타일·폼·규칙 T1~T13) — 변수·r·전략을 입력으로
 → ⑨ 상성 판정(MatchupReport: 축별 홈 공격/원정 수비·원정 공격/홈 수비 특징, 종합 우위·강도)
 → ⑩ 가설 세우기(상성 우위 기준, 시뮬 숫자 없음)
 → ⑪ 확률(λ홈·λ원정 → 분 단위 시뮬)
 → ⑫ 검증(가설 신호 ↔ 시뮬, V1~V5 반대 원인 분류, 등급 조정)
 → ⑬ 시나리오(시뮬 분포에서, 표시용)
 → ⑭ 보드 판정(생존 = 시뮬 확률)
 → ⑮ 최종 평(LLM 1회 + 검열 1회)
 → ⑯ 카드
 Elo(V1)·시장(V6)은 ③ 단계에서 받아 두되 ⑫ 검증·카드 표시로만 간다.

━━ 2. 고칠 것 — 우선순위 순 ━━

[F1] 확정 XI 재분석 때 상성부터 다시 (가장 먼저)
 - reanalyze: 확정(또는 2매체 보도) XI가 들어오면 ④ 깃발부터 ⑯까지 전부 다시 돈다.
   재사용은 ③의 기사 문서·⑤의 기사 추출 결과만(검색·LLM 추출 비용 절약). 구조 사실·라인업·새 사실 72시간은 다시 받는다.
 - "상성·시뮬 그대로, 시나리오 필수형 보강만" 경로 삭제.
 - 카드 머리: "🔁 확정 XI 반영 — 바뀐 것: 상성 축(전→후)·확률(전→후)·등급(전→후)".
 - 계약 R1: 같은 경기에서 XI가 예상→확정으로 바뀌면 MatchupReport 해시가 다시 계산된다(같은 XI면 같은 해시).
 - 돌연변이: 재분석에서 ⑦~⑪ 건너뛰기 → 빨강.

[F2] 변수·깃발·전략이 상성 재료로 들어간다
 - 순서: ⑦ 전략 판정을 ⑧ 상성 재료보다 먼저.
 - ⑧ 입력 시그니처: (ref, facts, varset_axis, turnover, strategy). 
   · 결장·징계 변수 → 그 선수가 쥔 무기(크로스·세트피스·역습·공중볼 등) 꺼짐, 복귀 변수 → 켜짐
   · 교체 운용 선수(선발 비율 30% 미만) → 후반 무기
   · turnover r → 폼·골 내용·스타일 집계에서 과거 경기 가중
   · 전략(수비 위주·3백 전환 등) → 스타일 6축 조정
 - 규칙 T1~T13 발동은 이 조정된 재료로 판정한다.
 - 계약 R2: 결장 변수가 있는데 그 선수의 무기가 켜진 채로 규칙이 발동하면 실패.
   계약 R3: turnover 팀의 폼·골 내용 계산에서 r 가중이 적용됐다(경기별 가중 기록이 MatchupReport에 남는다).
 - 돌연변이: ⑧에 varset 안 넘기기 / r 무시 → 빨강.

[F3] 확률 식 — 이중 계산 제거, 홈·원정 분리
 - 규칙 효과는 축 안에서 한 번만. ⑪에서 "규칙 λ를 따로 더하는" 항 삭제.
 - λ 식을 명시하고 코드도 그대로:
   log λ홈  = 리그 평균(로그) + 홈 이점 + 대회 상수 + Σ_축 β_축 · (홈 공격 특징_축 − 원정 수비 특징_축)
   log λ원정 = 리그 평균(로그)          + 대회 상수 + Σ_축 β_축 · (원정 공격 특징_축 − 홈 수비 특징_축)
   축마다 공격 쪽·수비 쪽 특징을 ⑨에서 따로 낸다(축 종합 숫자 하나로 두 λ를 만들지 않는다).
 - home_mul(홈 이점)은 lambda_const 자리 변수만 받는다.
 - 시간대·경기 상태 배율(축3)은 시뮬 안에서만.
 - 계약 R4: 같은 규칙 id가 λ 계산 경로에 두 번 나오면 실패. R5: λ홈 식에 원정 공격 특징이 들어가면 실패(반대도).
 - 🔴 임시 계수 표시 유지(적합 전).

[F4] 시장·옛 세 열 규칙 제거
 - compare.grade_step에서 시장(V6) 입력 삭제. 시장은 카드 표시만(C12).
 - s7_judge의 _lower(세 열 규칙) 삭제. 등급 조정은 ⑫ 검증 규칙(5-3: 상성 사각 hard 반대·가설 지지 0)만.
 - 계약 R6: 시장 배당을 바꿔도 등급·확률이 같다.

[F5] 보드 생존 = 시뮬 확률
 - ⑭ 생존은 ⑪ 스코어 분포에서 직접 계산(승무패·핸디·오버 1.5/2.5/3.5·보드 기준선).
 - 시나리오(⑬)와 필수형 보강 갈래는 표시용 — 생존 계산에 안 쓴다. reweight는 시나리오 무게 표시용으로만.
 - 계약 R7: 보드 생존 = 시뮬 확률(소수 넷째 자리). 시나리오 갈래를 추가·삭제해도 생존이 같다.

[F6] 가설 순서 — 실제 호출 순서로 확인
 - 현재 흐름도에서 가설 세우기(pipeline:348)가 검증(:319)보다 뒤에 적혀 있다. 실제 호출 순서를 찍어 보고.
 - 가설 세우기를 ⑨ 상성 판정 직후·⑪ 확률 앞으로 옮긴다. 입력: MatchupReport + VariableSet(hypo 자리) — 시뮬 출력 없음.
 - 상성 우위 팀 기준: 주 가설(우위 팀 승리 경로) 2~3개, 반대 가설(열세 팀이 뒤집는 변수) 2~3개. 우위 없음이면 양 팀 각 2개.
 - 계약 R8: 가설 세우기 호출이 확률 계산보다 먼저(호출 순서 테스트). C3 유지.

[F7] 글 단계 통합 — 상성 결론에서 한 편
 - 논평(s9_audit 작성)·이유 문단(s8b)·전술 예측(s2f)·최종 평(s9_say) → 최종 평 한 번(작성 1회 + 검열 1회).
 - 출력 칸: 헤드라인 한 줄 / 이유 문단 / 전술 예측(팀별 예상 운영·흐름·승부처) / 핵심 3줄 / 뒤집히는 조건.
 - 첫 줄은 상성 판정(우위 팀·강도) + 검증 요약. 근거 id ⊂ 지지된 가설·MatchupReport·VariableSet. 결론 방향 = 확률 방향.
 - 계약 R9: 카드 안 LLM 글 생성 호출이 경기당 작성 1·검열 1(재작성 시 +1)을 넘지 않는다.

[F8] 라인업 사다리·새 사실 72시간을 흐름에 드러낸다
 - ③에 하위 단계로 명시: 라인업 사다리(fotmob 경기 → ESPN HTML → 리그 공식 관찰분 → 기사 2매체), 상태(확정/보도/예상/없음)·출처·시각.
   🔔 라인업 알림(사용자가 누른 경기만 5분 간격) → 확정 시 F1 재분석.
 - 새 사실 72시간을 ③의 별도 하위 과제(F)로: 팀별 현지어+영어, 고정 출처(구단 공식 뉴스·리그 프리뷰), turnover 팀은 "전역·신병 합류·이적" 질의 추가.
