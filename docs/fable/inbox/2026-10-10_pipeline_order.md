# 파이프라인 순서 재편 지시서 — "찾고 → 세우고 → 시뮬레이션 → 검증 → 평"

🔴 **사용자 지시 2026-10-10(다섯째).** 받은 글을 **그대로** 둔 것이다 — 옮겨 적으며
고치지 않는다(CLAUDE.md: *"지시문은 파일로 넣는다. 옮겨 적지 않는다"*).

---

목적: 지금은 가설·시나리오를 LLM이 먼저 그리고 확률이 그 뒤를 따라가거나 따로 논다. 순서를 바꾼다.
① 딥서치로 재료(가설·변수·상성)를 먼저 모으고 ② 가설을 "시뮬레이션이 보여야 할 신호"로 세운 뒤 ③ 데이터 시뮬레이션을 돌리고
④ 가설이 시뮬레이션 결과로 지지되는지 검증하고 ⑤ 검증을 통과한 가설만으로 최종 평을 쓴다.
판정 계산 로직(모델·계수)은 바꾸지 않는다 — 단계의 순서와 연결만 바꾼다. 묻지 말고 끝까지.

━━ 단계 1. 수집 (딥서치 먼저) ━━
1-1 구조 사실: 경기 확정, 라인업(사다리), 결장·복귀, 순위·경우의 수(게이트), 일정·이동.
1-2 딥서치: 새 사실 72시간(B), 감독 발언, 선수단 변동(전역·이적·징계), 현지어+영어.
1-3 상성 재료: 보정 폼(축1), 스타일 6축·오늘 XI 변화(축2), 골 내용 프로필(축3, 분모 포함).
산출: 사실 묶음(id 붙음). 이 단계에서는 확률을 계산하지 않는다.

━━ 단계 2. 가설·변수 세우기 (시뮬레이션 전) ━━
2-1 변수: 사실 묶음에서 변수를 만든다(기존 s5 규칙·무게표·중복 금지·근거 불가 분리 그대로).
2-2 가설(LLM 1회, 구조화 출력): 팀마다 "이긴다면 왜" 2~3개, "무너지는 조건" 2~3개. 각 가설은 반드시 시뮬레이션으로 확인할 수 있는 신호를 단다:
   {가설 문장, 근거 변수 id, 예측 신호 = 지표·방향·기준}
   예) "부천은 오늘 골을 넣기 어렵다" → 신호: 부천 기대득점 < 리그 평균의 70% / 부천 무득점 확률 > 35%
   예) "후반 강원 우위" → 신호: 후반 득점 비중 강원 > 부천, 61분 이후 강원 득점 확률 > 부천
   예) "김천 새 선수단은 리드를 못 지킨다" → 신호: 김천 선제골 후 승리 확률 < 리그 평균
   쓸 수 있는 지표 목록은 코드가 준다(기대득점·무득점 확률·시간대 득점·선제골 후 결과·스코어 분포·승무패·오버). 목록 밖 지표 금지.
2-3 시나리오는 여기서 만들지 않는다(단계 4에서 시뮬레이션 결과로 만든다).

━━ 단계 3. 시뮬레이션 (데이터 모델) ━━
- 입력: 변수(적합된 효과만, 임시값 표시), 축1·축2·축3, 선수단 교체 처리(기준 항 가중 r·호흡), 동기 상태, 확정 XI.
- 분 단위(또는 같은 구조의 해석 계산)로 스코어 분포 → 승무패, 오버 1.5/2.5/3.5, 시간대 득점, 선제골 후 결과, 무득점 확률, 기대득점.
- 가설 문장은 시뮬레이션 입력이 아니다(LLM이 확률을 못 움직인다는 원칙 그대로).

━━ 단계 4. 검증 (가설 ↔ 시뮬레이션) ━━
4-1 가설마다 예측 신호를 시뮬레이션 출력과 대조(코드): 지지 / 반박 / 판단 불가(지표 없음·표본 부족).
4-2 반박된 가설은 원인을 코드가 분류한다:
   (a) 입력 누락 — 가설의 근거 변수가 시뮬레이션에 안 들어갔다(계수 없음·게이트 차단 등) → 그 사실을 표시
   (b) 기준 낡음 — 한쪽이 squad_turnover·감독 교체 직후·핵심 3명 이상 결장 → "기준 낡음 의심" 표시
   (c) 가설 오류 — 근거 사실이 약하거나 시뮬레이션과 정면으로 반대 → 가설 기각
4-3 재실행은 최대 1회: (a)는 그 변수의 효과가 적합돼 있는데 빠졌을 때만 넣고 다시 돈다. (b)는 기준 항 가중을 규칙대로(r·호흡) 다시 계산해 한 번 더 돈다.
     적합값이 없는 변수를 검증을 맞추려고 임의로 넣지 않는다. 재실행 뒤에도 반박이면 그대로 둔다.
4-4 시나리오 생성: 시뮬레이션 스코어 분포 상위 묶음(승·무·패별로 1~2개)을 시나리오로 삼고, 각 시나리오에 그 결과를 지지하는
     검증된 가설과 변수를 붙인다(전개 문장은 LLM, 근거는 지지된 가설·변수 id만).
4-5 산출: 가설 검증표 — 가설·신호·시뮬 값·판정(지지/반박/판단 불가)·반박 원인.

━━ 단계 5. 최종 평 ━━
- 최종 평(직전 지시서)은 지지된 가설과 그 근거만 쓴다. 반박된 가설은 "🔄 뒤집히는 조건" 후보로만.
- 판단 불가 가설은 평에 쓰지 않는다.
- 기준 낡음 의심이 있으면 평 첫 줄에 그 사실을 적는다.

━━ 카드 ━━
1겹: 헤드라인 → 📊 확률(시뮬) → ⚔️ 상성 → 🧪 가설 검증(지지 n · 반박 n — 한 줄씩 상위 3개) → 🧑‍🏫 최종 평 → 보드 판정.
긴 카드: 가설 검증표 전체, 재실행 여부와 이유, 시나리오별 지지 가설.

━━ 계약 ━━
- 단계 순서: 단계 2(가설)는 단계 3(시뮬) 결과를 입력으로 받지 않는다(가설이 결과를 보고 쓰이면 실패).
- 가설마다 예측 신호가 있고, 신호 지표가 허용 목록 안.
- 재실행 ≤ 1회, 재실행 사유 기록.
- 최종 평의 근거 id ⊂ 지지된 가설·변수.
- LLM 출력이 확률을 바꾸지 않는다. 단계별로 수정해라...
