# 🔴🔴 수정 지시서 — 예측 엔진 교체 + 경기 직전 상태 (배선 포함 · 통합본)

> 사용자 지시 2026-10-12 — **원문 그대로**(옮겨 적으며 고치지 않는다)

배경: 444경기 백필에서 새 구조(Elo 바닥 + 축0·축1)가 Elo만을 이겼다. 이 지시는 새 구조의 뼈대(바닥 점수 → 보정 → λ → 시뮬)를 유지한 채
그 안의 부품을 후보로 시험해 나은 것만 교체하고, 경기 직전 상태(휴식·일정·결장의 무게·벤치·정보 공백)를 더한다.
실사고(10-11): 광주 4-3 울산(광주 28경기 무승 · 3주 휴식 후 홈 · 울산 2연패), 가와사키 1-2 나고야(가와사키 주전 2명 부상 · 직전 컵 일정 · 나고야 교체 선수 결승골).
두 경기 모두 봇은 과거 성적으로 판단했고 경기 직전 상태를 몰랐다. 축구에서 흔한 경우다.

━━ 0. 원칙 ━━
- 손대는 곳은 확률 8단계뿐: ③ 구조 사실 · ④ 깃발 · ⑦ 변수 배치 · ⑧ 신원 검문 · ⑪ 상성 재료 · ⑬ 상성 판정 · ⑯ 확률 · ⑲ 되돌림.
  예외: 12절(정보 품질)은 ㉑㉒ 등급에만 붙는다(확률 불변).
  나머지(⑭⑮⑰⑱⑳㉔)는 동결 — 입력 이름이 바뀌는 곳만 따라 고친다.
- 모든 변경은 "후보 판"으로 먼저 만든다. 운영 확률은 현 새 구조(probfloor) 그대로 두고, 백필 판정을 통과한 판만 운영으로 승격한다.
- 모든 계수·학습률은 날짜 판(walk-forward)으로 저장: data/<표>/<as_of>.yaml. 로더는 as_of 이전 최신 판만. 손값 금지(없으면 🔴 + 확률 미산출).
- 과거 자료는 전부 fotmob.before_as_of 를 지난다(L1). 현재 상태 입구(시즌 누계·결장 명단·명부)는 재현에서 경기 단위 재합산만(L2).
- 확률에 들어가는 건 실측·백필로 이득이 확인된 숫자만. 확인할 수 없는 것(기사·사유·동기)은 등급·표시로만.
- 단계마다: 계약·테스트 먼저 → 구현 → 초록 → 커밋 → 한 줄 보고. 묻지 말고 끝까지. 결과 보고 전 판정 규칙을 바꾸지 않는다.
- 실사고 두 경기에 맞추려고 계수를 고치지 않는다. 적합은 백필 전체로만.

━━ 1. 평가 지표 (먼저 고친다 · tools/backfill_score.py) ━━
- 주지표: 로그 손실. 병기: RPS · 방향 적중률 · 상위 30/20/10% 선택 적중률(같은 경기 수) · 브라이어(참고).
- 비교는 전부 짝지은 차이 + 부트스트랩 95% 구간. 리그·시즌별.
- 평가 표본: J1·K1 두 시즌(현 580경기 재생분). 적합은 시즌 A, 평가는 시즌 B — 그리고 반대(교차). 같은 데이터로 적합·평가한 수는 보고 금지.
- 판정 규칙(고정): 후보가 기준보다 로그 손실 구간상 낫다 → 채택. 구간이 0을 품는다 → 단순한 쪽 유지. 나쁘다 → 폐기.
- 하위 그룹 보정표 도구 추가(11절에서 사용): 그룹별 평균 예측 − 실제, 구간.
계약 E1: 적합 기간과 평가 기간이 겹치면 실패.

━━ 3. 확률 변환 (⑬ 상성 판정 · ⑯ 확률) ━━
[모듈] app/core/probfloor.py 개편 — 손값 β 삭제.
   log λ홈  = b0 + b1·diff + b2·player_diff + h_league [+ 9절 채택 항]
   log λ원정 = b0 − b1·diff − b2·player_diff        [+ 9절 채택 항]
   (player_diff 는 4절 전까지 0으로 고정, 계수 b2 없음)
   그 위에 Dixon-Coles ρ(리그별) → 스코어 격자 → 승무패·오버·핸디·BTTS 전부 같은 격자에서.
[적합] tools/fit_probfloor.py --league --as-of — 포아송 최대우도(시간 감쇠 가중, 5절), b0·b1·b2·h_league·ρ 동시 적합, 판 저장 data/probfloor/<league>/<as_of>.yaml.
   h_league 는 기존 홈 이점 실측 판과 비교 기록(따로 곱하지 않는다 — 이중 계산 금지).
[배선]
   ⑬ matchup.report: 입력을 facts.rating.diff + player_diff 로 바꾼다. 축2·축3은 report 에 관찰값으로만 남기고 합산 제외(이미 결정).
   ⑯ probmodel.run: λ를 probfloor 가 주고, 분 단위 시뮬은 그 λ로 돈다. 상태별 배율(앞섬·동점·뒤짐)과 10절 벤치 항(60분 이후)은 시뮬 안에서만, 정규화로 팀 평균 득점 λ ±2% 유지.
   ProbOut 에 기록: λ홈·λ원정·diff·player_diff·채택된 일정 항·계수 판 날짜·ρ.
[카드] 확률 블록: "λ 1.62/1.08 ← diff +0.60·b1 0.31 · 선수 차 0.00 · 홈 +0.07 · 일정 −0.03 · ρ −0.08 · 판 2026-10-11"
계약 P1: ⑯ 에서 λ를 만드는 식이 probfloor 하나. 다른 곳이 λ를 곱하면 실패(시뮬 내부 상태·벤치 배율은 정규화 조건 하에서만 예외).
계약 P2: 오버·핸디·승무패가 같은 격자 합(소수 넷째 자리). P3: 홈 이점이 h_league 외 경로로 들어가면 실패.

━━ 4. 선수 점수 (⑦ 변수 배치 · ⑧ 신원 검문 · ⑪ 상성 재료) ━━
[모듈] app/core/ratings/player_pm.py — 플러스마이너스(릿지).
   데이터: 경기마다 선발·교체 분(in/out)·골 시간(fotmob 경기 페이지, before_as_of). 이미 받는 경기 페이지 캐시 재사용.
   구간 분할: 교체·골 시점으로 경기를 구간으로 자르고, 구간마다 (팀 득점 − 실점)/90분 을 응답, 그 구간 출전 선수 ±1 을 설명변수로.
   릿지 회귀(λ 백필 적합) → 선수 점수. 출전 분 < 300 은 리그·포지션 평균 쪽으로 수축(가중 = 분/(분+K)).
   판 저장 data/player_pm/<league>/<as_of>.parquet.
[배선]
   ⑧ 신원 검문 통과 XI(선수 id)만 받는다 — 이름 문자열 금지. 검문 실패 → player_diff 미산출 → 카드 "선수 점수 — 라인업 신원 미확정".

      예상 XI 단계에서만 결장 변수(부상·징계 hard)가 예상 XI 를 고친다(결장 선수를 예상 XI 에서 빼고 평소 대체자를 넣는다) · 카드 "예상 XI 기반".
   ⑪ s2e_matchup: player_diff = mean(홈 XI 점수) − mean(원정 XI 점수) → TeamRead.player_mean, MatchupReport.player_diff.
      기존 축0(가치 로그합)은 후보 비교용으로 함께 계산·기록하되 확률 경로는 4절 판정 결과를 따른다.
   ⑲ 되돌림·F1 재분석: 확정 XI 가 오면 player_diff 를 다시 계산 → ⑬⑯ 재실행(이미 있는 경로).
[비교 판] 바닥만 / 바닥+현 축0 / 바닥+player_diff / 바닥+둘 다 — 로그 손실·상위 20% 선택 적중률.
[카드] "선수 점수 차 +0.11(홈 XI 평균 +0.08 · 원정 −0.03) · 수축된 선수 3명(출전 분 부족)"
계약 PL1: player_diff 계산에 오늘 경기 정보(결과·이후 경기)가 들어가면 실패. PL2: 신원 미확정 선수가 점수 0으로 들어가면 실패(평균 대체 + 🔴).

━━ 5. 시간 감쇠 · xG (④ 깃발 · ⑪ 상성 재료) ━━
- 3절 적합(fit_probfloor)·4절 선수 점수·10절 usual_xi 에 지수 가중 w = exp(−ξ·경과일) 적용, ξ(반감기) 백필 적합. 판 저장.
- 축1 폼(최근 10경기 고정 창)은 ξ 가중 폼으로 교체 후보 — 바닥 점수에 이미 최근성이 들어가면(pi) 폼이 추가로 이득을 주는지 비교. 이득 없으면 축1 확률 경로에서 제외.
- ④ turnover 깃발: r 가중은 유지하되 선수 점수가 들어가면 중복 여부 비교(선수 점수가 교체를 이미 반영하면 r 를 끈다).
- xG 있는 리그: pi-ratings 를 골 차 대신 xG 차로 갱신하는 판 추가(pi_xg). 양 팀 xG 없는 경기 → 골판으로 대체 + 표시.
계약 T1: 같은 최근성 효과가 바닥 점수와 폼에 이중으로 들어가면 경고(비교표에서 이득 없을 때 폼 제외).

━━ 6. 경기 직전 상태 공변량 — 휴식·일정·휴식기 (후보 판 · ③ → ⑬⑯) ━━
[모듈] app/core/context.py 신설 — 전부 before_as_of 를 지난 경기 목록에서 계산(리그+컵+대표팀 차출 기간 포함).
   ContextRow{team_id, as_of,
     rest_days            : 직전 공식 경기(리그·컵 전부)부터 킥오프까지 일수
     load_14d             : 최근 14일 공식 경기 수
     load_7d_cup          : 최근 7일 컵 경기 수
     break_days           : 직전 리그 경기부터 일수(A매치 휴식기 등 감지)
     league_n_since_break : 휴식기 이후 리그 경기 수
     travel_km            : 직전 경기 장소 → 오늘 장소(구장 좌표 표, 없으면 ⬜)
     streak_len, streak_kind : 연속 무승/연패/연승 길이(확률 입력 아님 — 8절 검증용)}
[적합 후보] probfloor 식에 하나씩 추가해 비교(3절 식 위에):
   log λ홈  += c1·clip(rest_home − rest_away) + c2·(load_14d_home − load_14d_away)
   log λ원정 += c1·clip(rest_away − rest_home) + c2·(load_14d_away − load_14d_home)
   휴식기 효과: diff → diff·(1 − c3·post_break) — 휴식기 직후에 점수 차의 설명력이 줄어드는지 검정
     post_break = 1 if 양 팀 중 하나라도 break_days ≥ 14 이고 league_n_since_break = 0, else 0
   rest 는 0~10일로 자른다(clip). 계수는 시간 감쇠 가중 최대우도, 판 저장 data/context_coef/<league>/<as_of>.yaml.
[배선]
   ③ s2_facts.run: ContextRow 두 개 → facts.context.
   ⑬ matchup.report: 관찰값으로 기록(합산 아님).
   ⑯ probfloor: 채택된 항만 λ 식에 들어간다. 채택 안 된 항은 식에 없음(0).
   ⑰ V3(일정)는 유지하되, 채택된 항이 확률에 들어가면 V3 사유에 "확률에 반영됨(c1·c2·c3)" 표시 — 이중 해석 금지.
[카드] "일정: 홈 휴식 21일(휴식기 후 첫 경기) · 원정 휴식 3일 · 14일 내 경기 1 vs 4 · 반영 c1 +0.02/일 · 판 …"
계약 C6-1: ContextRow 계산에 킥오프 이후 경기가 들어가면 실패. C6-2: 채택 안 된 항이 λ에 닿으면 실패. C6-3: 컵 경기를 빼고 rest_days 를 세면 실패.

━━ 7. 결장의 무게 · 벤치 강도 (후보 판 · ⑦⑧⑪ → ⑬⑯) ━━
[원칙] 결장은 "누가 빠졌나"의 질로 센다. 이름 수가 아니다. 근거는 4절 선수 점수.
[모듈] app/core/ratings/lineup_strength.py
   usual_xi(team, as_of)  : 최근 리그 N경기 출전 분 가중 상위 11명(id) — 시간 감쇠 가중
   absence_loss           : Σ(usual_xi 중 오늘 XI 에 없는 선수 점수) − Σ(그 자리에 들어온 선수 점수)  [팀별]
   absence_reason         : 부상·징계·로테이션·미상 — 구단 공식 발표·리그 징계·기사 2매체(⑦ 변수) · 확률 입력 아님(표시)
   bench_mean             : 오늘 벤치 중 점수 상위 5명 평균(없으면 ⬜)
[적합 후보]
   (a) player_diff 만(4절) — 기준
   (b) + absence_loss 차 — player_diff 가 이미 담는지 검정(이득 0이면 버린다 = 중복)
   (c) + bench_mean 차 — 시뮬에서 60분 이후 λ 에만: λ_60+ ×= exp(d1·bench_diff) — 백필로 d1 적합, 정규화로 경기 전체 λ ±2%
[배선]
   ⑧ 신원 검문 통과 XI·벤치만 사용(벤치 id 미확정 → bench_mean ⬜, 확률 항 0).
   예상 XI 단계: 4절과 같은 규칙으로 예상 XI 구성 → player_diff·absence_loss 계산.
   확정 XI 도착 → ⑲ 재분석으로 다시 계산.
   ⑦ 부상 발표가 킥오프 뒤(예: 가와사키 10-12 발표)면 재현에서 쓰지 않는다(L1) — 운영 카드에선 "명단 제외(사유 미상)" 그대로.
[카드] "결장의 무게: 홈 −0.21(CB 0.14·MF 0.09 빠짐 → 대체 +0.02) · 원정 −0.03 · 벤치 상위5 홈 +0.01 / 원정 +0.06"
계약 C7-1: 결장 선수 수로 확률을 움직이면 실패(점수 기반만). C7-2: 벤치 항이 60분 이전 λ 에 닿으면 실패.

━━ 8. 연속 기록 과잉반영 점검 (검증 전용 · 확률 경로 아님) ━━
목적: "28경기 무승" 같은 기록이 바닥 점수를 과하게 끌어내리는지 확인. 연속 기록 자체는 확률 입력으로 넣지 않는다.
[측정] 백필 하위 그룹별 보정표(예측 vs 실제):
   streak_len ≥ 5(무승/연패 팀) · post_break 경기 · load_14d ≥ 4 팀 · 신규/승격 팀 · 감독 교체 후 5경기 이내(⑦ coach_change, 날짜 있는 것만)
   각 그룹에서 봇이 그 팀 승률을 체계적으로 낮게/높게 보는지(평균 예측 − 실제, 구간).
[조치 규칙(고정)]
   한 그룹에서 구간상 체계적 편향 → 그 그룹 변수를 6절 공변량 후보로 올려 같은 판정 절차를 밟는다(직접 보정 금지).
   편향 없음 → 아무것도 안 넣는다.
   2절 학습률·5절 시간 감쇠 재적합 시 이 그룹표를 함께 보고한다.
계약 C8-1: streak_len 이 λ 식에 직접 들어가면 실패.

━━ 9. 정보 품질 점수 → 등급 (㉑㉒ · 확률 불변 · 백필 판정 불필요) ━━
목적: 카드 재료가 비어 있으면(결장 미확보·새 사실 0·벤치 미확정) 같은 확률이라도 믿을 근거가 약하다. 확률은 그대로, 등급만 낮춘다.
[모듈] app/core/infoquality.py — InfoQ 0~5점(코드 계산, LLM 금지):
   +1 확정 XI(양 팀 id 확정) · +1 결장 사다리 한 칸 이상 성공(양 팀) · +1 새 사실 72시간 ≥1건(양 팀 합)
   +1 ContextRow 완전(rest·load 양 팀) · +1 벤치 id 확정
[배선]
   ㉑ 보드 판정·㉒ 반증 판정 뒤에 적용: InfoQ ≤ 2 → 등급 한 단계↓ + "조건부" 이상 불가 · 빠진 칸을 방아쇠로 자동 등록.
   InfoQ 는 확률·λ·생존에 닿지 않는다.
   운영 카드 저장: InfoQ 와 최종 확률 → score_cards.py 가 InfoQ 구간별 적중률을 따로 채점.
[카드] 머리 줄: "정보 품질 2/5 — 결장 미확보 · 새 사실 0 · 벤치 미확정 → 등급 한 단계↓"
계약 C9-1: InfoQ 가 확률 경로에 닿으면 실패. C9-2: InfoQ ≤ 2 인데 "간다"가 나오면 실패.
