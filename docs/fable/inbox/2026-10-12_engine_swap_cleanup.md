━━ 0. 배경 · 설계 원칙 ━━
배경
- 444·460경기 백필: 과거 자료만 쓴 Elo도 무작위보다 확실히 낫다 → 과거 자료에는 바닥 실력 정보가 있다.
- 실사고(10-11): 광주 4-3 울산, 가와사키 1-2 나고야 — 봇이 놓친 건 전부 "경기 전에 확인 가능했던 오늘의 사실"(휴식·부상·일정·벤치)이었다.
- 반대로 가설·상성 이야기·전술 예측(LLM)은 확률을 못 바꾸고, 과거 경기에 다시 만들 수 없어 맞는지 잴 방법이 없다.
- 광주 재현 가설 문장에 근거에 없는 "4-3"이 나왔다 — LLM 서술 단계는 누설 위험까지 있다.

설계 3층 (이 지시의 뼈대)
   [1층 바닥]  과거 자료 → 팀 기본 실력(바닥 점수). 과거는 실력을 재는 데만 쓴다.
   [2층 오늘]  경기 전에 확인 가능한 사실 → 보정(누가 뛰나·결장의 무게·휴식·일정·벤치). 여기에 힘을 쏟는다.
   [3층 운]    경기 전에 아무도 모르는 것(그날 몸 상태·판정·마무리 운) → 모델링하지 않는다. 받아들이고, 운의 몫이 큰 경기는 걸러 낸다.

원칙
- 확률(λ)에 들어가는 건 1·2층의 숫자 중 백필로 이득이 확인된 것만. 검증 불가 = 확률 불가.
- LLM 은 사실 추출(기사 → 결장·복귀·라인업 사실)에만 쓴다. 판단·예측·서술로 확률·등급을 움직이지 않는다.
- 새 구조의 뼈대(바닥 → 보정 → λ → 격자·시뮬) 유지, 부품은 후보로 시험해 나은 것만 교체.
- 모든 계수·학습률·문턱은 날짜 판(walk-forward) data/<표>/<league>/<as_of>.yaml. 로더는 as_of 이전 최신 판만. 손값 금지(없으면 🔴 + 확률 미산출).
- 과거 자료는 fotmob.before_as_of 를 지난다(L1). 현재 상태 입구는 재현에서 경기 단위 재합산만(L2).
- 실사고 두 경기에 맞추려고 계수·문턱을 고치지 않는다.
- 단계마다: 계약·테스트 먼저 → 구현 → 초록 → 커밋 → 한 줄 보고. 묻지 말고 끝까지. 결과 보고 전 판정 규칙을 바꾸지 않는다.

━━ 11. 판정 행동 · 정보 품질 · 역배 표시 (㉑㉓ · 확률 불변 · 즉시 적용 가능) ━━
