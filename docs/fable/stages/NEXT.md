`draw_possible` 을 **출처와 함께** 선언했다. 모르는 리그는 **만들지 않는다**.

### ⚠️ 그래도 NHL 은 지금 멈춘다 — 두 가드가 함께 일한다

```
격자를 못 만들었다 — 홈/원정 쪼갠 표가 min_venue_games(8) 에 못 미친다(개막 17번째 경기)
→ 격자가 없으면 파생 스코어도 못 뽑는다 → 시나리오를 지어내지 않는다
```

🔴 **이것이 맞는 동작이다.** 거짓 λ 로 거짓 스코어를 만들지 않는다. 시즌이 8경기쯤
진행되면 선다.

⚠️ v4 §9 단계 4·§10 이 *"정답지 재현율 80%"* 로 적혀 있다 — **그 게이트는 기준을
잃었다.** 지난 수치(29% → 14%)도 이제 아무것도 뜻하지 않는다. 서명 보고서 §2 에 적었다.

### 그래서 기준은 하나다 — **경기 결과**

| 묻는 것 | 어디 |
|---|---|
| 카드가 규격의 블록을 내는가 | `test_output_spec.py` 를 **규격 ↔ 카드 렌더러**로 고쳤다 |
| 우리가 적은 것이 맞았나 | `survive.grade()` → `ledger` · `python -m app.scheduler score` |
| 그때 그 결과에 얼마를 줬나 | `result_probability` — 교정의 재료 |
| 결과를 아예 안 그렸나 | `realized_scenario_id` 가 `NULL` — **가장 값진 기록** |

🔴 셋을 섞지 않는다: *맞았다* · *틀렸다* · **예측을 안 했다**(카드 없는 경기는 `건너뜀`).
🔴 채점이 예측을 고치지 않는다(§3 불변) — 계약이 그것을 잠근다.

### 실측 — 끝까지 돌렸다(실제 결과 3-2)

```
채점   결과 3-2 → realized **D**(난타전) · 이름 적은 마켓 0 중 0 맞음
원장   원정 승 ✗ · 홈 승 ○ · 오버 2.5 ○ · 언더 2.5 ✗
```

🔴 **읽는 법**: 맞는 시나리오를 그렸고(D), 오버 2.5 도 맞았을 것인데 **이름을 아무것도
적지 않았다.** 한 경기로는 아무 말도 못 한다 — 그래서 쌓는다.

🔴 `ledger` 가 `NOT_WIRED` 에서 빠졌다. 그리고 이 원장이 **λ 보정 계수를 재는 길**이다.
