## 1. 결정 — §0 절대 전제는 **지킨다**

사용자 2026-09-30: *"질문형 봇이다 — 지켜야 하니 걷어야 하니?"* → **지킨다.**

| 왜 | 근거 |
|---|---|
| 질문형이 §0 을 **더** 필요하게 만든다 | 배치에서 얇은 경기는 목록에 묻힌다. 질문형은 **사용자가 그 경기를 콕 집어 기다린다** — 뭔가 내놓으라는 압력이 최대이고, 그때 지어낸다(09-28 세르비아 2부가 그 모양이다) |
| 걷어도 못 쓴다 | 변수 2개로 시나리오를 만들면 반대 시나리오가 없어 생존이 **1.0 으로 계산된다.** §7 R5(변수 3개 미만 → 자료 부족)가 막지만, 그러면 질문마다 "자료 부족"이 나온다 |
| 걷을 필요가 없다 | §9 가 게이트 미달의 처방을 직접 적었다 — *"소스 지도·**예산 보강**으로 돌아간다"*. 예산을 늘리는 것은 v4 를 **따르는** 것이다 |

🔴 **고치는 것은 §0 이 아니라 §12-d 다.**

> §12-d(v3) — 세포 하나가 슬레이트 전체 예산을 먹지 않게 **경기별 예산 고정**,
> 잔여만 재분배

이것은 **배치 가정**이다. 20경기를 고르게 돌려야 해서 묶어 둔 것이다. 질문형은
경기가 하나다 — 같은 예산을 한 경기에 몰 수 있다.

**실측이 그것을 가리킨다** (2026-09-30, 필수 8건 ⑤ 세이부 라인업):

```
검색 결과 36건을 받았다
열기 예산 3건을 쓰고 소진        ← 맞는 기사는 그 36건 중에 있었다
남긴 사유: "본문 예산소진 (36건 중 일부만 열었다)"
```

🔴 **못 찾은 게 아니라 예산이 끊긴 것이다.**

## 2. 정답지 — 20경기가 아니라 1경기다 (숨기지 않는다)

§10 은 *"경기 20건·변수 약 150개"* 를 말하고, 그 출처를 *"이 채팅의 각 경기
분석문에서 페이블이 별도 yaml 로 뽑아 준다"* 로 적었다. 🔴 **그 채팅은 이 저장소에
없고, 페이블이 정하는 것은 사용자 지시 2026-09-30 으로 없어졌다.**

→ 정답지는 **사용자가 주는 경기로만 자란다.** 지금 있는 것:

| 경기 | 파일 | 무엇이 있나 |
|---|---|---|
| 새크라멘토 vs 라스베이거스 (USL) | `docs/fable/golden/2026-09-30_sac_lv.md` (원문) · `docs/fable/golden_v4.yaml` (구조) | 변수 **9건**(on 7 · unknown 2) · 확인 사실 **17건** · 기준 XI **22명** · 폼 수치 **13칸** · 시나리오 5 · 방아쇠 4 |

⚠️ **1경기로 잰 수치를 20경기 수치로 적지 않는다.** 보고서에 *"정답지 1/20 경기"*
를 함께 적는다(조용한 0 금지).

## 3. 게이트 — 숫자로

### 3-a 변수 재현 (주 게이트)

| 지표 | 식 | 1경기 기준 **통과선** |
|---|---|---|
| 재현율 | 재현한 on 변수 ÷ on 변수 | **≥ 80%** → 7건 중 **6건** |
| 방향 오류 | 방향 틀린 변수 ÷ 재현한 변수 | **≤ 5%** → 7건에서 **0건** |
| 출처 없는 변수 | 출처 URL 없는 채택 변수 | **0** |
| 경기 후 기사 혼입 | 킥오프 이후 발행 기사에 기댄 변수 | **0** |
| 🔴 미상 규율 | `state: unknown` 변수(R8·R9)를 봇도 **unknown + 사유**로 낸다 | **2/2** |

🔴 **"변수 1건 재현"의 정의** — `must_find` 항목을 **전부** 찾고 방향이 같다.
(느슨한 집계 — 과반만 — 도 보고서에 **함께** 적는다. 게이트는 엄격한 쪽이다.)

🔴 **미상에 값을 채우면 실패다.** §11-4 가 같은 말을 한다: *"정답지의 ✘ 경기는
봇이 '없음'을 내야 통과"*. 재현이 아니라 발명이기 때문이다.

### 3-b 폼 수치 재현 (보조 게이트)

변수가 아니라 **재료**다. 그러나 못 찾으면 R1~R9 가 서지 않는다. 13칸 중 **≥ 80%
(11칸)**. 🔴 못 찾은 칸은 **이름으로** 남긴다 — 0 으로 메우지 않는다.

### 3-c 필수 8건 (v4 가 못 박은 것 — 살아 있다)

2026-09-30 실측 **1/8**. 전에 *"3건은 잴 자료가 없다 — 사용자에게 물었다"* 고 적었다.
🔴 **그 물음을 걷는다.**

사용자 지시 2026-10-01:

> 내가 변수를 찾아야 해? 어떻게 내가 전문가도 아닌데 변수를 찾아야 하니??
> 변수를 알아서 자동으로 생성을 해야지

맞다. 그리고 **날짜는 이미 정본이 준다** — §10 제목이 *"정답지 (09-27\~29 실전
데이터)"* 다. 창이 **사흘**이다:

| 못 잰 건 | 묻지 않고 어떻게 구하나 |
|---|---|
| ③ 모리야스 "대폭 변경" | 모리야스는 **일본 감독**이다 → ② 와 **같은 경기**(우루과이–일본) |

### 4-1. 🔴 4-Q-3 에서 **계약 자체가 구멍이었다** — 그것을 먼저 메웠다

`app/extract.py` 는 2026-09-30 에 만들어졌고 **부르는 곳이 없었다.** 그런데
`tests/test_wiring.py` 의 고아 계약은 **초록이었다.**

이유: 계약이 호출을 **이름으로** 셌다. 다른 모듈의 `run(` 이 `used["run"]` 을
올려 줘서 `app.extract.run` 이 이어진 것처럼 보였다.

⚠️ **같은 병을 전에 한 번 고쳤는데 또 걸렸다.** 2026-09-30 리뷰 B2 가
`app.cassette.index` 를 찾아냈고(`cells.index(pos)` — **리스트 메서드**가 가려
줬다), 그때 막은 방법은 *파이썬 기본 자료형 메서드 이름은 이름만으로 인정하지
않는다* 였다. 🔴 **`run` 은 기본 자료형 메서드가 아니다 — 그 방어를 그냥 지나갔다.**

→ **이름 가리기를 버리고 귀속으로 바꿨다.** 호출을 `app.모듈.함수` 로 귀속시킨다:

| 규칙 | 예 |
|---|---|
| `from app.X import fn` 뒤의 맨 `fn` | `app.X.fn` 에 센다 |
| `from app import X` 뒤의 `X.fn` | `app.X.fn` 에 센다 |
| 그 파일이 스스로 정의한 이름 | 자기 모듈에 센다 |
| 표를 거친 호출 (`ADAPTERS[league].sources_slate(...)`) | **그 파일이 들여온 모듈 중 그 이름을 가진 것**에 센다 |
| 어느 것도 아니면 | **아무 데도 안 센다** |

🔴 손으로 유지할 목록이 **0** 이다 — 귀속은 import 문에서 자란다.
그리고 `test_배선_세기_자체가_동작한다` 가 **세는 장치 자체**를 잠근다(리뷰 B1 이
잡은 *동어반복 계약*을 되풀이하지 않기 위해).

바뀐 뒤 고아는 **정확히 한 건** 나왔다 — `app.extract.run`. 그것이 진실이었다.

### 4-2. ⚠️ 측정 위생 — **스테일 `.pyc` 가 거짓 측정을 만든다**

4-Q-4 를 돌연변이로 검증하다 겪었다. `max(` ↔ `min(` 은 **글자 수가 같다.**
파이썬의 `.pyc` 무효화는 (**mtime · 크기**)로 판단하므로, 크기가 같고 mtime
초가 겹치면 **고친 코드가 아니라 옛 바이트코드가 돈다.**

실측: 복구한 뒤에도 `budget_for(4, fetches=3, mode=QUESTION)` 이 `3` 을 냈다
(옳은 값은 `20`). 코드를 열어 보면 `max` 였다.

🔴 **4-Q-7 측정 전·돌연변이 검증마다 `__pycache__` 를 지운다.**

```bash
find . -name __pycache__ -type d -not -path "./.venv/*" -exec rm -rf {} +
```

⚠️ 이것은 거짓 **빨강**보다 거짓 **초록**이 무서운 자리다 — 돌연변이를 "계약이
잡았다"로 잘못 읽으면 잡지 못하는 계약을 믿게 된다.

둘이 어긋난다. 사실은 이렇다:

```
User-agent: anthropic-ai   Disallow: /        ← 앤트로픽의 크롤러
User-agent: *              (대부분 허용)      ← 우리 UA 가 걸리는 줄
우리 UA: "AnalystBot/3.0 (sports analysis; contact via telegram)"
```

🔴 **코드가 맞다.** 우리는 이름을 숨기지 않고 `AnalystBot` 이라고 밝히며, ESPN 의
`*` 규칙이 우리를 허용한다. 절대규칙 3 이 금지한 것은 *"프록시·UA 위장"* 이고,
정직하게 다른 이름을 쓰는 것은 위장이 아니다 — **다른 주체이기 때문이다**
(학습용 크롤러가 아니라 사용자 본인의 분석 봇).

⚠️ 그러나 이것은 **내 해석이고 규칙 해석은 사용자가 정한다**(지시 2026-09-30).
   사용자가 *"ESPN 은 쓰지 마라"* 고 하면 `net.mark_dead` 한 줄로 막는다.
   → `docs/fable/questions/2026-10-01_espn_robots.md`

🔴 `site.api.espn.com` 은 **다르다.** robots.txt 자리가 Access Denied 라 **허가를
확인할 수 없다.** 그 자리는 쓰지 않는다 — 우리 규약은 *"읽을 수 없으면 허용"* 이나
그것은 robots 가 **없는** 경우를 뜻하고, **거부로 답하는** 자리는 아니다.

⚠️ USL 공식 사이트의 일정·순위는 **`secure.widget.cloud.opta.net` 위젯**이다 —
Opta 상용 피드다. 긁지 않았다. 순위(R2)는 다른 길을 찾아야 한다.

| 결함 | 고친 것 | 계약 |

| 아무 기사의 인용이나 받는다 | 팀 언급 필수(`_names_hit`) — 🔴 `cisa.gov` 가 막힌다 | `test_intent_attribution.py` |

🔴 **시간 상한의 산수** — 이것이 질문형이 배치와 다른 **두 번째** 지점이다:

사용자가 *"예측해줘"* 하고 44분을 기다릴 수 없다. **개수만 올리면 못 막는다.**

### ⚠️ 그리고 **내 가드가 세포를 조용히 죽였다**

`queries.SPORT_QUESTIONS` 에 `"coach_change"`·`"live"` 라고 적었다. **둘 다 없는
이름이다** — 감독 교체 세포는 `intent` 를 쓰고(`subject` 에 `:coach` 를 붙여 id 만
가른다) 라이브는 `live_score` 다. 그래서 녹음이 **감독 교체 세포를 "축구에 없는
질문"으로 건너뛰었다** — §4 `coach_change` 의 보기가 *"조지아 사뇰 사임"*(축구!)인데도.

🔴 **"조용한 0"을 막으려 넣은 가드가 조용한 0 을 만들었다.** 원본(`cells.Q_TYPES`)을
읽지 않고 이름을 지어낸 값이다 — 이 저장소가 반복해 다친 자리 #1(사본 금지) 그대로다.

③ 녹음 도구가 쓰는 이름 ⊆ `Q_TYPES` ④ 모르는 이름은 **막지 않고 적어 둔다**
(오타 하나가 세포를 없애지 않게).
