## 🔴 설계에서 지킨 것 — **값을 규칙이 정한다**

v4 §3 마지막·§14-5 는 `direction`·`weight`·`strength`·`survival`·`verdict` 에
LLM 출력이 닿으면 계약 실패라고 한다. 단계 1 의 계약은 그것을 **문자열로** 봤다
(`app/llm.py` 소스에 `"weight ="` 이 있나) — 우회된다. 단계 2 는 **규칙으로** 닫았다:

| 칸 | 무엇이 정하나 |
|---|---|
| `weight` | `hardness` 가 정한다 — `WEIGHT_OF = {hard: 1.0, likely: 0.7, soft: 0.4}` (§4). 어긋나면 저장 실패 |
| `verdict` | `survival` 이 정한다 — 1.0 만 `name`, 0.8 이상만 `small` (§6). 어긋나면 저장 실패 |
| `direction` | `Literal["home","away","draw","over","under"]` (§1). 값 집합 밖은 없다 |
| `survival` | `Field(ge=0.0, le=1.0)` |
| `strength` | 음수 거부 |
| `Sufficiency.verdict` | **수가 정한다** — 방향 변수 3 미만 또는 반대 0 이면 `insufficient` (§1) |

🔴 **그래서 LLM 이 그 칸에 값을 흘려 넣을 수 없다.** 이름을 안 쓰는지가 아니라
**아무 값이나 넣을 수 없는지**를 본다.

## 🔴 배당은 **금칙 목록 없이** 막았다

모든 모델이 `extra="forbid"` 다(`_Strict`). 그래서 `odds`·`price`·`배당`·
`payout`·`decimal_odds`·**무엇이든** 스키마에 없는 칸이면 그 자리에서 터진다.

⚠️ 손으로 유지하는 금칙 이름 목록을 만들지 **않았다.** 이 저장소가
*"손으로 유지하는 목록은 언제나 한 발 늦는다"* 고 적어 둔 자리다 —
`extra="forbid"` 는 목록보다 **넓다.**

## 🔴 경기 후 기사 판별은 **베끼지 않고 불렀다**

§3: *"published_at 이 경기 이후면 저장 실패(v3 §12-c 검증기 그대로)."*
