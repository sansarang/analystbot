# 갈림길 — **NHL 플레이오프 경계를 어떻게 읽나** (2026-10-02)

## 어쩌다 나왔나

사용자 지시 *"돌려라"* → 라이브 실측에서 §4 `stakes` 가 미결정으로 떨어졌다:

```
미결정: 플레이오프·강등 경계를 모른다 — 순위만으로는 걸렸는지 못 판단한다(리그마다 다르다)
```

축구(fotmob)는 `legend[].indices` 로 경계를 **자료가 알려 준다**(MLS → 9위).
USL 은 `legend: null` 이라 **모른다**. NHL 은 그 칸이 아예 없다.

## 🔴 NHL 응답이 주는 것 — 그리고 주지 않는 것

`api-web.nhle.com/v1/standings/now` 한 줄에 이런 칸이 있다:

```
divisionSequence      디비전 안 순위
conferenceSequence    콘퍼런스 안 순위
wildcardSequence      와일드카드 순번
```

⚠️ **"몇 위까지 진출인가"는 응답에 없다.** NHL 규칙은 *디비전 상위 3팀 + 콘퍼런스별
와일드카드 2팀* 인데, 그 **3 과 2 는 리그 규정이고 자료가 아니다.**

🔴 그래서 지어내지 않았다 — `playoff_cut: None` 으로 두고 §4 가 미결정을 낸다.

## ✅ 닫혔다 — **사용자 지시 2026-10-02**: *"수정해라"* → **안 B**

`config/playoff_cuts.yaml` 에 **출처와 확인 날짜를 붙여** 선언했다.

```
NHL  division_plus_wildcard · 디비전 상위 3 + 와일드카드 2
     출처 nhl.com/info/standings-and-playoff-format · 확인 2026-10-02
```

⚠️ **사본 금지와 충돌하지 않는다.** 사본 금지는 *시스템에 이미 있는 사실*을 손으로
옮겨 적지 말라는 것이다. 리그 규정은 **우리 자료 어디에도 없다** — 그래서 선언이
맞고, 선언에는 출처가 붙는다.
🔴 **자료가 알려 주는 리그는 적지 않았다**(축구 fotmob 의 `legend`) — 적으면 사본이 된다.
🔴 **모르는 리그는 사유를 적었다** — USL(legend null)·NPB(클라이맥스 시리즈 구조).

안 A(`wildcardSequence` 만 읽기)를 버린 까닭: 그 칸은 **순번**이고 *"몇 장인가"* 를
말하지 않는다. 와일드카드가 2장이라는 것을 알아야 `3` 을 `진출`로 읽는다.

실측 — 경계가 서자 변수가 늘었다:
```
전: 변수 2개(travel_schedule·home_field) · 방향 1종 → §7 R5 자료 부족
후: 변수 4개 (stakes 가 **양 팀** 다 선다) · 방향 2종 → **R5 통과**
🔴 그리고 다음 벽이 드러났다 — §5-b 에 'hockey' 템플릿이 없다
```

## 〔지난 판〕 아래는 **닫히기 전**에 적어 둔 것이다 (A~C)

⚠️ 읽을 때 주의 — 여기 남은 `⏳` 는 **그때의 표시**이고 지금은 닫혔다.

| 안 | 뜻 | 대가 |
|---|---|---|
| **A** `wildcardSequence` 를 경계로 읽는다 | `1~2` 면 진출권, 그보다 크면 밖 | 자료가 직접 주는 값이다. ⚠️ **개막 직후에는 뜻이 없다**(전 팀이 0~1경기) |
| **B** 리그마다 경계를 yaml 에 적는다 | NHL `디비전 3 + 와일드카드 2` 처럼 | 🔴 **사본이다** — 규정이 바뀌면 따라가지 않는다 |
| **C** 그대로 둔다 | `stakes` 는 하키에서 영영 미결정 | 변수 하나를 못 쓴다 — 지금 NHL 은 변수 2개로 §7 R5 에 걸린다 |

⚠️ **사용자 지시 2026-09-30**(*"규칙 해석도 사용자가 정한다"*)에 걸리는 자리라
   내가 고르지 않는다.
