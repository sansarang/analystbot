## ⑫ 는 섰다 — 그리고 **빈 결과를 냈다**

방아쇠의 꼴은 *"**무엇이 보이면** → **무엇이 바뀌고** → **상한 얼마**"* 셋이고,
자동화는 그 셋을 전부 **이미 있는 것에서** 뽑는다. 지어낸 숫자가 없다:

| 칸 | 어디서 |
|---|---|
| 무엇이 보이면 | 변수 하나가 **거짓으로 드러나는 것** |
| 언제 | §4 유형의 `watch` → `cells.WAKE` 의 깨는 시각 |
| 무엇이 바뀌고 | 그 변수를 **빼고 §5 를 다시 돌린** 결과 |
| **상한 얼마** | 그 상태로 **§6 을 다시 돌린** 생존·등급 |

**반사실 재계산 한 번이 방아쇠 한 줄이다.** 그런데 정답지 경기에서 돌리니:

```
변수 11개를 **하나씩 전부** 빼 봤다  →  등급 변화 **0건**
```

## 🔴 원인 — 확률 무게가 변수를 **끊어 놓았다**

실측으로 못 박았다:

```
          strength        확률(포아송)
전       A 4.6 B 2.2      A 0.1844 B 0.0930
변수 1개 뺀 뒤  A 4.2 B 2.2      A 0.1844 B 0.0930   ← 🔴 **한 치도 안 움직인다**
```

포아송 격자는 **순위표(홈/원정 쪼갠 표)에서** 나온다. 변수와 아무 관계가 없다.
→ 무게가 확률이면 **변수를 아무리 모아도 생존·등급이 안 바뀐다.**

🔴 **그런데 v4 §0 은 정확히 그 반대를 전제한다:**

> 변수 개수·정확도 = 시나리오 품질

즉 지금 구조에서는 **딥서치로 변수 150개를 모으는 일이 결론에 아무 영향이 없다.**
변수가 하는 일은 *어느 시나리오가 **존재하나***(방향 묶음)와 *가설·방향 판정*뿐이다.

⚠️ 같은 변수로 **strength 무게**로 돌리면 등급이 움직인다 — 원인이 무게임을 계약이
못 박았다(`test_확률_무게에서는_변수가_등급을_못_바꾼다`).

🔴 **이것은 내가 세 턴 전에 만든 문제다.** *"근거 개수는 확률이 아니다"* 는 딥서치의
답이 옳았지만, 확률을 **리그 표에서만** 끌어오면 변수가 끊긴다는 것을 못 봤다.

## ✅ 닫혔다 — **사용자 지시 2026-10-02**: *"수정해라"*

### 🔴 답: **D** — 그리고 A 를 막은 것은 딥서치다

A(변수가 λ 를 움직인다)를 지으려면 **보정 계수**가 필요하다. 찾아봤다:

> 선수 결장이 팀 기대득점을 **몇 % 낮추는가**에 대한 **발표된 계수가 없다.**
> xG 연구는 *선수 능력 보정*(위치·슛 질)에 몰려 있고, 결장의 크기는 각 구단
> 내부 분석에 남아 있다. 공개된 수치는 포지션별 xG 조정 ~14% 정도이고 그것은
> **결장 계수가 아니다.**

🔴 **그래서 계수를 지어내면 그것이 전부 거짓이 된다.** 절대 문턱 `3.0` 의 잘못을
되풀이하는 자리다. 계수가 없으면 A 는 **지을 수 없다.**

⚠️ 그렇다고 B·C 로 갈 수도 없다 — B 는 무승부 과소평가로 돌아가고(실측: 16.2% 가
5.1% 로 보였다), C 는 적정 채점 규칙을 깨서 `0.8` 이라는 선의 뜻을 없앤다.

### 🔴 그래서 §0 의 전제를 **이렇게 읽는다**

```
v4 §0  "변수 개수·정확도 = 시나리오 품질"
→ 변수는 **어떤 이야기가 가능한가**(시나리오 집합·방향·가설·방아쇠)를 정한다
→ 확률은 **그 이야기들의 무게**를 정한다(리그 표에서 나온다)
```

⚠️ **v4 문서를 고치지 않았다** — 정본은 `export` 로 받은 파일이고 손으로 못 고친다
(CLAUDE.md §사본 금지). 이 읽기는 **사용자 지시로 선 해석**이고 여기 적힌다.

🔴 **변수가 하는 일은 여전히 크다** — 실측으로 보인다:
```
NHL 경기: 변수 2개 → 자료 부족(§7 R5 로 멈춘다)
          변수 4개 → R5 통과 · 시나리오 생성으로 넘어간다
```
즉 변수는 **카드가 나오는지 안 나오는지**를 정한다. 등급을 못 움직이는 것과
아무 일도 안 하는 것은 다르다.

### 🔴 언제 A 를 짓나 — **짓지 않는다** (사용자 지시 2026-10-02)

전 판에 *"채점이 쌓인 뒤 측정해서 짓는다"* 고 적었다. **그 탈출구는 닫혔다:**

> 쌓이는거는 우리 로직이 맞냐 틀렸냐만 **검증하는 방법으로만** 사용한다..

🔴 원장으로 계수를 맞추는 것이 금지다. 발표된 계수도 없다. → **A 는 없다.**
그래서 이 결정은 **D 로 끝났고**, §0 의 읽기(변수는 이야기를, 확률은 무게를)가
임시가 아니라 **최종이다.**

⚠️ 기계가 그것을 막는다(`test_원장으로_규칙을_고치지_않는다`).

## 〔지난 판〕 아래는 **닫히기 전**에 적어 둔 것이다 (A~D)

⚠️ 읽을 때 주의 — 여기 남은 `⏳` 는 **그때의 표시**이고 지금은 닫혔다.


### A. **변수가 λ 를 움직이게 한다** (딥서치가 가리키는 길)

실제 모형은 결장·휴식·감독 교체를 **공격비·수비비 보정**으로 넣는다. 그러면 변수가
확률에 닿고 §0 이 되살아난다.

```
λ_home = 공격비(홈) × 수비비(원정) × H × (1 + Σ 홈 변수 보정)
```

⚠️ **보정 계수에 실측 근거가 없다** — *"주전 공격수 결장 = 득점 몇 % 감소"* 를 재려면
경기별 자료가 쌓여야 한다. 🔴 지어내면 전 판의 잘못(절대 문턱 3.0)을 되풀이한다.
→ 할 수 있는 정직한 판: **계수를 `0` 으로 두고 칸만 만들어 두고**, 채점(§9 단계 8)이
   쌓이면 그 자료로 맞춘다. 그때까지 ⑫ 는 *"근거만 움직인다"* 를 그대로 적는다.

### B. **무게를 §5-d(근거 개수)로 되돌린다**

변수가 즉시 생존에 닿는다. ⚠️ 그러나 딥서치가 못 박은 문제로 돌아간다 — 무승부가
두 번째로 그럴듯한데 정규화 5% 이고, `0.8` 이라는 선이 아무것도 뜻하지 않는다.

### C. **둘을 곱한다** — `무게 = 확률 × (근거 합 ÷ 전체 근거)`

변수도 닿고 확률도 산다. ⚠️ **적정 채점 규칙이 아니다** — 더 이상 확률이 아니므로
`1.0 / 0.8` 의 뜻이 또 흐려진다.

### D. **그대로 둔다**

확률이 등급을 정하고, 변수는 *시나리오 구성·가설·방향 판정*만 한다. ⚠️ 그러면 §0 의
전제를 **문서에서 고쳐야** 한다 — *"변수는 어떤 이야기가 가능한지를 정하고, 확률은
그 이야기들의 무게를 정한다"* 로.

🔴 **내 판단으로는 A(계수 0 으로 칸만) + D(문서 수정)가 맞다.** 그러나 §0 은 이
프로젝트의 절대 전제이고, 그것을 고치는 것은 **사용자만** 할 수 있다.
