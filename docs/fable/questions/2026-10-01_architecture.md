# 구조 — **서버가 미리 분석하고, 질문은 꺼낸다** (2026-10-01)

## 사용자 지시 원문

> 내가 원하는 거는 **기존에 서버에서 분석을 하고 있다** .. 사용자가 경기를 질문을
> 한다 .. 아까 내가 보여준 **결과물대로** 사용자에게 답변을 줘야 한다

앞선 지시(같은 날)와 이어진다:

> 서버에서 당일 날짜 및 그다음 날짜 터울은 하루, 어떤 경기가 있는지 저장이 되어
> 있어야 한다 … 그러면 사용자가 경기에 대해 질문을 했을 때 **바로 답할 수 있고**,
> 아니면 너가 그 경기들을 **미리 예측해서** 대답을 해줄 수가 있다

## 🔴 내가 잘못 잡고 있던 것

| 내 첫 판 | 🔴 사용자가 말한 것 |
|---|---|
| 사용자가 물으면 **그때** 딥서치한다 | 서버가 **미리** 분석해 둔다 |
| 사람이 기다리니 **빨라야** 한다 | 질문은 **조회**다 — 분석은 이미 끝났다 |
| → 깊은 분석에 **90초** 상한을 걸었다 | → 깊은 분석은 **밤새 돌아도 된다** |

⚠️ 90초 상한의 전제가 틀렸다. 깊이를 조일 이유가 없는 경로에 조임을 걸었다.

## 고친 것 — 모드가 **셋**이다

| 모드 | 누가 기다리나 | 열기 예산 | 시간 상한 |
|---|---|---|---|
| `SLATE` | 아무도 | 경기별 **고정**(§12-d 원문) | 없다 — 개수가 작다 |
| `DEEP` | 🔴 **아무도** — 서버가 미리 | **20** (몰아준다) | **300초** |
| `ASK` | 🔴 **사람** — 묻고 기다린다 | **20** (같다) | **90초** |

🔴 **깊이는 같고 시간만 다르다.** 열기까지 줄이면 `ASK` 가 *다른 분석*이 되고,
같은 질문에 두 가지 답이 생긴다. 계약이 그것을 잠근다.

🔴 `ASK` 가 왜 남나: 미리 분석되지 **않은** 경기를 물을 수 있다(슬레이트 밖이거나
아직 안 돈 경기). 그때는 얕더라도 빨리 답하고 *"아직 깊이 분석되지 않았다"* 를
함께 적는다(§19-b-6).

## 산수 — 서버가 슬레이트를 다 돌 수 있나 (실측)

```
한 경기 실측(세포 4개)   검색 8건 · 열기 43건 · 직렬 951초
슬레이트                 31경기 (NHL 16 · MLB 8 · NPB 7, 2026-10-01 이후)
```

🔴 **평균이 아니라 분산이 문제였다**:

```
새크라멘토  네 세포에 19초
라스베이거스 라인업 한 세포에 15분 51초   ← 느린 호스트 20건을 직렬로 기다렸다
```

상한을 걸면 그 꼬리가 잘린다. 상한 300초로:

| | 한 경기 최악 | 31경기 |
|---|---|---|
| 지금(세포 **직렬**) | 20분 | **10.3시간** — 하루엔 들어가나 여유가 없다 |
| v4 §12-d 가 요구하는 **병렬** | 5분 | **2.6시간** |

→ 🔴 계약이 *"`DEEP_SECONDS` 를 올려 반나절을 넘기지 못하게"* 잠갔다. 넘기면 분석이
못 끝난 경기를 사용자가 묻게 되고, **그것은 조용한 실패다.**

## 🔴 진짜 벽 — 검색 용량 (사용자 결정이 필요하다)

병렬로 가면 요청이 몰린다. 그런데 **이미 엔진 넷이 정지 중**이다(실측 2026-10-01,
내 녹음이 유발했다):

```
brave        Suspended: too many requests
duckduckgo   CAPTCHA
qwant        CAPTCHA
google cse   Suspended: too many requests   ← 비용 잠금으로 꺼져 있다
```

필요량: 31경기 × 검색 8건 = **하루 248 질의** (이틀치면 두 배).

| 선택 | 무엇 | 비용 |
|---|---|---|
| ① 분석 대상을 **좁힌다** | 리그 몇 개만 깊게 | 0 — 커버리지가 줄어든다 |
| ② Google CSE 를 **켠다** | 무료 **100 질의/일** · 카드 미등록 | 0 (§11-7 정의상 유료 아님) · 🔴 할당량이 248 에 모자란다 |
| ③ SearXNG 엔진을 **늘린다** | `settings.yml` 에 더 붙인다 | 0 — 정지 빈도는 재봐야 안다 |
| ④ 유료 검색 | — | 🔴 **절대 규칙 위반.** 하지 않는다 |

🔴 **섞는 것이 답일 수 있으나 재보지 않았다.** ③ 을 먼저 재는 것이 비용 0 이고,
그 결과를 보고 ①·② 를 정하는 것이 순서다. 다만 **어디까지 깊게 볼지는 예산이고,
예산은 사용자 소관이다**(§13-7).
