```

                recent_pattern · h2h_pattern · match_type · coach_change
```

### 🔴 세 갈래를 가른다 — 섞으면 고칠 곳을 못 찾는다

| 갈래 | 뜻 | 고칠 곳 |

| **변수** | 유형·방향이 정해졌다 | — |

실측(새크라멘토 vs 라스베이거스): 변수 **11** · 배경 **17** · 미결정 **2**.

## 🔴 짓는 중에 드러난 것 — 스키마가 두 곳에서 막는다

`app/classify.py` 가 `app/types.py` 를 **처음으로** 불렀다. 그러면서 단계 2 스키마가
실물과 맞는지 처음 드러났고 둘이 걸렸다.

### ① `weight == WEIGHT_OF[hardness]` 강제 → **hardness 를 깎는다**

§4 의 `h2h_pattern.sample_weight`(1.0 / 0.7 / 0.4)를 weight 에 직접 넣으면 스키마가
거부한다. ⚠️ 그런데 그 셋은 `hard / likely / soft` 의 weight 와 **똑같다** — 같은
규칙을 hardness 로 말할 수 있고, **작은 표본은 더 약한 주장**이므로 그것이 더 맞다.
→ 해결됐다(코드·계약 반영).

### ② ✅ `published_at` — **사용자 결정 2026-10-02: 안 A** (고쳤다)

`types.Variable` 과 `types.Background` 가 `published_at` 을 **필수**로 받는다.
그런데 순위표에는 발행 시각이 **없다**(fotmob 표 · `standings/now` 둘 다).

```
classify.Classified.to_variable()  →  (None, "발행 시각이 없다 — 지어내지 않는다")
```

🔴 **지어내지 않았다.** 그러나 그러면 `stakes`·`home_field` 변수가 §3 에 **영영 못
들어간다** — 둘 다 순위표에서 나온다.

**사용자 답: A.** `published_at: datetime | None` 으로 열었다.

🔴 **그냥 열면 구멍이다** — 이 칸은 §12-c-2(경기 후 기사 배제)가 쓰는 칸이라,
날짜 없는 **기사**가 그 검사를 비껴간 채 무게 1.0 을 갖는다. 조건 **둘**을 걸었다:

```
① dateless_reason 이 **반드시** 있어야 한다 — 조용히 비울 수 없다
② hardness 는 **soft** 여야 한다
   §12-c-1 *"날짜를 못 읽는 자료는 soft 로만 남긴다"* 가 이미 그 규칙이다
③ 날짜가 **있는데** 사유가 적혀 있으면 거부 — 둘 중 하나다
④ `Variables.dateless` 가 **건너뛴 항목을 이름으로** 들고 있다(조용한 0 금지)
⑤ 날짜가 **있는** 항목은 여전히 경기 후 검사를 받는다 — 열어 준 것은 날짜 없는 자료뿐
```

⚠️ **안 B(수집 시각을 그 칸에 넣기)는 버렸다** — §12-c-1·§12-c-2 가 모든 순위표를
*"방금 나온 자료"* 로 읽어 **날짜 검사가 통째로 무력해진다.**

실측 2026-10-02 — 안 A 로 §3 구조가 섰다:

```
새크라멘토 vs 라스베이거스  →  §3 Variables 성립
  변수 11 · 배경 19 · 못 만든 것 0
  🔴 날짜 없이 들어온 항목 3건이 `dateless` 에 이름으로 남는다
  방향 strength {home 4.6, away 2.2}
```

계약 5건(`tests/stage2/test_types.py`) · **돌연변이 2종으로 물리는지 확인**했다
(soft 조건·사유 조건을 각각 떼어 보니 그 자리에서 빨개졌다).
