## 결함 1 — `stakes` 가 **양쪽에 걸렸을 때** 규칙이 없다 ✅ **고쳤다**

**지금 규칙**(§4): `stakes` 방향 = *"걸린 팀 쪽 승리 방향"*

**실측**: 네이션스리그 C조 2그룹 — 몬테네그로 6점 **승격 경쟁**, 라트비아 1점
**강등 회피**. **양쪽이 다 걸렸다.** 규칙이 한쪽을 못 고르니 그 사실이 변수에서
통째로 빠진다.

```
지금    라트비아–몬테네그로  방향 변수 2개 · 방향 1종 → 🔴 자료 부족
        키프로스–아르메니아  방향 변수 1개 · 방향 1종 → 🔴 자료 부족
```

🔴 **제안**: `stakes` 에 **`splits_direction: true`** 를 준다.
§4 가 이미 `coach_change` 에 그것을 갖고 있다 — *"두 방향을 밀면 **두 항목으로
나눠 저장한다**"*. **새 장치가 아니라 있는 장치를 한 유형에 더 쓰는 것이다.**

```
제안 뒤  라트비아–몬테네그로  변수 4개 · 방향 2종 {away 2.4, home 0.4} → ✅ 통과
         키프로스–아르메니아  변수 3개 · 방향 2종 {home 1.4, away 0.4} → ✅ 통과
```

⚠️ **친선 경기는 이것으로도 안 풀린다** — 순위 stakes 가 없다(우즈벡–시리아).
🔴 그리고 그것이 **맞는 답이다**: 그 경기의 「자료 부족」 판정이 내 낙첨을 막았을 것이다.

| 결정 | |
|---|---|
| **넣는다** | `variable_types.yaml` 의 `stakes` 에 `splits_direction: true` |
| 안 넣는다 | 양쪽이 걸린 경기는 stakes 를 쓰지 않는다(지금 그대로) |

## 결함 4 — **난타전 시나리오가 세 번 연속 안 만들어졌다** ✅ **고쳤다**

**지금 규칙**(§5-c-1 · §7 R3): *"서로 다른 팀의 변수가 각각 **수비 약화**(absence

🔴 **`lineup_intent`(감독 인용)을 요구한다.** 감독 인용이 없으면 발동하지 않는다.

**실측 — 자료가 난타전을 가리키는데 규칙이 안 받는다**:

| 경기 | 난타전 신호 | 5c-1 |
|---|---|---|
| 키프로스–아르메니아 | 맞대결 2경기 **9골** · 양팀득점 2/2 · 아르메니아 BTTS 4/5 | 🔴 미발동 |

⚠️ §10 정답지의 **유일한 ✘ 사례**가 아르메니아–몬테네그로 2-3 이고 사유가

🔴 **제안**: 발동 조건에 **OR 를 하나 더 둔다.**


⚠️ 숫자(3.0·3.5)는 **내가 고른 것이다** — 사용자가 정해야 한다. 실측값을 붙인다:

## 결함 5 — 🔴 **보드 없는 경기의 총점 기준선이 순환이다** ✅ **고쳤다**

**지금 규칙**(§6-c-3): *"보드가 없는 경기는 우리 기준선으로 계산한다 — 총점
기준선은 **시나리오 스코어 최대합 + 0.5**"*

**실측** (시애틀–캔자스시티):

```
시나리오 스코어 최대합 3  →  기준선 3.5  →  언더 3.5 survival **1.00**
```

🔴 **정의상 1.00 이다.** 기준선을 우리 시나리오에서 뽑았으니 어떤 시나리오도 넘을
수 없다. **언더가 공짜로 "낸다" 등급을 받는다.**

실제 보드 줄로 재면 전혀 다르다:

```
언더 2.5  0.55   ← 이름 못 적는다
언더 3.0  0.55   ← 이름 못 적는다
언더 3.5  1.00   ← 우리 기준선. 순환
```

🔴 **제안 셋 중 하나**:

| 안 | 내용 |
|---|---|
| **A** | 보드 없는 경기는 **총점 마켓을 이름으로 적지 않는다.** §6-f 표(기준선별 생존)만 낸다 |
| B | 기준선을 **자료에서** 뽑는다 — 리그 평균 총득점 등. 우리 시나리오에서 뽑지 않는다 |
| C | 지금 그대로 두고, 카드에 *"우리 기준선 · 순환 주의"* 를 표기한다 |

제 쪽은 **A** 가 안전해 보이나 결정은 사용자다.

# 🔴 결함 7 (새로 나왔다) — `5c-1` 이 만든 시나리오의 strength 를 규칙이 정하지 않는다

§5-d: *"시나리오 strength = **소속 변수 weight 합**"*.

그런데 난타전을 띄우는 근거(평균 총득점)는 **총점 패턴이라 방향이 없다** → §1 대로
**배경**이고, 배경에는 weight 가 없다. **합할 것이 없다.**

⚠️ 문서의 유일한 선례가 §5-c-5 의 `floor_strength: 0.3` 이다. 그것을 쓰되
`user_decision_pending: true` 로 **지어낸 값임을 표시**했다.

| 결정 | |
|---|---|
| **0.3 그대로** | §5-c-5 선례를 따른다 |
| 다른 값 | 숫자를 주세요 |
| 다르게 | 근거가 된 배경의 "세기"를 weight 로 환산하는 규칙을 둔다 |

🔴 지금 값이 결론을 바꿉니다 — 시애틀 건에서 D 의 strength 가 0.3 이라 언더 3.5 가
0.96(소액)입니다. **1.0 이면 0.86, 2.0 이면 0.78(이름 없음)** 이 됩니다.

## ⑦ `5c-1` strength — **지어낸 0.3 을 §5-d 에서 나오게 바꿨다**

§5-d 가 이미 답을 갖고 있었다: *"시나리오 strength = **소속 변수 weight 합**"*.
난타전을 띄우는 사실은 방향이 없어 **배경**이지만 **hardness 는 있다.** 그 weight 를
합하면 값을 고르지 않아도 된다.

```yaml
strength: 발동 근거가 된 배경 사실들의 weight 합(§5-d)
floor_strength: 0.3
floor_when: 근거의 hardness 를 못 읽을 때만
```

실측(시애틀–KC): 근거 = KC 최근 5경기 평균 4.60골(공시 → hard) → **D strength 1.0**.
두 근거(h2h + recent)가 다 발동하면 2.0 — 신호가 두 겹이면 더 무겁다.
