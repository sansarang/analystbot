# 갈림길 — **대회별 현지어 표의 원본이 무엇인가** (2026-10-01)

## 무엇이 걸렸나 (실측)

정답지 경기(USL, 미국 2부 축구)를 녹음하다 나왔다. `queries.DEFAULT_LANGS` 가
`("ko", "en")` 이어서 **미국 팀을 한국어로 검색**했다:

```
Las Vegas Lights 감독 인터뷰 1일      ← 한국어 + 한국식 날짜
Las Vegas Lights 선발 등판 1일        ← 야구 용어("선발 등판")
```

결과 17건 중 다수가 `zhihu.com`(중국어 Q&A)이었고 — 한국어 질의가 한국어 자료를
못 찾자 검색 엔진이 엉뚱한 언어로 흘렀다 — **열기 예산 17건을 거기 태웠다.**
라인업·감독 교체·선발 전부 **사실 0건.**

## 🔴 고친 것 (즉시)

`DEFAULT_LANGS` 를 **`("en",)`** 으로 바꿨다.

근거는 이 파일이 **이미 적어 둔 것**이다(§12-b 주석):

> 한국어를 모든 리그의 1순위로 두지 않는다 — 한국어로 NPB 를 검색하면 번역 기사만
> 나오고, 그 기사에는 타순이 없다(실측 2026-09-27).

🔴 **모르는 리그도 같다.** 한국어 보도는 번역이거나 아예 없다. 한국어 1순위는
**한국 리그에서만** 맞고, 그 리그들(`KBO`·`K리그1`)은 `LANGS` 표에 이름이 있다.

⚠️ USL 을 `LANGS` 표에 **넣지 않았다.** 기본이 영어가 되었으니 넣을 필요가 없다 —
넣으면 손으로 유지하는 목록이 한 줄 늘어난다(사본 금지).

## 🔴 아직 못 푼 것 — **대회별 현지어**

`해외축구` 는 football-data 무료 티어의 **13개 대회**다. 영어만으로는 현지 소스를
놓친다:

| 대회 | 현지어 | 영어로 찾으면 |
|---|---|---|
| Ligue 1 | 프랑스어 | L'Équipe 의 예상 XI 를 못 본다 |
| Serie A | 이탈리아어 | Gazzetta 를 못 본다 |
| Bundesliga | 독일어 | kicker 를 못 본다 |
| Campeonato Brasileiro | 포르투갈어 | globo 를 못 본다 |
| Primera División | 스페인어 | Marca·AS 를 못 본다 |

**대회 → 현지어 표가 필요하다.** 🔴 그러나 **그 표의 원본이 무엇인지 모른다**:

- `app/collect/fdorg.py` 는 대회 이름을 **응답에서** 받는다(13개를 손으로 안 적는다).
  그 응답에 `area.code`(국가 코드)가 **온다** — 그것이 원본일 수 있다. **아직 안 쟀다.**
- v4 §12-b·§13 은 언어를 "현지어 먼저"라고만 하고 **대회별 표를 주지 않는다.**

→ 🔴 **지어내지 않는다.** 응답에 국가 코드가 실제로 오는지 재고, 오면 그것을
원본으로 쓴다. 안 오면 사용자에게 묻는다.

| 날짜 | 무엇 | 누가 | 답 | 근거 |

| 2026-10-01 | 모르는 리그의 기본 언어 | **실측** | **영어** (`("en",)`) | 한국어 질의가 zhihu 로 흘러 예산 17건을 태웠다 |

| 2026-10-01 | 대회별 현지어 표의 원본 | **측정 대기** | ⏳ | football-data 응답의 `area.code` 를 아직 안 쟀다 |

# 🔴 추가 실측 (2026-10-01, 같은 날) — **원인이 하나가 아니었다**

위에서 나는 1차 녹음의 zhihu 홍수를 *"한국어로 검색해서"* 라고 적었다.
**절반만 맞았다.** 엔진을 하나씩 재보니 더 큰 원인이 있었다.

## `bing` 이 **질의를 무시하고 있었다**

엔진마다 따로 질의하고 **결과 항목의 `engines` 귀속**으로 셌다(전체 개수는 못
믿는다 — 정지된 엔진을 지목해도 다른 엔진 결과가 섞여 온다).

```
"Sacramento Republic vs Las Vegas Lights starting lineup"
   → Natural Language Processing · IBM Research · 知乎(중국어 NLP)   관련 0/10
"New York Yankees probable pitcher"
   → It's NEW · Daum · Newgrounds              ← `new` 한 낱말에만 걸렸다
"Borussia Dortmund injury news"
   → Backend Development · GeeksforGeeks
```

🔴 질의 다섯으로 재현했다. **그런데 `bing` 은 당시 유일하게 "작동하는" 엔진이었다**
(brave·duckduckgo·qwant·google cse 가 전부 정지). 그래서 검색 결과의 대부분이
무관한 페이지였고, **열기 예산 20/20 을 거기 태웠다.**

⚠️ 원인을 하나로 단정한 것을 고친다(§11-3 추측 금지). 언어도 문제였고,
**엔진이 깨진 것이 더 큰 문제였다.**

## 질로 가린 엔진표

| 엔진 | 귀속 결과 | 질 | 판정 |
|---|---|---|---|
| `bing` | 10 | 🔴 **관련 0/10** | **끈다** |
| `yahoo` | 7 | ✅ 7/7 — fotmob·sofascore·uslchampionship·livescore | 켠다 |
| `google` | 10 | ✅ 10/10 — 🔴 *"Starting XI is in #SACvLV"* 를 찾았다 | **켠다** |
| `google news` | 10 | ✅ 8/10 — 구단·리그 **공식** | **켠다** |
| `naver` | 15 | ✅ 13/15 | **켠다** |
| `yep` | 20 | 🟡 위키·선수 페이지 — 폼·개인 기록에 쓴다 | 켠다 |
| `mwmbl` | 1 | ❌ 2018 시즌 페이지 하나 | 안 켠다 |
| `startpage`·`mojeek`·`wikipedia`·`marginalia`·`presearch`·`stract`·`reddit` | **0** | — | 둔다(비용 0) |

## 바꾼 뒤 — 같은 질의

```
전       17건 · 관련 ~40% · 기여 엔진 {bing 10, yahoo 7}
후    🔴 50건 · 관련 **96%** · 기여 엔진 {yahoo 7, yep 20, naver 15, google 10}
```

🔴 잡힌 것 중에 **`Starting XI is in #SACvLV`**(확정 XI)와
**`Match Recap: … Draw Against Sacramento Republic FC`**(경기 결과)가 있다.

⚠️ 후자는 §10 정답지 **(b) 생존 결과**(단계 7)에 필요한 자료다 — 전에 *"사용자가
결과 있는 경기를 줘야 한다"* 고 적었는데 **봇이 수집할 수 있다.** 그 줄을 고쳤다.

## 🔴 그래서 "검색 용량" 질문의 답이 달라졌다

사용자에게 *"하루 248 질의를 어떻게 대나"* 를 물으려 했다. **묻기 전에 재야 했다** —
용량이 모자란 것이 아니라 **엔진 하나가 깨져 있었다.**

| 전에 생각한 것 | 🔴 실측 |
|---|---|
| 작동 엔진 2개 (bing·yahoo) | **실제로는 1개**(yahoo). bing 은 쓰레기였다 |
| 용량을 늘리려면 CSE·범위 축소가 필요 | **엔진 4개를 더 켰다** — 비용 0, 질 96% |

→ Google CSE(§19-i-3)는 **아직 잠근 채로 둔다.** 비용 0 으로 해결됐다.

## 🔴🔴 라이브가 이 결정을 다시 열었다 — **아시안게임 한국 vs 중국** (2026-10-02)

사용자 지시: *"아시안 게임 15시 한국대 중국 여자축구 실제로 테스트 해봐자.."*

**킥오프 30분 전**에 진짜로 녹음해 돌렸다(`python -m app.scheduler prekick`).

```
사실 9건 · 세포 13개 · 변수 **0건** → §7 R5 자료 부족 → 시나리오 0
세포가 검색 3/3 · 열기 20/20 을 쓰고 사실 0건
열린 주소: geocountries.com/china · thefootballstand.com/friendlies/… (경기와 무관)
```

### 🔴 그런데 **변수는 웹에 있었다** — 내가 손으로 찾으니 전부 나온다

```
맞대결  43전 한국 4승 · 최근 11경기 5무 6패 · 마지막 승리 2015-08
휴식    9/29 준결승 0-2 패 → 3일
감독    "반드시 이긴다"(10/1 회견) · 8년 만의 메달 도전
구장    시즈오카 에코파 — **중립**
```

🔴 **세상에 자료가 없는 것이 아니다. 봇이 못 찾은 것이다.** 원인 둘:

| 원인 | 자세히 |
|---|---|
| **① 검색 언어가 영어뿐이다** | `LANGS` 에 `Asian Games` 가 없어 `DEFAULT_LANGS = ("en",)` 로 간다. **한국 대표팀 기사는 한국어 매체(SBS·국제뉴스·연합)에 있다.** 🔴 USL 을 고치려고 영어 기본으로 바꾼 것이 **한국 대표팀을 깨뜨렸다** |
| ② 맞대결·폼이 **산문에 있다** | 순위표도 fotmob 경기 페이지도 없다. `43전 4승` 은 기사 문장이고 그것을 읽으려면 `extract.py`(L1~L3)가 필요한데 **미배선**이다 |

### ⚠️ 그리고 토너먼트는 **구조적으로** 안 된다

우리 측정 넷이 **전부 순위표에서 나온다**: `stakes` · `home_field` · 포아송 격자 ·
총점 기준선. 아시안게임은 **녹아웃이라 순위표가 없다.** 그래서 경기 페이지를 찾았더라도
무게는 §5-d(근거 합)로 내려가고 난타전·총점 기준선은 서지 않는다.
🔴 **중립 구장**이라 `home_field` 는 애초에 **틀린 변수**다 — 지금은 순위표가 없어
안 섰지만, 있었으면 **거짓 변수를 세웠을 것**이다.

### ⏳ 결정 — 검색 언어를 **무엇에 맞추나**

| 안 | 뜻 | 대가 |
|---|---|---|
| **A** 리그마다 적는다(지금 꼴) | `LANGS["Asian Games"] = ("ko","ja","zh","en")` | 대회가 늘 때마다 손으로 적는다. 대표팀 경기는 **상대에 따라** 언어가 달라지는데 리그 하나로는 못 담는다 |
| **B** **팀의 언어**를 따른다 | 나라 → 언어 선언을 둔다 | 선언이 하나 더 늘지만 *"한국 경기는 한국어로 찾는다"* 가 리그와 무관하게 참이다 |
| C 늘 여러 언어를 던진다 | 검색 예산 ×N | 🔴 엔진 정지를 부른다(실측 전례) |

## ✅ 닫혔다 — **사용자 지시 2026-10-02** → **안 B · 영어가 먼저**

> 한국어로 찾지 말고 영어로 찾으면 되잖아...**공통으로 영어 그다음은 그나라 현지어**..

🔴 **영어가 공통이다** — 현지어는 그 나라 경기에만 듣고 영어는 거의 모든 경기에 듣는다.
예산(검색 3회)을 쓰는 순서가 그 순서여야 한다.

```
Asian Games · South Korea W  → ('en', 'ko')
Asian Games · China W        → ('en', 'zh')     🔴 같은 리그인데 다르다
NPB         · 読売…           → ('en', 'ja')     리그 선언에서
USL         · Las Vegas …    → ('en',)          선언이 없다 — 사유가 남는다
```

⚠️ yaml 에는 **현지어만** 적는다 — `en` 을 거기 적으면 순서가 갈린다(계약이 막는다).

### 🔴 순서를 바꾸자 **숨어 있던 결함**이 드러났다

코드가 *"첫 언어"* 와 *"현지어"* 를 **같은 것으로 쓰고 있었다**(`lang == langs[0]`).
그때는 첫 언어가 곧 현지어였으니 **우연히** 맞았다. 영어를 앞으로 돌리자:

```
전: 영어 변형에 `広島`(약칭) · 일본어 변형에 `広島東洋カープ`(정식명)   ← 거꾸로다
후: 일본어 변형에 `広島` · 영어 변형에 `広島東洋カープ`
```

🔴 **계약이 그것을 잡았다**(`test_현지어_변형이_팀명까지_바꾼다`). 현지 약칭은 **그
나라 매체가 쓰는 표기**이므로 그 나라 언어 질의에 붙어야 한다.

## 〔지난 판〕 처음 닫은 꼴 — **안 B**

`config/search_langs.yaml` — **팀**이 선언돼 있으면 그것이 이기고, 없으면 리그
(`queries.LANGS`), 없으면 영어다. 🔴 **고른 이유를 함께 돌려준다**(`langs_for`).

```
Asian Games · South Korea   → ko+en   [팀 선언]
Asian Games · China         → zh+en   [팀 선언]   ← 🔴 같은 리그인데 다르다
NPB · 없는팀                 → ja+en   [리그 선언]
USL · Las Vegas Lights FC   → en      [둘 다 없음 — 전 결함을 되돌리지 않았다]
```

⚠️ **선언한 팀만 쓴다** — 나라를 전수로 적지 않는다(적으면 유지 못 하는 사본이다).
없는 팀은 사유에 *"그 팀 기사가 다른 언어로만 나오면 **못 찾는다**"* 가 남는다.

## 🔴🔴 그리고 고치자마자 **더 위험한 것이 드러났다**

한국어로 찾으니 **찾아졌다** — 그런데 **남자 대표팀**이었다:

```
lineup:Asian Games:South Korea:… :player  Heung-Min Son · Min-Jae Kim · Kang-In Lee
lineup:…:past_stats                        opponent: Uruguay
```

🔴 **우리 경기는 여자축구다.** 날짜도 같고 팀 이름도 `South Korea`·`China` 로 **글자까지
같아서** 어떤 가드도 막지 못했다. **0건보다 나쁘다** — 0건은 멈추지만 틀린 자료는
카드를 만든다(§17-g-3 · M14 가 막으려는 바로 그 사고다).

### 막은 방법 둘

| 무엇 | 어떻게 |
|---|---|
| §13-c ② **우리 두 팀의 경기인가** | 전에는 **날짜만** 봤다. 페이지의 두 팀을 질문의 팀·상대와 맞춘다 |
| 🔴 **남녀·연령 표식** | `verify.same_squad_kind` — `South Korea` ↔ `South Korea W` 는 **다른 팀**이다. fotmob 표기(` W`·`U23`)를 쓴다 |

⚠️ **접미사를 코드로 떼지 않는다** — 떼면 남녀가 합쳐지고 그것이 더 위험하다.
⚠️ 상대를 모르면 **막을 수 없다** — 우리 팀만 보고 *"검사가 약하다"* 를 로그에 남긴다.

🔴 **그래도 이 경기는 분석되지 않는다**: 이름을 `South Korea W` 로 바로잡으니 경기
페이지를 **아예 못 찾았다**(사실 7건 전부 엉뚱한 인용). 여자 아시안게임은 우리 검색
경로에 안 잡힌다 — 자료가 없는 것이 아니라 **길이 없다.**

### ✅ 그래도 이 테스트가 증명한 것

```
킥오프 전 녹음이 **실제로 돈다** — 31분 전에 녹음 1 · 건너뜀 20(사유와 함께)
카드가 **저장된다** — 변수 0 · 배경 6 · 충분성 insufficient(사유 포함)
🔴 그리고 봇이 **지어내지 않았다** — "자료 부족"이라고 적고 멈췄다
```

⚠️ 그 저장 자체가 라이브로 처음 드러난 결함이었다 — `prekick` 이 **사실만 모으고 카드를
저장하지 않고 있었다.** 고쳤고 계약을 걸었다(`test_녹음이_카드를_저장한다`).
