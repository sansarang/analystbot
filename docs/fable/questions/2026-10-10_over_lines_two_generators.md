# 오버 줄이 **두 군데서 나온다** — 같은 카드에서 서로 다른 수를 말한다

🔴 **실측 2026-10-10 · 김천–안양 최종 카드**(`var/accept/gc_final2.log`)

```
 시뮬: 승무패 52%/29%/19% · 오버 1.5 72% · 2.5 46% · 3.5 25% · 선제골 팀 승 66%
📊 확률 변화 … 오버 1.5 95% · 2.5 63% · 3.5 36%
```

한 카드 안에서 **오버 1.5 가 72% 와 95%** 로 둘이다. 만든 곳이 다르다:

| 줄 | 만드는 곳 | 재료 |
|---|---|---|
| `시뮬:` | `app/core/sim.py`(§4 분 단위) | 축1·축2·축3 + 상태 배율 |
| `📊 확률 변화` 의 오버 | 총골 재가중(앞 지시서) | 총골 기준 2.139 + 포아송 |

⚠️ 둘 다 **우리 수**다 — 사람이 보면 어느 쪽이 봇의 말인지 알 수 없다.
🔴 나는 **고르지 않는다**(사용자 지시 2026-09-30: *"이제부터 페이블이 결정할 거는
   없다"*). 갈림길을 적고 멈춘다.

## 갈림길 — 어느 쪽이 카드의 오버 줄인가

- **A. 시뮬이 이긴다** — §4 가 *"90분을 분 단위로 … 스코어 분포 → 승무패, 오버
  1.5/2.5/3.5"* 라고 적었으니 오버는 시뮬 산출이다. 총골 재가중은 시뮬의 **λ
  입력**으로만 쓴다.
- **B. 총골 재가중이 이긴다** — 오버는 이미 재가중 경로가 내고 있었고(앞 지시서),
  시뮬의 오버는 **참고**로 긴 카드에만 적는다.
- **C. 둘을 다 보인다** — 지금 모양. 🔴 다만 **어느 쪽이 무엇인지 카드가 말해야**
  한다(지금은 둘 다 그냥 `오버 1.5` 다).

⚠️ 왜 이렇게 벌어지나(아직 **안 쟀다**): 시뮬은 상태 배율(앞섬 ×0.85 · 뒤짐
   ×1.20 · 둘 다 **임시값**)로 골을 깎고, 재가중은 그 배율을 모른다.

**범위 밖이라 손대지 않았다** — 이 문서만 적고 §5 긴 카드 작업을 계속했다.
