# 🔴 `starts_kst` 는 **순간**이다 — 절대규칙 2 의 뒷문장을 못 지키고 있다

**물어야 하는 것은 하나다: 이 칸을 어떻게 할까.** (실측 2026-10-05 · 인계 ①-2)

---

## 무엇을 쟀나

`games.starts_kst` 는 `TIMESTAMPTZ` 다. 포스트그레스는 그 칸을 **늘 UTC 로**
보관하고 입력의 오프셋을 **버린다.** 그래서 수집기 일곱 곳이 넣고 있던
`when.astimezone(KST)` 는 **아무 효과가 없었다.**

```
라이브 DB 52행 중 starts_kst = starts_utc        → 52 / 52   (전부)
그중 UTC 달력 날짜 ≠ KST 달력 날짜               → 16 / 52

France  vs Belgium  2026-10-05 18:45Z  → ::date 10-05 / 🔴 KST 로는 10-06
Portugal vs Norway  2026-10-04 18:45Z  → ::date 10-04 / 🔴 KST 로는 10-05
```

**손해를 세어 봤다** — `sources.DbSources.slate(2026-10-06)` 가 종전 꼴에서
**0건**, 고친 뒤 **1건**. `/health` 의 `오늘 경기수` 가 **3 → 4**.

## 무엇을 고쳤나 (이번 커밋)

| 전 | 후 |
|---|---|
| 질의 일곱 자리가 `starts_kst::date`(세션 시간대 = UTC) | `timefmt.sql_kst_day()` **하나** |
| 수집기 일곱 곳이 `.astimezone(KST)` (무효) | `timefmt.db_instant()` **하나**(UTC) |
| 계약 둘이 **버려지는 오프셋**을 검사(초록인데 거짓) | 순간 + 표시(`kst_label`)를 센다 |

계약 넷이 그 자리를 막는다(`tests/test_time_contract.py` · 돌연변이 M111~M113
전부 빨강으로 확인했다).

## 🔴 남은 것 — **사용자 결정**

절대규칙 2 는 두 문장이다:

> ① DB 는 UTC 저장, 표시만 KST.  ② **현지 시각과 KST 를 둘 다 저장한다.**

①은 지켜졌다. **②는 이 스키마로 지킬 수 없다** — `TIMESTAMPTZ` 에는 벽시계가
안 들어간다. `starts_local` 도 같은 칸 꼴이라 같은 병이고, 지금 32/52 행이
`NULL` 이다(fotmob·espn·nhl·fdorg 는 현지 시간대를 아예 안 준다).

| 보기 | 무엇을 하나 | 대가 |
|---|---|---|
| **A** | 두 칸을 **그냥 둔다** — 이름이 거짓이지만 계약이 오용을 막는다 | 다음 사람이 또 믿는다. 스키마 변경 0 |
| **B** | `starts_kst` 를 **없앤다**(= `starts_utc` 와 중복) | 질의·행 7곳 + 색인 1개 손봄. 거짓 믿음의 뿌리가 사라진다 |
| **C** | `starts_local` 을 `TIMESTAMP`(naive) + `local_tz TEXT` 로 바꾼다 | 절대규칙 2 ②를 **실제로** 지킨다. 현지 시간대를 주는 소스는 지금 **NPB 뿐**이다 |
| **D** | B + C 둘 다 | 스키마 변경 가장 큼 |

🔴 **나는 고르지 않는다**(묻는 곳은 하나 — 사용자 · 2026-09-30).
⚠️ 고르기 전까지 코드는 **A** 로 돈다 — 계약이 오용을 막고, 이름은 거짓인 채다.
