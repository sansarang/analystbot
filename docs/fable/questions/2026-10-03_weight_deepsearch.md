## 🔴 딥서치 ① — **C 는 확률이 아니게 된다** (방법론)

확률에 **바깥 정보를 섞는 정식 방법**을 찾았다. 그것은 곱이 아니라 **로그오즈 공간의
보정**이다 — `linear-in-log-odds`(= beta calibration)가 그 이름이고, 적정 채점 규칙
(Brier·로그)으로 평가·최적화되는 **모수가 있는 변환**이다.

```
정식:  logit(p') = a · logit(p) + b          ← a·b 는 결과 자료로 **맞춘** 모수다
우리 C: p' = p × (근거합 ÷ 전체근거)          ← 모수가 없고, 합이 1 이 되지도 않는다
```

🔴 즉 C 는 *"확률을 조금 기울인 것"* 이 아니라 **확률이 아닌 수**다. 그러면 `1.0 /
0.8` 이라는 등급 선이 뜻을 잃는다(§6-b 가 그 선으로 이름을 적는다).
⚠️ 그리고 정식 쪽(로그오즈 보정)은 **모수를 맞춰야** 하는데, 우리는 원장으로 모수를
   맞추는 것이 **금지**다(사용자 지시 2026-10-02: *"검증하는 방법으로만"*).

→ **C 는 거부.** B 는 전 판 실측이 이미 거부했다(무승부 16.2% 가 5.1% 로 보였다).

## 🔴 딥서치 ② — **A 가 열린 자리가 있다** (전 판이 못 본 것)

전 판은 *"결장이 기대득점을 몇 % 낮추는가"* 하나만 찾았다. 그 계수는 **여전히 없고**,
심지어 **부호가 안정적이지도 않다** — 국가대표 차출로 주전이 빠진 팀이 오히려 공격
산출이 올랐다는 연구가 있다(점유 지향 전환·전술 적응).

🔴 그러나 λ 에 닿는 길이 **그것 하나가 아니었다.** 둘을 찾았다:

### (가) 야구 **선발 투수** — 계수가 필요 없다 (산수다)

```
그 등판의 기대 실점 = 선발 ERA × 기대 이닝 ÷ 9
남은 이닝의 기대 실점 = 팀 불펜 ERA × 남은 이닝 ÷ 9
```

**ERA 의 정의 자체가** *"9이닝당 자책점"* 이다 — 변환에 **맞출 모수가 없다.**
공표된 방법도 있다: `Pitching Performance Score` = (리그 평균 투수가 같은 이닝에
내줄 실점) − (그 선발이 내줄 기대 실점). 즉 *"선발 품질 → 기대 실점"* 은 이미
**발표된 산수**이고, 지어내는 수가 아니다.

⚠️ 필요한 입력은 셋뿐이고 **전부 봇이 이미 받는다**:
`선발 ERA`(`npb.parse_pitchers`) · `기대 이닝`(같은 표의 `투구회 ÷ 등판`) ·
`팀 불펜 ERA`(`tmp_*` 팀 투수 성적표).

🔴 그러면 `pitcher_state` 가 **λ 를 움직인다** — 변수가 생존에 닿는다.

### (나) 축구 **라인업 시장가치** — 결장 계수를 안 쓰고 결장을 반영한다

Peeters 가 Transfermarkt **팀 가치**만으로 대표팀 경기를 예측해 배당에 맞먹고 Elo·
FIFA 랭킹을 이겼다. 후속 연구는 그것을 **그 경기 라인업의 가치**로 바꿨다 — 다친
선수·빠진 선수가 **자동으로 빠진다**(가치는 선수마다 관측값이므로 *"결장 계수"* 가
아예 필요 없다).

⚠️ **그런데 우리에겐 시장가치 소스가 없다.** Transfermarkt 를 소스로 쓸지는 **새
   갈림길**이고, 사용자 답 없이 고르지 않는다(§13-a 는 그 도메인을 언급조차 안 한다).
   → 아래 "남는 질문"에 적는다.

# ✅ 두 번째 딥서치 — **축구 라인업 시장가치** (2026-10-03 · 사용자 지시)

> 축구 라인업 시장가치 소스(Transfermarkt 등)를 쓰나? **딥서치해서 찾아서 넣어라.**

## 🔴 ① 소스 — **새로 들일 것이 없었다**

```
fotmob 경기 페이지 페이로드
  content.lineup.{homeTeam,awayTeam}.starters[].marketValue
  실측 2026-10-03: 선발 11명 · 교체 15명 **전원**에 값이 있다
  예) 중국 vs 팔레스타인 — 중국 선발 가치 합 5,054,501 (11/11 읽음)
```

🔴 그 페이지는 봇이 **이미 열고 있다**(깊이 소스) — robots 결정도 이미 서 있다.
⚠️ Transfermarkt 도 `User-agent: * Allow: /` 라 **쓸 수는 있었다**(실측). 쓰지
   않는다 — 같은 자료를 이미 받는데 호스트를 늘리면 막히는 자리만 늘어난다.

## 🔴 ② 그런데 **λ 에는 넣지 않는다** — 계수가 없다

| 무엇 | 발표됐나 |
|---|---|
| 라인업 가치 자료 | ✅ 있다(위) |
| 가치 → **승패 확률** 모형 **꼴** | ✅ `(log 가치차)` 에 걸린 **순서 프로빗**(Peeters 2018 · arXiv 2411.09085) |
| 그 모형의 **계수** | ❌ **논문에 실려 있지 않다**(방향만: `β_TM > 0`) |
| 가치 → **λ(골)** 매핑 | ❌ 없다 |
| 임금·가치 → 승점(시즌) | `R²` 만(62~90%) — **경기당 λ 로 못 쓴다** |

🔴 **야구와 다른 점이 여기다.** `ERA` 는 *"9이닝당 자책점"* 이라 λ 와 **같은 단위**고
변환에 맞출 모수가 없다. 시장가치는 **골 단위가 아니다** — 가치비를 λ 에 곱하면
그것은 *"탄력성 = 1"* 이라는 **지어낸 계수**다(발표된 R² 들은 강하게 비선형·잡음이
크다고 말한다).

⚠️ 골 단위 대안(선발들의 경기당 득점관여 합)도 재 봤다 — fotmob 이 이 경기에서
   `season_goals` 를 **`None`** 으로 준다(국제 친선). 자료가 없어 못 쓴다.

## ✅ 그래서 **변수로 넣었다**

```
§4 lineup_value   "가치가 떨어진 팀 반대 방향"
  오늘 선발 가치 합 ÷ **기준 선발**(직전 경기) 가치 합 − 1
  문턱 -15%(yaml · 실측으로 고친다) · 선발 11명 **전원** 읽혀야 쓴다
  🔴 확정 XI 가 아니면 쓰지 않는다 — 예상 XI 로 하락을 말하면 거짓이다
```

🔴 **이것이 작은 일이 아니다**: 결장·로테이션을 **숫자로** 재게 됐다. 전까지
`def_absence`·`squad_rotation` 은 **LLM 의 yes/no 에만** 의존했다.
⚠️ 다만 D 의 범위 안이다 — 변수는 *시나리오·가설·방아쇠*에 닿고 **등급은 못 바꾼다**.
   축구에서 변수가 λ 에 닿는 길은 **계수가 발표되면** 열린다. 그때까지 열리지 않는다.

🔴 기계가 그것을 막는다: `test_라인업_가치가_λ에_닿지_않는다` 가 `app/league.py` 에서
   `market_value`·`value_sum` 을 찾으면 빨개진다.
