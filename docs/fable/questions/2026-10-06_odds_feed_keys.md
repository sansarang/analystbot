# 🔴 배당 피드 키 — **사용자에게 묻는 것 하나**

네 층 지시서 §10-1: *"키 발급이 필요하면 **사용자에게 키 발급만 요청**하고(가입은
사용자가) 나머지 단계를 계속한다."* → 나머지 단계(2~10)는 **다 끝냈다.** 남은 것은
이 한 칸이다.

## 무엇이 필요한가

| 피드 | 실측(2026-10-06) | 넣을 곳 |
|---|---|---|
| the_odds_api | `GET /v4/sports/?apiKey=` → **401 MISSING_KEY**(피드는 살아 있다) · 월 500 크레딧 · 남은 수를 응답 헤더로 준다 | `.env` 의 `ODDS_API_KEY` |
| oddspapi | `GET /v4/tournaments?sportId=1` → **401 MISSING_API_KEY** · 월 250 · 과거 배당 무과금(문서) | `.env` 의 `ODDSPAPI_KEY` |

🔴 **가입 화면에서 카드 등록을 요구하면 그 피드는 등록하지 않는다**(§2-1 ·
   Brave 때와 같은 기준). 두 곳 다 카드가 필요하면 **사용자 보드만으로** 간다 —
   그 길은 이미 돈다(§2-6: 보드 글·캡처 → 로컬 OCR → 같은 파서).

## 지금 상태 — 키 없이 무엇이 되고 무엇이 안 되나

| 되는 것 | 증거 |
|---|---|
| ① 기준 확률 | 한국 1722 vs 우즈벡 1653 → 홈 54% 무 29% 원정 17% |
| ③ 우리 확률 | 시나리오 무게 비율 — 홈 61% 무 11% 원정 28% |
| 사용자 보드 → 시장 열 | `1.66/3.79/4.55` → 55%/24%/20%(업체 몫 8.6% · Shin 57/24/19) |
| §6 판정·§7 등급 내림 | 온두라스–자메이카에서 **"우리만 반대"** → 등급 없음이 실제로 걸렸다 |

| 안 되는 것 | 왜 |
|---|---|
| **봇이 혼자 배당을 받는 것**(§11 검수 세 번째 경기) | 키가 없다 — 그래서 카드가 *"시장 없음 — 키가 없다"* 를 적는다 |
| ② 라인업 보정의 확률 이동 | 평소 XI 표본이 **1경기**다(§4-1 은 3경기 최소) · ΔS→dr 환산 계수도 적합할 자료가 없다 |

⚠️ ② 는 **키와 무관**하다 — 직전 경기 링크를 **더 따라가야**(최근 5경기) 열린다.
   그것은 지시서에 없는 범위 확장이므로 **묻고 나서** 한다.
