# 🔴🔴 **카탈로그** — 내 동작을 봇 부품으로 (사용자 설계 2026-10-02)

## 사용자 원문 (요지)

> 핵심은 ① **카탈로그**다. 내 "딥서치"의 8할은 **이 경기에서 뭘 확인해야 하는지
> 아는 것**이다 … 봇이 경기마다 카탈로그 전 유형을 돌린다. 그러면 "무엇을 찾을지"를
> 모델이 정할 필요가 없다. **8B 모델이 제일 못하는 게 바로 그 판단**이라 코드로 뺀다.

> 못 옮기는 것 하나 — 카탈로그에 없는 **처음 보는 변수**다. 에리트레아 망명,
> 팔레스타인의 날 같은 것. 이건 **학습 고리**로 메운다 … 카탈로그는 슬레이트마다 자란다.

| 새 유형 5종 | ✅ 선언 + 근거 문서 방식으로 더한다(이 문서가 그 근거다) |

| 시나리오 문장 | ✅ **코드가 쓴다**(§5-e 변경) · 모델은 ③ 좁은 질문에만 |

🔴 그래서 *"정답지"* 는 **파일이 아니다.** 경기를 분석할 때 그 경기의 **측정지**를

그것이 또 "정답"이 되고, 사용자가 그것을 지우라고 한 까닭이 그것이다.

## ✅ ③ 좁은 질문 추출기 (2026-10-02)

> ③ 기사를 읽는다 — *"이 기사가 X 결장을 말하나?"* → 유형별 좁은 질문 →
> **yes/no/unknown + 본문 인용**, 인용이 원문에 실제로 있는지 **코드가 검사**

```
질문: 수비수나 골키퍼가 이 경기에 못 나온다고 적혀 있나?
answer 는 yes/no/unknown 중 하나. 기사에 그 이야기가 없으면 unknown.
yes 면 quote 에 그 **한 문장**만 원문 그대로. subject 에 대상 이름.
```

실측(같은 산문 · qwen3:8b):
```
def_absence     YES · quote "주전 수비수 장슬기는 … 경고 누적으로 … 결장한다."
                     subject 장슬기   ← 🔴 ④ 명단 대조가 이 칸을 쓴다
coach_conflict  no/unknown  (맞다 — 갈등 이야기가 없다)
event_match     no/unknown  (맞다 — 동메달전이지 행사가 아니다)
```

### 🔴 두 번 틀리고 고쳤다 — 둘 다 **내 탓**이었다

| 증상 | 원인 | 고침 |
|---|---|---|
| `Unterminated string starting at line 3` | 🔴 **프롬프트가 길었다.** 같은 스키마에 짧은 프롬프트를 주면 `{"answer":"yes"}` 가 바로 나온다 — 스키마 탓이 아니었다 | 세 줄로 줄이고 인용을 **한 문장**으로 못 박았다 · 본문도 2500자로 |
| 셋 다 `unknown` | 🔴 **`decides` 를 그대로 물었다.** 그것은 *코드*가 쓰는 판정 기준이고 질문이 아니다 | `asks:` 칸을 따로 뒀다(물음표로 끝나는 한 문장) |

⚠️ 계약이 둘을 잠근다: `asks != decides` · `asks` 는 `?` 로 끝난다 · 프롬프트는 4줄
이하 240자 미만 · `ASK_BODY_CHARS < BODY_CHARS`.

### 경계

```
🔴 yes 만 사실이 된다 — no·unknown 은 **사실이 아니고 사유다**
🔴 unknown 이 enum 에 있어야 한다 — 없으면 7B 는 모르는 것도 no 로 답한다
🔴 사실 값에 방향이 없다 — 그것은 §4 규칙이 정한다(§17-c)
```

## ✅ ② 재검색 루프 (2026-10-02)

> ② 빗나가면 각도를 바꾼다 — 프리뷰 → 감독 회견 → 현지 매체 → 현지어
> **관련 0건이면 다음 템플릿** (봇: 예산 3회 / 나: 경기당 2~4회 + 각도 전환)

🔴 **루프는 이미 있었다.** 빠진 것은 예산이 *"맞힌 각도"* 와 *"빗나간 각도"* 를
구분하지 않는 것이었다 — 그래서 템플릿이 4개인 유형은 **4번째를 영영 못 던지고**,
1번째에서 맞혀도 남은 예산이 돌아오지 않았다.

```
Budget.angles        빗나가도 되는 횟수 (yaml `catalog_policy.max_angles`)
Budget.take_angle()  🔴 빗나간 각도에만 부른다 — 맞히면 그 줄에 오지 않는다
out_of_angles        끊긴 사유가 **셋으로 갈린다**: 각도 ≠ 검색 횟수 ≠ 시간
spent                "검색 3/6 · 열기 2/4 · 빗나간 각도 2/2 🔴 각도 예산 소진"
```

🔴 **뜻을 못 박았다**: `max_angles` 는 *빗나가도 되는 횟수*다. 첫 시도는 전환이 아니므로
**던지는 각도는 max_angles + 1** 이다. ⚠️ 이 뜻이 흐려지면 *"템플릿 4개인데 왜 3개만
돌았나"* 를 영영 못 센다.

⚠️ **직접 주소 소스는 각도를 깎지 않는다.** 공식 API 가 0건을 내는 것은 *"각도가 틀렸다"*
가 아니라 *"그 자료가 없다"* 다 — 그것으로 깎으면 검색이 시작도 못 한다.

### 숫자는 아직 미정이다 — 그것이 맞다

`max_angles: 4`(사용자 실측 *"경기당 2~4회"*)로 시작하고 yaml 에 *"미정 — 실제 테스트로
정한다"* 를 적어 뒀다. 🔴 **`빗나간 각도 N/M` 이 그 숫자를 정하는 자료다.**
