## 이번 프로브가 뒤집은 것 — "lineups 증식 101건"

지난 며칠 `_startup_forensics` 가 이렇게 울렸다:

```
🔴 lineups mlb — 타순 길이 ≠ 9 인 행 101건 (08-26 14:23 ~ 09-02 22:40).
   이 라인업은 슬롯이 밀려 가짜 '타순 이동'이 라인업 의도·T5 로 흘렀다
```

**상태별로 갈라 보니 오염이 아니었다.**

```
길이이상  확정(confirmed) 0건  /  잠정(predicted) 20건
```

`save_lineup` 은 라인업 공시 **전**에도 무조건 저장한다. 그때 타순이 9명이
아닌 것은 **정상**이다 — 아직 발표가 안 됐을 뿐이다. 확정 상태의 이상은
**0건**이고, 판정에 쓰이는 것은 확정분이다.

🔴 **그리고 내가 어제 넣은 M-3 계측이 같은 실수를 하고 있었다.**
`daily_summary` 의 `타순 길이 이상 n건` 은 상태를 구분하지 않는다 —
그대로 두면 오늘 저녁부터 매일 "이상 20건"이 요약 카드에 찍힌다.
정상 동작을 결함으로 세는 지표는 진짜 결함을 그 속에 묻는다.

**수정안 (승인 후):** M-3 카운트와 `_startup_forensics` 를 `status='confirmed'`
로 한정. 잠정분은 세지 않거나 별도 표기.
