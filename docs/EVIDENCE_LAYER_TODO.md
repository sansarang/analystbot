# STEP 7-1 · 7-3 — 증거 카드·어댑터

## 🔴 결장 목록의 **팀 귀속 오류** (soccer_export_0920 ①)

실측 2026-09-20 위성 추출:

```
마치다@가시와  홈['Kohei Tezuka','Yuto Yamada','Tomoaki Okubo']
               원정['Kohei Tezuka','Yuto Yamada','Tomoaki Okubo']   ← 같은 3명
               (셋 다 가시와 선수다)
AT마드리드@레알 홈['Alexander Sørloth','Pablo Barrios']
               원정['Alexander Sørloth','Pablo Barrios']            ← 같은 2명
```

**귀속을 못 정하면 양쪽에 복사하고 있다.** 그러면 `lineup_out` 방향이 양쪽
악재로 잡혀 **상쇄**되고(실측: 한화@LG 도 같은 모양), 결과적으로 결장이
판정에 **한 번도 닿지 않는다**.

🔴 **귀속 불가는 `unknown` 으로 두고 어느 쪽에도 세지 않는다.**
선수-팀 매칭은 **`player_id` + `team_id`** 로 한다(`absence_registry_0920 §5`).
이름 문자열로 팀을 추정하지 않는다.

# STEP 7-4 — 기사 수집

## 🔴 출처 없는 추출은 **soft 로도 쓰지 않는다** (soccer_export_0920 ④)

실측: 위성 상자의 `source`·`fetched_at` 이 **빈 문자열**인 경기 6건.

구체적 위험 — 인천 **무고사 결장**이 추출에는 있는데 프리뷰 기사와 충돌한다.
**검증할 출처가 없어서 어느 쪽이 맞는지 판정할 수 없다.**

→ `source` 가 비면 그 카드는 **버린다**. soft 등급으로도 세지 않는다.
(`absence_registry_0920 §6` 과 같은 조건.)

## 본문 기준 중복 제거 (KJ-4)

🔴 **같은 보도자료가 8개 매체에 뜬다.** 매체 수를 근거 수로 세면 하나의 원문이
여덟 개로 부풀려진다.

```
정규화한 본문의 shingle 유사도 ≥ 기준값  →  같은 원문으로 묶는다
기준값은 config/rules.yaml (미검증 사전값 · 채점 뒤 데이터로만 변경)
```

⚠️ `n_sources` 는 매체 수가 아니라 **서로 다른 원문 수**다.
`absence_registry_0920 §4` 의 "기사 2건 이상"도 이 정의를 따른다.
⚠️ URL 기준 중복 제거는 이미 있다(`extract_game_facts` 의 `seen_url`) —
그것으로는 **부족하다**.
