# U14 — 발송 경로 전환·라운드로빈·출력 규격

## 왜

```
재현 3건:
  제공자 잔량 추적(app/llm/quota.py) 없음 — 429 면 다음으로 가기만 하고
    어느 제공자에 얼마나 남았는지 모른다(CHN-1 은 임시 규칙이었다)
  출력 규격 렌더(app/engine/spec_render.py) 없음 — 확인✔/못함✗·시장 흐름
    줄·결정축·반대축·조건이 카드에 0건
  섀도 7일 판정(app/engine/shadow_v3.py) 없음 — 전환 기준을 잴 코드가 없다
```
🔴 **운영 발송은 아직 v3 가 아니다**(`settings.order_v3 = False`). 즉 U0~U13 이
   만든 것이 **카드에 한 글자도 안 닿는다.** 이 U 가 그 길을 여는데, **여는
   행위 자체는 사용자 확인 지점**이다(지시문 3대 확인 지점 중 셋째).

## ① 이 함수/상태를 읽는 곳 **전부**

```
settings.order_v3                      ← config.py:422
  └ pipeline.py:2261 · matchup.py:1235 (_use_v3) · pipeline.py:5290(데이터로 가름)
openai_compat.complete → 429/401 즉시 다음  ← CHN-1 임시본. 여기에 잔량을 얹는다
judge_route.chain · FREE_PROVIDERS · is_free
(신규) quota.note_headers · remaining · order_by_remaining
(신규) spec_render.render      ← 카드·채팅·요약 **공통**
(신규) shadow_v3.criteria · evaluate
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **스위치를 켜지 않는다.** 이 커밋은 `order_v3` 기본값을 건드리지 않는다.
  전환 시각은 사용자가 정한다. 섀도 표 없이 켜면 검증 없이 카드가 바뀐다.
- 🔴 잔량 추적이 **라우팅을 바꾸면** 사슬 순서가 달라진다. 그래서 기본은
  `chain()` 순서 그대로이고, 잔량은 **429 를 맞은 제공자를 건너뛸 때만**
  쓴다. 순서를 뒤집는 것은 지시받지 않았다.
- 🔴 헤더가 없는 제공자(gemini 는 `x-ratelimit-*` 를 안 준다)를 **0 으로
  읽지 않는다.** 모르는 것과 없는 것은 다르다 — 모르면 종전 순서다.
- ⚠️ `spec_render` 는 **문자열만** 만든다. 발송 경로에 꽂지 않는다(U14-2 에서
  전환과 함께). 지금 꽂으면 카드가 오늘 밤에 바뀐다.
- ⚠️ 섀도 표는 **7일이 걸린다.** 오늘 낼 수 있는 것은 판정 코드와 1일치다.

## ③ 되돌리기

커밋 1개 revert. 새 모듈 셋(`quota.py`·`spec_render.py`·`shadow_v3.py`) 삭제.
`openai_compat` 의 잔량 기록은 한 줄이라 떼면 CHN-1 임시본 그대로다.
발송 경로·스위치를 안 건드렸으므로 카드는 그대로다.

## ④ 측정

라운드로빈 헤더 추적 로그 원문 · 출력 규격 렌더 3장 · 섀도 1일치 표
(7일 표와 전환 시각은 **사용자 확인 뒤**).
