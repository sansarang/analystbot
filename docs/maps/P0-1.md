# P0-1 — 판정이 p_code 를 무시했다. 승자·확신 둘 다 LLM 자기신고였다

## 왜

어젯밤 7432 Parma@Como 에서 같은 경기에 값이 **둘** 나왔고 서로 만나지 않았다:
```
[verdict] Parma@Como 승자 Parma Calcio 1913 · 확신 상 · 서술 287자
[dbref]   확신 상→상
[v3]      Parma@Como 승자 Parma Calcio 1913 · 확신 상
[prob]    game=7432 p_market=0.7712 adj={} p_code=0.72 확신=하   ← 코드 경로
```
시장은 코모 77%, 코드 확신은 `하`인데 카드로 가는 값은 **파르마 승 · 확신 상**
이었다. 원인은 두 줄이다:

```python
# app/engine/verdict.py:141 — parsed 는 LLM JSON 그대로다
out = {"승자": str(parsed["승자"]).strip(), "확신": level(parsed.get("확신")), ...}

# app/engine/verdict.py:30 — CONF-1 안전장치는 expected 를 줘야 걸린다
def level(raw, expected=None):
    if expected is None:
        return t if t in LEVELS else "하"      # ← 자기신고 통과
```
`decide()` 는 `level(parsed.get("확신"))` 로 **expected 없이** 부른다.
`gate_vs_llm()` 은 `analyze.py:180` 에 있지만 이 경로가 부르지 않는다.

## 왜 A 가 아니라 B 인가 (2026-09-15 사용자 결정)

`decide()` 안에서 p_code 를 읽으려면 시장 뼈대가 판정보다 **앞**에 와야 하는데,
지금 계약 두 개가 그 반대를 잠그고 있다:
```
tests/test_prob_market_spine.py:107  verdict.py 에 "p_code" 글자가 있으면 실패
tests/test_prob_market_spine.py:151  judge_matchup 이 _attach_market_spine 보다 앞
```
그래서 **B**: `decide()` 는 손대지 않고, 뼈대가 붙은 **뒤에** `apply_winner` 를
코드 값으로 한 번 더 불러 덮어쓴다. 계약 2개 다 산다. LLM 프롬프트에 배당이
들어가지 않는다는 성질도 그대로다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
_attach_market_spine(pool, jg)
  app/pipeline.py            2973(야구) · 3110(축구) — 둘 다 judge 뒤
```

## ② 이 변경이 **깨뜨릴 수 있는** 기존 동작

- `llm_winner`/`llm_level` 원장 칸이 코드 값으로 오염된다 → **덮어쓰기 전에
  `jg["llm_verdict"]` 로 대피**시키고 pick_ledger 가 그것을 읽게 한다.
- `_apply_extras` 가 `level()` 을 expected 없이 부른다 → 두 번째 호출에서
  코드 등급이 다시 자기신고로 떨어진다. expected 를 받게 고친다.
- 야구 경로도 같은 `apply_winner` 를 쓴다 → 2-way(`승자`)·3-way(`결과`) 둘 다
  덮어쓰기가 성립해야 한다.
- `p_code` 가 None(시장 없음)이면 승자를 **지어내지 않는다** — 승자 None ·
  확신 하 · 보드.
