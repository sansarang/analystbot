# STR-1 영향 지도 — `season` 이라는 이름이 거짓말이었다

## 1. 무엇이 틀렸나 (실측 원문)

오늘 내보내기:

```json
"season": {"gs": 6, "ip": 32.3, "era": 3.06, "k9": 6.4, "bb9": 2.78, "hr9": 1.11},
"season_note": "우리 DB 의 선발 등판 집계다 — 공식 시즌 스탯 API 값이 아니다. FIP 는 리그 상수가 없어 null."
```

`gs` 가 1~6 이다. 공식 시즌은 28선발인데 우리 값은 **우리가 본 등판 전부**다.
주석으로 사과하면서 이름은 그대로 둔 자리다 — **읽는 쪽은 이름을 믿는다.**
페이블이 "시즈 7선발 2.70"을 공식 시즌으로 읽은 것이 그 증거다.

CLAUDE.md §9: 표시용 필드는 이름에 `_official`·`_display` 를 붙인다.
우리 집계는 표시용도 공식도 아닌 **최근 N등판**이므로 `recent6` 가 맞다.

## 2. 어디를 고치나

| 파일 | 무엇 |
|---|---|
| `app/export/for_fable.py` | `season` → `recent6` · `season_official` 칸 신설 |
(그것뿐이다 — 아래 ①을 보라)

## 3. 영향 지도 5문

**① 공식값을 받을 경로를 새로 만들어야 하나.**
🔴 **아니다. 이미 있다 — 그런데 아무도 안 부른다.**
`app/collectors/starter_season.py` 가 `hydrate=stats(group=[pitching],
type=[season])` 로 공식 시즌 스탯을 받고, 이름→id 는 공식 로스터 지도
(`_roster`)로 푼다(이름 매칭 금지 규칙을 지키는 방식이다).
`attach()` 가 `research.{side}_starter_season` 을 채우게 돼 있다. 그런데:

```
$ rg -n "starter_season" app/pipeline.py
(출력 없음)
```

캐시 실측에서도 그 칸이 없다 — `away_starter_recent`·`starter_status` 는 있고
`*_starter_season` 은 **아예 없다**. "만들어 놓고 안 이음"이 또 한 건이다.

**② 그러면 내보내기가 직접 부르면 되나.**
안 된다. 내보내기는 **읽기 전용**이고 새로 수집하지 않는다 — `_read_cache`
머리말이 그 규약을 적고 있다. 배선은 파이프라인 쪽 일이고 별건이다(2-4-b).
이 단위는 **읽는 자리를 만들어 둔다** — 배선이 붙는 순간 값이 흐른다.

**③ 이름을 바꾸면 무엇이 깨지나.**
`season` 을 읽는 곳은 내보내기 안뿐이다 — `empty_game`(스키마) ·
`_starter_block`(채움) · `to_md`(표시) 셋. 판정 경로는 이 문서를 읽지 않는다
(내보내기는 산출물이고 입력이 아니다). `rg '"season"'` 으로 확인한다.

**④ 공식 시즌값이 판정에 새나.**
새면 안 된다. v1.4 동결 규칙이 **시즌 누적(방어율·타율·순위)을 판정 입력에서
금지**한다. 그래서 이름에 `_official` 을 붙이고 **표시용**임을 이름이 말하게
한다. 실제 값 채우기는 다음 단위(STR-2)이고, 이 단위에서는 칸과 사유만 만든다.

**⑤ 무엇이 조용히 0이 되나.**
id 가 없는 과거 경기는 `season_official` 이 null 이다. 그때 **빈 dict 을 내지
않고 사유를 적는다** — "공식 시즌 스탯을 아직 안 받았다"와 "그 투수가 0이닝을
던졌다"는 다르다.

## 4. 안 하는 것

- 공식 시즌 스탯을 **이 단위에서 부르지 않는다**(STR-2).
- KBO·NPB 선발 id 를 만들지 않는다 — statsapi 가 없는 리그다.
- 판정 경로에 `season_official` 을 잇지 않는다. 영원히 표시용이다.
