# MBL-1 — 야구 모델 로더 (야구 모델 지시문 2단계)

## 왜

자료13(야구 모델 확률)을 만들려면 과거 경기·선발·타순·투구 기록이 한 곳에
있어야 한다. 운영 DB 에는 **MLB 452경기(2024-08~)** 뿐이라 모델 적합에 부족하다.
statsapi 에 2018~2026 시즌이 전부 있다(시즌당 약 2,470경기, 실측 2026-09-13).

🔴 **statsapi 는 `season` 파라미터만 신뢰한다.** 실측:
```
schedule?sportId=1&season=2024&gameType=R  → totalGames=2469
schedule?sportId=1&date=2024-07-01         → totalGames=3      ← 날짜 단일 조회 결함
```
날짜별로 긁으면 경기를 통째로 놓친다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
새 패키지 app/model_baseball/ — 읽는 곳은 3·4단계(아직 없다)
운영 코드와 분리한다: app/engine·app/collectors 를 건드리지 않는다
저장소: data/model_baseball.sqlite (로컬 파일. 운영 Postgres 와 무관)
```
빌려 쓰는 원본:
| 무엇 | 원본 |
|---|---|
| statsapi 도메인 | 이미 봇이 쓰는 `statsapi.mlb.com/api/v1` |
| 배당 원파일 | `data/raw/odds_hist/*.xlsx` (Wayback 확보분 2010~2021) |

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `app/model_baseball/{__init__,load,teams}.py` | 새 패키지 |
| `data/model_baseball.sqlite` | 로컬 분석용 DB. **운영 DB 아니다** |

🔴 **팀·선수 키는 statsapi id 를 그대로 쓴다** — 이름 매칭을 피한다(지시문 2단계).
   KBO·NPB 는 6단계에서 별칭표를 만든다.
🔴 **머니라인은 원값으로 저장한다.** 디빅은 4단계다 — 여기서 확률로 바꾸면
   그 변환이 두 곳에 생긴다.

## ③ 리그·종목 분기

`league` 칼럼 하나로 가른다(`mlb`/`kbo`/`npb`). 지금은 mlb 만 적재한다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **날짜 조회 결함으로 경기 누락** | `season` 파라미터만 쓴다. 계약이 소스에 `date=` 부재를 단언 |
| 🔴 **이닝 표기를 소수로 읽는다** | `6.1` 은 6.1이 아니라 6과 1/3이다. `parse_ip` 계약 5케이스 |
| 같은 경기 중복 적재 | `game_id` PK + upsert. 계약 |
| 종료 안 된 경기가 섞인다 | `codedGameState == "F"` 만. 계약 |
| 배당을 여기서 확률로 바꾼다 | 소스에 `devig`·`implied_prob` 부재 계약 |
| 운영 DB 를 건드린다 | SQLite 파일만 쓴다 |

⚠️ **아직 못 잰 것**: 전 시즌 다운로드 소요 시간·요청 수. 한 시즌으로 먼저 재고
   보고한다(지시문 1단계 완료 조건이 요청 수·시간 기록을 요구한다).

## ⑤ 사본

- 팀 별칭표를 만들지 않는다 — statsapi id 가 키다.
- 디빅·확률 변환을 여기 두지 않는다.
