# MBM-3 — 모델이 승률의 부호를 뒤집었다. 좋은 투수진이 지는 값을 냈다.

## 왜 (재현)

MBF-1 스모크에서 **홈 선발 1실점/6.2이닝 · 원정 선발 5실점/4.1이닝**인데
`p_model = 0.3499` 가 나왔다. 최소 재현:

```
sp_home 3.312  sp_away 5.562   (낮을수록 좋다)
bp_home 4.029  bp_away 4.800
타선 동일 · 구장 동일          → p_home = 0.364      ← 🔴 뒤집혔다
```

원인은 추측이 아니라 소스에 있다 (`model.predict`):

```python
ra_h = expected_runs(away["sp"]["ra9"], away["sp"]["ip"], away["bp"]["ra9"])
ra_a = expected_runs(home["sp"]["ra9"], home["sp"]["ip"], home["bp"]["ra9"])
...
h = pythag(rs_h, ra_h)      # rs_h = 홈 타선
```

`ra_h` 에 **원정 투수진**이 들어갔다. 그러면 `pythag(rs_h, ra_h)` 는
"홈 타선 ÷ 원정 투수진" — 둘 다 **홈이 뽑는 득점**을 말하는 값이라 팀 강도가
아니다. 그리고 홈 투수가 좋을수록 `ra_a` 가 작아져 **원정** 피타고리안이
올라간다. 정확히 부호가 반대다.

⚠️ MBM-2 는 **분포만** 쟀다(홈승률 0.5216, 절사 0.32~0.68). 분포는 부호가
   뒤집혀도 그대로다 — 그래서 못 봤다. **방향을 재는 계약이 없었다.**

원장 `p_model` 에만 기록되고 있었다(MBF-1 커밋 이후 오늘 슬레이트부터).

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `predict` 의 `ra_h`·`ra_a` 배정 | **값이 바뀐다**. 새 키·새 파일 없음 |
| `exp_total` | **안 바뀐다** — `(rs_h+ra_h+rs_a+ra_a)/2` 는 넷의 합이라 배정과 무관 |

## ③ 리그·종목·경로 분기

없다. 한 함수 안의 배정이다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **부호가 또 뒤집힌다** | 방향 계약 — 선발·불펜·타선 각각 한 축만 좋게 하고 `p_home > 0.5` |
| 총득점이 같이 바뀐다 | 수정 전후 `exp_total` 동일을 단언 |
| 대칭이 깨진다 | 양쪽을 맞바꾸면 `p_home + p_away ≈ 1 + 2·hfa` |
| 절사가 풀린다 | 극단 입력에서 0.32~0.68 유지 단언 |

⚠️ **아직 못 잰 것**: 실데이터 AUC. MBL-1 로 적재한 2024 시즌 sqlite 는
   임시 파일이라 남아 있지 않다. 4단계(백테스트 A/D)에서 재적재해 잰다.
   **그때까지 `MODEL_W` 는 0 이다** — 이 값이 발송에 닿지 않는다.
