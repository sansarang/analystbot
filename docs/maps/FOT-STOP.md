# FOT-STOP — FotMob 대량 호출 중단 (영향 지도 5문)

사용자 결정 2026-09-21: **"결정 1 (FotMob): 끄는 방향. a. 즉시: 대량 호출
중단(1-i-3 소급 날짜 루프·신규 확장 금지). 현재 일일 호출 수를 보고."**

## ① 🔴 일일 호출 수 — 보고

```
satellite_15m   96회/일 × 축구 26경기 × 2호출
   slate(날짜)        2,496   ← 같은 날짜를 **매 경기마다 다시 받는다**
   matchDetails       2,496
finals_job(13시)  2일 × 리그 6            12
pipeline upsert_slate  리그당 1회        ≈ 10
tools/backfill_results 수동 45일 × 2        90  (돌릴 때만)
──────────────────────────────────────────────
하루 합계                              ≈ 5,014 회
그중 **중복 slate**                    ≈ 2,400 회 (**48%**)
```

⚠️ **계산값이다.** 근거: 축구 경기 수는 실측(최근 7일 평균 26.1경기/일),
   주기는 `_job_specs()` 의 `IntervalTrigger(minutes=15)`, 호출 수는 `attach`
   본문(`slate` + `match_lineup`). `MIN_GAP_SEC=2` 라 한 사이클 52호출 =
   104초로 15분 주기 안에 들어간다 — **막히지 않고 그대로 나간다.**
⚠️ 정확한 실측은 FotMob 이 DS-1 런타임을 지나야 가능하다(집계가 거기 있다).
   지금 재려고 한 사이클을 더 돌리는 것은 "즉시 중단" 지시와 어긋나 하지 않았다.

## ② 🔴 절반이 순수한 낭비였다

`attach` 가 경기마다 `slate(날짜)` 를 새로 받는데, 같은 사이클의 26경기가
**같은 날짜**다. 캐시가 없었다(`grep cache app/collectors/fotmob.py` → 0건).

## ③ 무엇을 하나

| 대상 | 조치 |
|---|---|
| `backfill(dates)` 소급 루프 | **관문**을 단다 — `bulk_allowed=True` 없이는 요청 0 |
| `slate(date)` | **짧은 캐시**(TTL) — 같은 사이클의 중복을 없앤다 |
| 신규 확장 | 하지 않는다 |

🔴 **끄는 것이 아니라 줄이는 것이다.** 전환(`enabled=false`)은 **c 단계**이고
   사용자가 대체 표를 본 뒤다. 지금 끄면 축구가 통째로 빈다.

## ④ 사본이 생기나

- TTL 값은 `fotmob.SLATE_TTL_SEC` 하나. 캐시는 프로세스 안 dict 다
  (Redis 를 쓰면 키 규약이 하나 더 생긴다 — 이 목적에는 과하다).
- ⚠️ 캐시를 **영원히 두지 않는다.** 진행 중 경기의 상태가 바뀐다.
  계약이 `0 < TTL <= 600` 을 잠근다.

## ⑤ 되돌릴 수 있나

`backfill(bulk_allowed=True)` 로 언제든 돈다 — 관문이지 삭제가 아니다.
캐시는 `clear_slate_cache()` 로 비운다.

## ⑥ 틀렸을 때 누가 알려주나

계약 6건: 소급 루프에 관문이 있나 · 부르면 요청 0 인가 · **승인하면 도나** ·
같은 사이클 slate 를 다시 안 받나 · 캐시가 날짜별로 갈리나 · TTL 이 유한한가.
