# ANL-2 — 분석 프롬프트에 **출력 지시가 없다.** 그래서 산문이 온다

## 왜

실측 2026-09-17 운영: 분석 대상 **6건(시장 과대 4 · 가치 의심 2) 전부 실패**,
그래서 `main_axis` 0/13.

한 번 불러 원문을 봤다:
```
[matchup_prelim] gemini/gemini-3.5-flash-lite 응답이 JSON 이 아니다 (1033자)
  앞='제공해주신 분석 데이터를 바탕으로 **Cleveland Guardians vs Detroit
      Tigers** 경기 결과를 예측 및 정리해 드립니다.\n\n---\n\n### [경기 정보]…'
```
**마크다운 산문이다.**

판정 프롬프트는 되고 있다 — 거기엔 이 줄이 있다(`prompts.py` :29 :104 :338):
> "아래 JSON만 출력한다. 다른 텍스트, 마크다운 백틱 금지."

`analyze.build_input` 에는 **그런 줄이 한 줄도 없다.** 자료 블록만 준다.
**JSON 을 내라고 말한 적이 없으면서 JSON 이 아니라고 버렸다.**

## 🔴 함정 — `build_input` 은 **검사 기준으로도** 쓰인다

`l1` 이 `build_input(blk)` 을 불러 두 가지를 잰다:
```python
if bare not in blk_text.replace(" ", ""):   # 시장_판단_이유의 숫자가 입력에 있나
src = _nouns(blk_text)                      # 결정축_근거가 입력의 사실인가
```
지시문을 그냥 붙이면 **그 검사가 느슨해진다** —
- 지시문에 숫자가 들어가면 LLM 이 그 숫자를 인용해도 통과한다
- 지시문의 낱말(`결정축`·`반대축`…)이 `src` 에 들어가 **근거를 스키마 이름으로
  때워도** 통과한다

→ **자료와 지시를 가른다.** `build_input(blk)` 는 종전 그대로(자료만) 두고,
   실제 호출만 `with_schema=True` 로 지시를 덧붙인다. `l1` 은 안 바뀐다.
→ 그리고 지시문에 **숫자를 한 글자도 안 쓴다**(칸 이름·라벨만).

## ① 이 함수/상태를 읽는 곳 **전부**

```
analyze.build_input          ← 고치는 곳 (인자 추가. 기본값은 종전 동작)
analyze.run (:275)           ← 여기만 with_schema=True
analyze.l1 (:138)            ← build_input(blk) 그대로. **안 바뀐다**
analyze.SCHEMA/DIRECTIONS/MARKET_VIEWS  ← 지시문을 **여기서 만든다**(사본 금지)
prompts.py "아래 JSON만 출력한다…"       ← 되고 있는 문장. 계약이 대조한다
tests/test_u12_final.py 등     ← build_input 을 부르는 테스트
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **`l1` 의 판단이 바뀌면 안 된다.** 기본값 `with_schema=False` 라
  `build_input(blk)` 결과가 **글자 하나 안 바뀐다.** 계약이 그것을 잰다.
- 🔴 **지시문에 숫자를 쓰지 않는다** — 숫자 검사의 기준이 넓어진다.
  계약이 지시문에 숫자가 없는지 잰다.
- 🔴 **칸 이름·라벨을 손으로 적지 않는다.** `SCHEMA`·`DIRECTIONS`·
  `MARKET_VIEWS` 에서 만든다 — 스키마가 바뀌면 지시문이 따라간다.
- 🔴 **판정 프롬프트를 안 건드린다.** 거긴 되고 있다. 문장만 베끼고,
  계약이 그 문장이 `prompts.py` 에 실재하는지 대조한다(사본 감시).
- ⚠️ 이 수정으로 **호출 횟수·모델·max_tokens 는 안 바뀐다.** 재시도(A)와
  실제 모델 기록(C)은 별건이다.
