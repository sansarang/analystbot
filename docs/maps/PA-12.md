# PA-12 — 야구는 기사를 모으고도 추출을 안 한다. 그래서 확인이 0건이다

## 왜

원장 실측(2026-09-16):
```
g8773 방향=home need 5개
   need: home.out · home.doubt · home.last3 · away.out · away.doubt
   확인=[]  반증=[]  미상=["home.out","home.doubt","home.last3","away.out","away.doubt"]
```
가설을 5개 세웠는데 **5개 전부 미상**이다. 재현에서도 같은 그림이 나온다:
```
[재현] 야구 수집 기사 35건 · 추출 호출 0회
```

원인은 `satellite.gather:815` 한 줄이다:
```python
await _write_cache(redis, sport, gid, articles)   # ← 야구도 기사는 저장된다
if sport == "soccer":                              # ← 이 줄
    facts = await extract_game_facts(...)
    await _write_extract(redis, sport, gid, facts)
```
기사는 모으는데 **사실을 뽑는 단계만 축구로 막혀 있다.** `read_extract` 가
빈 dict 를 돌려주고 `confirm` 이 need 전건을 '미상'으로 찍는다.

🔴 **가설을 세우고 아무것도 확인하지 못한 채 판정한다.** 야구가 동전 던지기
   였던 이유의 한 조각이 여기 있다(AUC 0.5122 · 브라이어 0.2537).

## SCT-5 를 어기는가 — 아니다

SCT-5 가 막은 이유는 *"야구 스키마(**타순·등판**)는 4-4 에 없고, 없는 칸을
억지로 채우면 그게 곧 거짓 재료가 된다"* 였다.

그런데 **야구 가설이 요구하는 칸은 타순·등판이 아니다**:
```
야구 need   = out · doubt · last3
추출 스키마 = team · out · doubt · xi_status · xi · bench_notable · last3 · midweek · notes
```
셋 다 종목을 안 가리는 공용 칸이다. 그리고 U6 의 `apply_need` 가 **need 밖
칸을 판정 입력에서 뺀다** — 야구에 열어도 타순·등판 같은 없는 칸은 애초에
만들어지지 않는다. SCT-5 의 걱정이 구조로 이미 해결돼 있다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
satellite.gather:815              ← 고치는 곳 (종목 분기)
  ├ _write_cache                  ← 기사. 야구도 지금 저장된다(안 건드린다)
  ├ extract_game_facts(need=…)    ← U6 가 need 인자를 이미 받는다
  └ _write_extract                ← `scout:extract:{sport}:{game_id}`
satellite.read_extract            ← pick_ledger.record_confirm_and_analysis 가 읽는다
hypothesis.need_keys(h)           ← 무엇을 뽑을지 정하는 원본
apply_need(box, side, need_keys)  ← need 밖 칸을 collected_extra 로 옮긴다
satellite_sports 설정             ← 'mlb,kbo,npb,soccer' — 이미 야구 포함
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **축구 동작을 바꾸지 않는다.** 축구는 지금도 추출한다 — 조건이 넓어질
  뿐이다. 계약이 축구 경로를 그대로 잰다.
- 🔴 **LLM 콜이 는다. 상쇄가 없다.** 경기당 1콜(EXT-1 로 이미 1콜)이고
  MLB 15 + KBO 5 + NPB 6 ≈ **하루 26콜 순증**. groq 무료 한도는 분당 8,000
  토큰이라 오늘 아침 잔량이 175까지 내려간 적이 있다. 위성은 15분 잡이라
  분산되고, 같은 URL 묶음이면 다시 묻지 않는다(URL 해시 캐시).
  ⚠️ **처음에 "need 가 비면 콜을 안 낸다"고 적었는데 그건 못 지킨다.**
     `gather` 는 `need` 를 받지 않고, 위성은 **판정보다 먼저** 도는 잡이라
     그 시점에 가설이 아직 없다. 원장에서 읽어오는 길은 있지만 "레저는
     측정 전용"을 어긴다 — 하지 않는다. 그래서 이 단위는 **콜이 순증한다.**
- 🔴 **없는 칸은 애초에 못 만든다.** 추출 스키마에 타순·등판 칸이 없어서
  LLM 이 그 칸을 만들 자리가 없다. SCT-5 의 걱정이 스키마로 이미 막혀 있다.
  (`need` 필터는 축구와 똑같이 `None` 으로 둔다 — 종목을 가르지 않는다.)
- ⚠️ 추출이 실패해도 **기사 수집 반환값은 그대로**다(종전 규약 유지).
- ⚠️ KBO 공시(`_kbo_official`)는 기사 앞에 붙는다 — 추출 입력이 늘어난다.
  그게 목적이다(말소로 결장을 알리는 리그다).

## ③ 되돌리기

되돌리면 야구는 종전처럼 추출 없이 돌고 확인이 전건 미상이 된다.

## ④ 측정

①과 **같은 명령**이 통과한다. 그리고 배포 뒤 야구 슬레이트에서
`[scout] … 추출` 로그가 찍히고, 원장 `confirmed`/`refuted` 가 빈 배열이
아닌 값을 갖는 원문.
