# BIG-2 — 빅매치 태그를 FOT-3·FOT-4 에 연결 (사용자 지시)

## 왜

`BIG-1` 이 태그를 만들었지만 **쓰는 곳이 0** 이다. 두 자리가 이 조건을
기다리며 열려 있었다:
- FOT-3: 양 팀 결장이 **둘 다 미상**일 때 → 빅매치만 구단 공식 RSS 1회
- FOT-4: LLM 추출을 **빅매치에만**(그 외는 구조 JSON 만)

재현:
```
PYTHONPATH=. .venv/bin/python <scratchpad>/repro_big2.py
  → FOT-4 False · FOT-3 False
```

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "is_big_match\|bigmatch" app/ tests/
app/engine/bigmatch.py          정의(BIG-1)
tests/test_bigmatch.py          계약
   → app/ 안 호출부 **0**
```
붙이는 자리 둘: `satellite.extract_game_facts`(FOT-4)와
`satellite_soccer.cross_check_unavailable`(FOT-3).

## ② 만드는/바꾸는 상태

**없다.** 두 함수의 **행동 조건**만 바뀐다.
| 어디 | 전 | 후 |
|---|---|---|
| 추출(FOT-4) | 전 경기 LLM 1콜 | **빅매치만** LLM. 그 외는 구조 JSON 만 |
| 교차검증(FOT-3) | 둘 다 미상이면 `missing` 유지 | 빅매치면 그 사실을 남긴다(구단 RSS 자리 표시) |

🔴 **순위는 호출부가 넘긴다**(BIG-1 규약). 지금 축구 경로에는 리그 순위표가
   없다 — 그래서 **더비만으로** 판정되고, 그 사실이 `reason` 에 남는다
   (`순위 모름 · 더비 아님`). 순위 배선은 별도 단위다.

⚠️ 구단 공식 RSS **수집 자체는 이번에 만들지 않는다**(Phase D3 의 몫이다).
   지금은 "빅매치인데 둘 다 미상"인 경기를 **표시**만 한다 — 그래야 D3 가
   붙을 자리와 그 대상 수를 알 수 있다.

## ③ 리그·종목·경로 분기가 생기는가

축구만이다. 야구는 추출·교차검증 경로를 타지 않는다(SCT-5 부터 그렇다).

## ④ 실패하면 "시끄럽게" 실패하는가

- LLM 을 건너뛰면 **왜 건너뛰었는지** 로그에 남긴다(`빅매치 아님 — LLM 생략`).
  조용히 0콜이 되면 "모델이 죽었다"와 구분이 안 된다.
- 빅매치인데 결장을 둘 다 모르면 `missing` 에 `(빅매치)` 를 붙여 남긴다.

## ⑤ 시스템에 이미 있는 사실을 다시 적고 있지 않은가

- 더비·규칙·상수는 `bigmatch`/`derbies.yaml` 한 곳.
- 결장 규칙(FotMob 정본·TM 2순위)은 FOT-3 그대로 — 이번 단위가 바꾸지 않는다.
