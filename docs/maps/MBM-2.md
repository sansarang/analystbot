# MBM-2 — 확률이 0.04~1.00 으로 폭주했다 (wOBA 환산 계수 과대)

## 왜

MBM-1 의 2024시즌 실행 결과:
```
실제 홈승률          0.5216      ← 지시문 범위(0.52~0.55) 안. 여기는 정상
모델 홈승률(평균 p)   0.5380
확률 범위            0.0400 ~ 1.0000 (표준편차 0.2509)   ← 🔴 폭주
선발 ra9  평균 4.441 · 표준편차 0.874 · 범위 2.23~8.34   ← 정상
기대 총득점 평균      8.78                                ← 정상
```
**야구 단일 경기 승률이 100% 일 수 없다.** 이 저장소가 이미 적어 둔 근거
(`scoring.cap_probability`): *"완벽한 정보를 가져도 MLB 단일 경기 예측 상한은
약 72% 이고 학계 최고 모델은 61.77% 다."*

원인은 wOBA→득점 환산 계수다. `WOBA_TO_RPG = 1/0.0125 = 80` 으로 뒀는데
표준 환산은 `wRAA/PA = (wOBA − lg)/1.25`, 경기당 타석 약 38 → **계수 ≈ 30** 이다.
80 을 쓰면 wOBA 0.04 차이가 **3.2점**이 아니라 **8.5점** 차이가 된다.

## ① 이 함수/상태를 읽는 곳 **전부**
```
model.off_axis → team_offense → predict.rs_h/rs_a → win_prob
읽는 곳은 model.py 안과 4단계(아직 없다)
```

## ② 만드는/바꾸는 상태
| 상태 | 성격 |
|---|---|
| `WOBA_TO_RPG` | 80 → 표준 환산(≈30). 계산식으로 적는다 |
| `P_CAP` | 승률 상하한. 🔴 `config.max_win_prob_mlb` 를 그대로 쓴다 |

🔴 **숫자를 두 곳에 적지 않는다** — 0.68 은 이미 `config.max_win_prob_mlb` 다.
   모델이 따로 0.68 을 박으면 그것이 다음 사본이다.

## ③ 리그·종목·경로 분기
분기를 만들지 않는다. 상한은 종목별 설정에서 오고, KBO·NPB 는 6단계에서
같은 자리(`config`)의 값을 쓴다.

## ④ 조용히 실패하는가
| 위험 | 대응 |
|---|---|
| 🔴 **또 폭주한다** | 계수 범위 계약 + 극단 입력에서 상하한 계약 |
| 절사가 캘리브레이션을 가린다 | 4단계 로지스틱 적합이 절사 **전** 값으로 학습하도록 남긴다 |
| 상한을 모델이 따로 적는다 | `config.max_win_prob_mlb` 대조 계약 |

⚠️ 못 잰 것: 계수를 고친 뒤의 확률 분포·AUC. 재실행으로 잰다.

## ⑤ 사본
- 승률 상한을 새로 정하지 않는다.
- wOBA 가중치는 `league_means` 와 `_woba` 가 같은 값을 쓴다(한 벌).
