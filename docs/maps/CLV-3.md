# CLV-3 — CLV 의 부호가 뒤집혀 있었고, 어느 쪽 배당인지도 안 가렸다

## 왜 (실측 2026-09-13)

CLV 는 **"우리가 돈을 버는가"에 답하는 유일한 지표**다. 적중률은 시장을
베끼면 올라가지만 수익은 마진만큼 진다 — 그걸 가르는 게 CLV 다.
그 지표가 지금 **두 군데서 망가져 있다.**

### ① 부호가 식과 말이 반대다

```python
def clv_pp(at_verdict, closing):
    """양수면 우리가 좋은 값에 잡았다."""      ← 머리말
    return round((a - b) * 100, 2)            ← (판정시각 확률 − 마감 확률)
```
`clv_pp(2.00, 1.50) = −16.67`. 그런데 2.00 에 잡아 1.50 에 닫혔으면
**시장을 크게 이긴 것**이다(우리가 더 좋은 값을 먹었다). 종전 기존 계약도
그 값을 그대로 박아 두고 있었다(`test_clv는_확률_퍼센트포인트_차이다`).

🔴 수익 지표의 부호가 뒤집히면 **결론이 통째로 뒤집힌다.** "CLV 평균 양수"를
   보고 잘하고 있다고 읽는 순간 정반대다.

### ② 어느 쪽 배당인지 안 가린다

```sql
SELECT o.odds FROM odds_snapshots o
 WHERE o.game_id = $1 AND o.market = 'h2h'     -- side 조건이 없다
 ORDER BY o.captured_at DESC LIMIT 1
```
실측 game 1741: 같은 경기에 **두산 38행 · NC 38행**이 있다. 이 쿼리는
**마지막에 들어온 아무 쪽**을 집는다. 판정 시각엔 홈, 마감엔 원정을 집으면
그 차이는 아무 의미가 없다. 오늘 찍힌 8건도 어느 쪽인지 모른다.

⚠️ 함께 확인한 것(고치지 않는다): 과거 122행이 빈 것은 결함이 아니라
   **기능이 오늘 태어났기 때문**이다. `odds_closing` 이 0건인 것도 채점이
   아직 안 돌았기 때문이고, 그 경로는 **한 번도 실행된 적이 없다.**

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "clv_pp\|_CLV_SNAP\|_CLV_SAVE\|record_clv" app/
app/engine/pick_ledger.py   정의 · record_analysis 1회(verdict) · grade_pending 1회(closing)
   → 밖에서 부르는 곳은 없다. 값은 `pick_ledger.clv` 컬럼에만 쌓인다
```
`clv` 컬럼을 읽는 집계는 아직 없다 — 그래서 **지금 고치면 소급 오염이 없다.**

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `clv_pp` 반환 부호 | **뒤집는다**(마감 확률 − 판정시각 확률) |
| `_CLV_SAVE` 두 SQL | 같은 방향으로 맞춘다 |
| `_CLV_SNAP` | `pick_ledger.predicted_side` 로 **우리 쪽 팀만** |
| 기존 `clv` 4행 | 전부 `0.00` 이라 부호가 무의미하다. 손대지 않는다 |

🔴 **고른 쪽을 모르면 기록하지 않는다.** `predicted_side` 가 NULL 이면
   반대쪽 값으로 채우지 않는다 — **무의미한 값이 NULL 보다 나쁘다.**
⚠️ 새 컬럼·새 테이블 없음. 기존 칸의 의미를 바로잡는 것뿐이다.

## ③ 리그·종목·경로 분기

없다. 축구는 배당 스냅샷 자체가 0 이라(실측 오늘 12경기 전부) 종전처럼
NULL 로 남는다 — 이 수정과 무관한 별건이다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **부호를 반만 고친다**(파이썬만, SQL 은 그대로) | 두 SQL 문자열의 뺄셈 순서를 계약이 단언 |
| 🔴 반대쪽 배당이 섞인다 | `_CLV_SNAP` 에 `o.side`·`predicted_side`·`pick_ledger` 존재를 단언 |
| 고른 쪽을 모를 때 아무 값이나 쓴다 | 스냅샷 None 이면 `execute` 를 **한 번도 안 부른다**는 계약 |
| 기존 계약이 옛 부호를 박고 있다 | 그 계약(`test_clv는…`)을 새 부호로 함께 고친다 |
| SQL 타입 오류 | 문자열 계약은 못 잡는다 — **실DB 실행이 유일한 검증**(CLV-2 전례). 배포 후 첫 채점에서 확인한다 |

⚠️ **아직 못 잰 것**: CLV 평균값. `odds_closing` 경로가 아직 한 번도 안
   돌았다. 오늘 밤 채점이 처음이다 — 거기서 처음 숫자를 본다.

## ⑤ 사본

내재확률 변환을 다시 쓰지 않는다(`_implied_prob`). 부호 규약은 이 파일
한 곳에만 적고, 집계 쪽에 옮겨 적지 않는다.
