# SAT-S4 — 축구에 **층1**을 만든다. Transfermarkt 부상표.

사용자 지시 2026-09-12: "니가 권장하는대로 하고 **토르는 ddg 검색전용**으로
한다 … **인공위성이 핵심이다** 명심해라"

## 왜

지금 축구 위성은 **전부 검색**이다 — 다음/야후 뉴스 + 토르 DDG. 야구에는 그
아래 **구조화된 표**가 한 층 더 있다(`transactions_to_articles`(MLB statsapi) ·
`_kbo_official`(KBO 공시 델타) · `_mlb_velocity_articles`(Statcast)). 축구에는
그 층이 통째로 없다. 검색은 "제목에 있으면" 얻는 것이고, 표는 **칸으로** 얻는다.

실측 2026-09-12 (운영 컨테이너, 7리그 전수):

```
한 URL 모양(verletztespieler/wettbewerb/{code})으로 7리그 전부 파싱된다.
행 수  세리에A 67 · 분데스 67 · EPL 60 · J1 50 · 덴마크 35 · 라리가 24 · K리그1 18
칸     선수 · 소속 · 부위 · 복귀예정일
오늘 실제 대진에 걸린 예:
  Rodrygo / Real Madrid / Cruciate ligament tear / 30/09/2026
  Young-jae Seo / Daejeon Hana Citizen / Ankle injury
  Nicolai Vallys / FC Tokyo / Cruciate ligament injury
```

### 실측이 바꾼 설계 — 퍼지 매칭은 쓸 수 없다

처음엔 토큰 자카드로 우리 DB 팀명 ↔ TM 팀명을 맞추려 했다. **오매칭이 나왔다:**

```
✓ AC Milan → Inter Milan   0.50 / 2위 0.00      ← 인테르 부상자가 AC밀란 경기에 붙는다
```

`AC` 가 두 글자라 토큰에서 빠지고 `milan` 만 남았다. 그리고 부상표에는 **그날
부상자가 있는 팀만** 있어서 진짜 AC밀란이라는 선택지가 목록에 아예 없었다.
리그 전체 명단으로 후보를 늘려 보려 했으나 명단 페이지는 그 링크 모양을 쓰지
않는다(팀 1~2개만 잡힌다). 손으로 만든 불용어 목록도 역효과였다 —
`city`·`united`·`real` 을 지우자 **맨시티·맨유·Athletic Club 을 내가 못 맞췄다.**

→ **퍼지를 버린다.** 법인격 토큰(`FC`·`AC`·`SK`·`calcio` …)만 떼고 **완전일치**,
  진짜로 이름이 다른 것만 **실측 별칭표 10줄**. 전수 재측정:

```
맞음 76 · 표에없음 14 · 오매칭 0 · TM키충돌 0
```

"표에없음" 14건은 대부분 진짜로 그날 부상자가 없는 팀이다(AC밀란·브뢴뷔·
마치다·부천·안양·강원·상주). **우리는 "없다"와 "이름이 안 맞는다"를 가를 수
없으므로 "부상자 없음"이라고 쓰지 않는다** — 아무것도 안 붙이고 키를 로그에 남긴다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rln "gather_soccer" app/ tests/
app/collectors/satellite_soccer.py   정의
app/collectors/satellite.py          _ADAPTERS["soccer"]  ← 유일한 호출부
tests/test_satellite_split.py · tests/test_satellite_soccer.py

위성 산출물을 읽는 곳:  satellite.read_cache → gather._satellite → order_v3 채택
```

빌려 쓰는 원본 — **다시 만들지 않는다**:
| 무엇 | 원본 |
|---|---|
| 기사 모양 | `satellite._article` |
| 리그 코드가 사는 자리 | `app/leagues.py` (`fd_code`·`odds_key`·`elo` 옆) |
| 리그 라벨 | `LEAGUES[...]["label"]` (계약이 전수 대조) |
| 검색·본문·토르 | 그대로 — 이 단위는 **검색을 건드리지 않는다** |

## ② 만드는/바꾸는 상태

| 상태 | 성격 | 다른 곳이 다른 규칙으로 갱신하나 |
|---|---|---|
| `LEAGUES[*]["tm_code"]` | 새 키 7개 | 아니다. 읽는 곳은 위성 하나 |
| `SOC.TM_ALIAS` · `tm_key` | 새 표·새 함수 | 🔴 `SOCCER_ALIAS`(검색용 한국어)와 **다른 표**다. 섞으면 한쪽 고칠 때 다른 쪽이 깨진다 |
| `SOC._TM_CACHE` | 프로세스 내 캐시 (리그·날짜) | 날짜가 바뀌면 통째로 버린다 |
| 기사 `age_h` | 층1 은 `0.0` | 🔴 아래 |

🔴 **`age_h=None` 이면 층1 이 가장 먼저 버려진다.** `gather._satellite` 가
   `age_h is None` 을 뒤로 보내고 `MAX_SAT=15` 에서 자른다. 축구는 이미
   뉴스 12 + 토르 2 를 쌓으므로 층1 이 정확히 그 경계에 선다. 방금 받은
   **살아 있는 표**이니 `0.0` 이 정직하다. 계약이 잠근다.

⚠️ DB·Redis·env·프롬프트·max_tokens 를 건드리지 않는다.

## ③ 리그·종목·경로 분기

**새 분기를 만들지 않는다.** 이미 있는 `_SOCCER_SOURCE` 의 리그가 곧 대상이고,
코드는 `LEAGUES` 에서 온다. 야구는 한 글자도 안 바뀐다(파일이 다르다).

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **남의 팀 부상자가 붙는다** ← 가장 큰 반대 위험 | 퍼지 금지 계약 + AC밀란/인테르 계약 + 키 충돌 전수 계약 |
| 🔴 층1 이 `MAX_SAT` 에서 잘린다 | `age_h == 0.0` 계약 |
| 표에 없는 팀을 "부상자 없음"으로 단정 | 기사를 만들지 않는다 + 키 로그. 계약 |
| 별칭이 빠져 그 팀만 조용히 0 | 별칭표 10줄을 값으로 단언 + 76쌍 중 17쌍 대조 |
| 리그를 빠뜨린다 | `_SOCCER_SOURCE` 전수를 돌며 받는지 단언 |
| 리그 코드를 위성에 베껴 적는다 | `hasattr(SOC, "_TM_CODE")` 부재를 단언 |
| 부상표가 터져 뉴스까지 죽는다 | 층1 은 try/except, 로그 한 줄. 계약 |
| 경기마다 표를 다시 받는다 | 리그·날짜 캐시. 호출 1회 계약 |
| 🔴 **계약이 실제 HTTP 를 때린다** | autouse 로 `_tm_fetch` 를 기본 봉인(SAT-S2 `리그앙` 전례) |
| 토르가 층1 에 붙는다 | `_tm_fetch` 에 tor 부재 단언 + `tor_search` 머리말에 실측 |

⚠️ **아직 못 잰 것**
- 실제 슬레이트에서 층1 이 몇 건을 더하고, `MAX_SAT=15` 에서 무엇이 밀려나는가.
  `age_h=0.0` 으로 층1 은 살지만 **뉴스 뒤쪽이 잘린다.** 첫 사이클에서 잰다.
- **출전정지**는 못 찾았다. `sperrenausfaelle` 는 200 인데 행 0 이고
  (EPL·세리에A·K리그1·J1 전부), 부상표에 정지 항목은 없다. **모른다**로 남긴다.
- 라리가 부상표에 2부 팀(말라가·라싱·데포르)이 섞여 있다. 우리 두 팀으로
  거르므로 새지는 않지만, **표의 리그 정의가 우리와 다르다**는 신호다.

## ⑤ 이미 있는 사실을 다시 적는가

- 리그 코드를 위성에 적지 않는다 — `LEAGUES` 가 원본이고 계약이 강제한다.
- 검색용 한국어 별칭(`SOCCER_ALIAS`)과 TM 별칭(`TM_ALIAS`)은 **목적이 다른 두 표**다.
  합치면 한쪽 실측이 다른 쪽을 망친다.
- 기사 모양을 다시 만들지 않는다 — `_article`.
- 토르 규칙을 문서에만 적지 않는다 — `tor_search` 머리말(코드)에 실측과 함께 둔다.
