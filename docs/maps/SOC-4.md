# SOC-4 — 일정 소스 하나가 막히면 축구 분석이 통째로 죽었다

## 왜

실측 2026-09-12 22:03 (운영 수동 실행). football-data 로 **12경기를 이미 받아
놓고도** 파이프라인이 예외로 끝났다:

```
[football_data] upserted 12 matches for 2026-09-13 (KST)
...
ProviderBlockedError: odds: deploy pre-trip: already OUT_OF_USAGE_CREDITS
```

배당 API 는 **2026-08-27부터 크레딧 소진**이다. 그런데 그 이벤트 조회는
**2순위 소스**다 — football-data 가 커버하지 못하는 리그(J1·K리그1·덴마크)만
담당한다. 1순위가 성공했는데 2순위가 막혀 **전 슬레이트가 0** 이 되는 것은
결함이다. 그리고 이 결함은 **16일째 아무도 모르고 있었다** — 축구는 요청 시에만
도는데, 그 요청이 이 자리에서 죽었다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "upsert_games_from_odds_events\|upsert_games_from_football_data" app/
app/pipeline.py:1441-1450   build_analysis 안의 축구 분기  ← 유일한 호출부
app/collectors/odds.py      정의
app/collectors/football.py  정의
```

그 블록은 `build_analysis` 안에 인라인이라 **따로 시험할 방법이 없었다.**
→ `_load_soccer_fixtures(pool, date, league_key, fd)` 로 **꺼내서** 계약을 건다.
   신규 함수는 태어나는 날 계약과 함께 태어난다.

빌려 쓰는 원본 — 새로 만들지 않는다:
| 무엇 | 원본 |
|---|---|
| 리그별 odds_key | `app/leagues.py` |
| 차단 판정 | `app/api_guard.py` (`ProviderBlockedError`) |
| 1순위/2순위 순서 | 지금 코드 그대로 |

## ② 만드는/바꾸는 상태

| 상태 | 성격 | 다른 곳이 다른 규칙으로 갱신하나 |
|---|---|---|
| `pipeline._load_soccer_fixtures` | 새 함수 (인라인 블록을 그대로 옮김) | 아니다 |
| 예외 처리 | 소스별 try → 경고 로그 | 🔴 아래 |

🔴 **삼키면 "소스가 막혔다"와 "경기가 없다"를 못 가른다.** 그래서 경고에
   **소스 이름과 그 소스가 담당하는 리그**를 함께 남긴다. 계약이 그 문구의
   존재를 단언한다(조용한 0 금지).

⚠️ DB·Redis·env·프롬프트를 건드리지 않는다. 순서·인자·반환값 불변.

## ③ 리그·종목·경로 분기

분기를 만들지 않는다. 지금 있는 1순위(football-data) → 2순위(Odds 이벤트)
순서를 그대로 옮기고, 각 단계를 **독립적으로** 실패할 수 있게 한다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **진짜 실패를 삼킨다** ← 가장 큰 반대 위험 | 소스 이름 + 담당 리그를 경고로. 계약이 두 소스 각각의 로그를 센다 |
| 🔴 1순위 성공이 2순위 실패에 끌려간다 | 성공분이 그대로 반환되는지 계약 |
| 반대로 2순위만 살아도 돌아야 한다 | 반대 방향 계약 |
| 둘 다 막히면 예외 대신 빈손 | 빈손 + 로그 2줄 계약. 이후 "조용한 0" 감시는 기존 경로가 본다 |
| 목 모드 동작이 바뀐다 | `fd.mock` 이면 부르지 않던 기존 동작을 계약으로 고정 |

⚠️ **아직 못 잰 것**: 배당이 막힌 동안 J1·K리그1·덴마크 일정을 **무엇으로**
   채울지는 이 단위의 범위가 아니다. 지금은 "없다"고 말할 뿐이다.

## ⑤ 이미 있는 사실을 다시 적는가

- 리그 목록을 로그에 손으로 적지 않는다 — `LEAGUES` 에서 `fd_names` 가 빈
  리그를 골라 만든다(그 리그가 곧 배당 담당이다).
- 차단 판정을 다시 하지 않는다 — `ProviderBlockedError` 를 그대로 받는다.
