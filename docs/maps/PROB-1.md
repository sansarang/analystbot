# PROB-1 — 확률 뼈대를 시장으로. 조정은 코드가, 서술만 LLM이.

사용자 결정 2026-09-13(결정 1): `p = 시장 확률(디빅) → 검증된 변수로 코드가
±%p → LLM은 서술만`. **(b)·(c) 금지 — LLM 프롬프트에 배당·시장확률·괴리
숫자를 넣지 않는다.** 절대 규칙 2는 유지.

## 왜

운영 원장 178경기 재측정:
```
판정 확률 AUC 0.5122 · 브라이어 0.2537  ← 50%로 찍는 것보다 나쁘다
시장 확률 AUC 0.6421 · 브라이어 0.2394  ← 유일하게 유의
자료12 Elo AUC 0.440~0.477             ← 대체재가 될 수 없다
```

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "_market_probs(" app/pipeline.py
389 정의 · 755 · 1655          ← 북별 디빅·평균까지 이미 한다
$ grep -rn "def implied_probs" app/
app/engine/market_edge.py:41   ← 마진 제거 구현. **다시 만들지 않는다**
$ grep -rn "_run_baseball_matchups\|_run_soccer_matchups" app/pipeline.py
2145 · 호출 1곳씩              ← 여기에 호출 한 줄
```

빌려 쓰는 원본 — 새로 만들지 않는다:
| 무엇 | 원본 |
|---|---|
| 배당 → 디빅 확률 | `pipeline._market_probs` (북별 평균까지) |
| 마진 제거 | `market_edge.implied_probs` |
| 조정 상한 | 사용자 결정 1-2 의 변수별 표 |
| 원장 기록 | `pick_ledger` (CLV-1 과 같은 표) |

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `app/engine/prob.py` | 새 모듈 — `p_market` · `adjustments` · `p_code` |

🔴 **LLM 프롬프트에 배당·확률 숫자를 넣지 않는다.** 계약이 프롬프트 원문을
   grep 한다(결정 1 완료 조건).
🔴 **`p_market` 이 NULL 이면 `p_code` 도 NULL** — Elo 로 대체하지 않는다
   (AUC 0.44~0.48, 혼합하면 더 나빠진다).
🔴 **`pick` 은 결정 6의 CLV 기준 충족 전까지 항상 null.**

## ③ 리그·종목 분기

2-way(야구) / 3-way(축구) 만 가른다. 조정 변수 표가 종목별로 다르다 —
표를 코드에 **한 곳**에 두고 종목으로 조회한다(분기문 아님).

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **배당이 LLM 프롬프트로 샌다** ← 가장 큰 반대 위험 | 프롬프트 전수 grep 계약 |
| 🔴 `p_market` 없는데 0.5 로 채운다 | NULL 유지. 계약 |
| 조정이 상한을 넘는다 | 변수별·합계 상한을 값으로 단언 |
| 조정 근거가 안 남는다 | `adj_pp` JSON 에 `{변수명: %p}`. 빈 조정은 `{}` |
| Elo 가 슬쩍 들어온다 | `prob.py` 에 elo 부재 계약 |
| 승률 상한을 넘는다 | 기존 클립(0.32~0.68 / 0.72) 재사용 |

⚠️ **아직 못 잰 것**: 조정 변수들이 실제로 CLV 를 개선하는가. 결정 6이 잰다.
