# U2 — 파생 시장(핸디·U/O) 저장 + manual 북

## 왜

핸디·U/O 라인이 저장되지 않아 **S8 라인 이동·S9 구조 픽이 통째로 불가능**하다.
`parse_soccer_odds` 는 실소스에 `spread=-0.5`·`overUnder=2.5` 가 있는데
h2h 3행만 내고 버린다.

## 소스 측정 (2026-09-15 17:0x KST · 코드 0 · 사용자 결정 A)

| 소스 | 결과 | 근거 |
|---|---|---|
| 오즈포털 **경기 페이지** | 🔴 불가 | 리그 페이지에 경기 링크 **0개**(JS 렌더). `id`(11411627)는 있으나 slug 불명. ajax 2종 **404** → **U2-b 로 등록만** |
| **ESPN core API** | ✅ 채택 | `sports.core.api` · 정적 JSON. `spread -0.5` · `overUnder 2.5` · `overOdds -110` · `underOdds -115` · `spreadOdds +120/-170` · `moneyLine 135/210/240` · **`open` 블록 포함** |
| FotMob `matchDetails` | 🔴 불가 | `content.odds` 없음. `matchFacts.poll.oddspoll` 은 1X2 **투표**다 |

⚠️ `site.api.espn.com` 은 로컬·서버 양쪽 **403**. `sports.core.api` 만 된다.
⚠️ ESPN `SOCCER_LEAGUES` 에 **ACL 이 없다**(epl·la_liga·serie_a·bundesliga·
   ligue1·eredivisie·kleague1·j1). ACL 은 **manual** 로만 들어온다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
espn_odds.parse_soccer_odds  ← fetch_soccer ← scheduler._espn_soccer_snapshot
espn_odds.from_american      ← CHN 때 만든 축구 전용 환산(재사용)
odds_free.store_rows         ← 적재 공통(snap_tag 는 tag_open 이 붙인다)
odds_snapshots.market        ← markets.py · book_gap · record_move · S9(예정)
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **h2h 행이 줄면 안 된다.** 파생 시장을 더하는 것이지 바꾸는 게 아니다.
  계약이 h2h 3행이 그대로인지 본다.
- 🔴 `snap_tag='open'` 을 ESPN 응답의 `open` 블록에서만 붙인다. 현재가에
  붙이면 거짓 개장가가 된다 — 계약이 "현재가 행에는 open 이 없다"를 잠근다.
- 🔴 **요청 증가 금지.** `fetch_soccer` 는 `only_names` 가 비면 요청 0이다
  (예산 규칙). 그 성질을 그대로 두고 파싱만 늘린다 — 같은 응답을 더 읽을 뿐이다.
- ⚠️ `market='spreads'` 의 `side` 는 팀명, `line` 은 그 팀 기준 핸디다.
  홈 `-0.5` 면 원정은 `+0.5` — 부호를 뒤집어 저장한다(둘 다 있어야 디빅한다).
- ⚠️ manual 은 **사람이 넣는 값**이다. 소스 이름을 `manual` 로 남겨 실소스와
  섞이지 않게 한다(`book='manual'`).

## ③ 되돌리기

커밋 1개 revert + `DELETE FROM odds_snapshots WHERE market IN ('spreads','totals')
OR book='manual'`. 스키마 변경 없음(컬럼 `line` 은 이미 있다).

## ④ 측정

라리가 3경기 `spreads`·`totals` 실소스 행 + 대전-교토 manual 행 원문.
