# PA-27-c — 대체된 축을 **두 번 뺀다** (시장 되짚기가 틀렸다)

## 왜

`reweigh` 는 배당을 다시 긁지 않는다(재판정마다 긁으면 요청이 는다). 대신
`p_code = p_market + Σ축소(adj)` 를 되짚어 시장값을 얻는다.

PA-27-b 가 `주전결장` 을 **빼고 난** `base_adj` 로 되짚는다 — 그런데 `p_code`
를 만든 것은 **빼기 전의 adj** 다. 그만큼 시장을 높게 잡고, 새 결장 축을 다시
빼므로 **대체했다면서 그 축을 한 번 더 빼는 셈**이다.

실측 (adj={'주전결장':-1.5,'짧은휴식':-2.0} · p_code=0.62 · 홈 결장 2명):
```
되짚기 base_adj → 시장 0.6300 → p_after 0.6050   ← 틀렸다
되짚기 orig_adj → 시장 0.6375 → p_after 0.6125   ← 맞다
차이 0.75%p · 방향은 늘 결장 쪽
```

## ① 이 함수/상태를 읽는 곳 **전부**

```
rejudge.reweigh            ← 고치는 곳 (`_market_of` 호출 한 자리)
rejudge._market_of         ← 되짚기 본체. 안 건드린다
pick_ledger (PA-27)        ← 유일한 호출자
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **대체가 안 일어나는 경로는 값이 그대로다.** `주전결장` 이 없거나 결장
  확인이 없으면 `orig_adj == base_adj` 라 종전과 같다. 계약이 잰다.
- 🔴 **호출자가 넘긴 dict 를 안 건드린다.** `orig_adj` 도 사본이다.
- 🔴 **되짚기는 한 번만 한다.** 두 자리에서 되짚으면 기준이 갈린다 —
  계약이 `_market_of(` 등장 횟수를 잰다.
- ⚠️ 상한(0.32~0.68)에 걸린 값이면 되짚기가 정확하지 않다 — 종전부터 있던
  한계이고 이번에 바뀌지 않는다.
