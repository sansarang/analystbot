# EXP-3 영향 지도 — 내보내기 산출물 로컬 회수

## 1. 무엇이 틀렸나 (재현 원문)

```
$ test -x tools/pull_export.sh ; echo $?
1
```

EXP-2 로 서버는 T-3h·T-60 산출물을 볼륨(`/data/export/`)에 쓴다. 그러나
지시문 1-1 의 통과 조건은 파일이 **로컬 다운로드 폴더에도** 있을 것을 요구한다.
컨테이너는 사용자 맥에 쓸 수 없으므로(→ FORKS F-18) 받아오는 쪽이 필요하다.

## 2. 어디를 고치나

| 파일 | 무엇 |
|---|---|
| `tools/pull_export.sh` (신규) | 볼륨의 파일을 다운로드 폴더로 받아온다 |
| `tests/export/test_exp3_pull.py` (신규) | 양쪽 경로가 스크립트에 남아 있는지 잠근다 |

## 3. 영향 지도 5문

**① 운영을 건드리나.**
아니다. 로컬 셸 스크립트이고 `railway ssh ... cat` 으로 **읽기만** 한다.
컨테이너에 쓰지 않고, 서비스를 재시작하지 않고, DB·Redis 를 만지지 않는다.
규율 7(컨테이너 직접 수정 금지)을 지킨다 — `railway ssh` 는 읽기 전용으로만 쓴다.

**② 파일을 덮어쓰나.**
받는 쪽에서 이름이 겹치면 **덮지 않고 `_r2` 로 늘린다** — `for_fable.out_path`
와 같은 규칙이다. 규칙을 두 곳에 손으로 적지 않도록, 스크립트는 같은
기준(존재하면 번호를 올린다)을 쓰되 파일명 자체는 서버가 정한 것을 그대로 쓴다.

**③ 무엇이 조용히 0이 되나.**
볼륨에 파일이 없으면 받을 것이 없다. 그때 **조용히 끝내지 않는다** — 목록이
비었다는 것을 찍고 종료 코드 1로 나간다. "받았다"와 "받을 게 없었다"가
구분되지 않으면 내일 아침에 무엇이 없었는지 알 수 없다.

**④ 어느 경로를 아나.**
볼륨 경로는 `RAILWAY_VOLUME_MOUNT_PATH` 가 정하고 지금 값은 `/data` 다.
스크립트가 그 값을 **컨테이너에 물어본다** — 손으로 `/data` 를 적으면
마운트가 바뀌는 날 사본이 된다(사본 금지).

**⑤ 테스트가 무엇을 잡나.**
네트워크를 타는 부분은 테스트하지 않는다. 잠그는 것은 **두 가지 회귀**다 —
(a) 받는 쪽 경로가 `for_fable.resolve_out_dir()` 의 로컬 기본값과 갈라지는 것
(b) 볼륨 경로를 코드에 박아 넣는 것.

## 4. 안 하는 것

- 자동으로 당기지 않는다. 서버가 주체이고 맥은 켜져 있지 않아도 된다 —
  사람이 필요할 때 부른다.
- 서버에서 맥으로 밀지 않는다(푸시 경로를 만들지 않는다).
