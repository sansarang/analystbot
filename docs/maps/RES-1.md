# RES-1 — KBO 결과를 네이버 일정 API 에서 받는다 (영향 지도 5문)

사용자 지시 2026-09-21: "결과 소스도 지금 해라" · "고 크롤러와 맞춰라"

## ① 무엇이 끊기나 — 실측

```
games(kbo) 09-20 까지 전부 final · 점수 있음      → 채점은 아직 안 막혔다
최종 적재   2026-09-21 04:01  ← 게이트를 켠 13:0x **직전**
```
결과를 채우던 것은 `kbo.upsert_games` 이고 소스는 `koreabaseball.com` 이다.
robots 거부로 껐다(D33). → **내일 04:01 잡부터 결과가 안 들어오고 채점이 멈춘다.**

## ② 결과가 다른 곳에 있다 — 실측 2026-09-21 14:10 (로컬)

```
GET api-gw.sports.naver.com/schedule/games?upperCategoryId=kbaseball&fromDate=2026-09-20…
  homeTeamScore · awayTeamScore · statusCode:'RESULT' · winner · cancel · suspended
  2026-09-20  한화 3 - 4 LG · KIA 8 - 6 NC
```
이 소스는 같은 날 사용자 지시로 **켜져 있다**(Go 크롤러와 맞춤).
⚠️ 날짜는 **하이픈 형식**이다 — `20260920` 은 400 이다(실측).

## ③ 어디를 건드리나

| 파일 | 무엇 |
|---|---|
| `app/collectors/naver_kbo.py` | `upsert_results()` **함수 1개** |
| `app/scheduler.py` | `ingest_kbo_finals()` + `finals_job` 한 줄 |

**새 모듈 0 · 새 테이블 0 · 새 컬럼 0 · 판정 경로 변경 0.**

## ④ 사본이 생기나

🔴 **안 생기게 했다.**
- 팀명: `naver_kbo.TEAM_TO_ODDS` 가 원본. 함수에 팀명을 적지 않는다.
  (DB 의 KBO 팀명이 이미 `Hanwha Eagles` 형식임을 실측했다.)
- 매칭: `game_match.apply_result` 가 원본. 직접 INSERT/UPDATE 하지 않는다 —
  같은 경기가 두 행으로 갈라지면 예측이 영원히 미채점으로 남는다(2026-08-27).
- 매핑에 없는 팀(`BMBC1` 같은 껍데기)은 **거르는 규칙을 새로 만들지 않고**
  표에 없으면 건너뛴다.

계약이 이 둘을 잠근다(`test_팀명_표를_새로_만들지_않았다` ·
`test_매칭_규칙을_새로_만들지_않았다`).

## ⑤ 기존 경로를 건드리나

- `kbo.upsert_games` 는 **그대로 둔다** — koreabaseball 접근이 허락되면 되돌아온다.
- `finals_job` 은 줄이 하나 는다. FotMob 적재와 **같은 자리·같은 모양**이고,
  `grade_pending` **앞**에 둔다(결과가 들어와야 채점할 것이 생긴다).
- 실패해도 다음 종목은 계속한다(기존 규약 그대로).

## ⑥ 틀렸을 때 누가 알려주나

계약 7건: 끝난 경기만 점수 · 취소는 점수 None · 진행중은 손대지 않음 ·
KST→UTC · 팀명 사본 없음 · 매칭 사본 없음 · **스케줄러가 실제로 부른다**
(마지막 것이 이 저장소의 반복 결함 "만들어 놓고 안 이음"을 막는다).

## ⚠️ 이 수정이 되돌리는 것과 아닌 것

- 되돌린다: **결과·채점** · 타순·순위·불펜·예고선발(naver 를 켠 덕).
- 안 되돌린다: 박스스코어(타자·투수 개인기록) · 팀기록 · 엔트리 · 구장 계수.
  그것들은 koreabaseball 전용이고 여전히 막혀 있다.
  ⚠️ 박스스코어는 **게이트 이전부터** 끊겨 있었다(D35) — 별건이다.
