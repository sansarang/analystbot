# D1-4 — "샤프 부재" 플래그 (오즈포털 북 넷이 전부 소프트북이다)

## 왜

사용자가 의심한 것을 쟀고 **맞았다**(실측 2026-09-14, 오늘 3경기):
```
Torino vs Roma        최고 환급률 94.8%   🔴 96% 미만
Villarreal vs Betis   최고 환급률 95.7%   🔴
Leeds vs Newcastle    최고 환급률 95.9%   🔴
id별 평균  op-549 94.80 · op-1205 94.73 · op-851 94.60 · op-1133 93.90
```
피나클급(보통 97~98%)이 **하나도 없다.** 그러면 `sharp_proxy` 는 대용조차
아니고 "덜 넓은 마진의 소프트북"일 뿐이다. 그리고 이것이 앞선 gap 이
0.78~2.14%p 로 좁게 나온 이유다 — 넷이 같은 성격이라 폭이 좁을 수밖에 없다.

🔴 **그래서 "브랜드 과대 기각" 결론을 그대로 쓰면 안 된다.** 기각의 근거가
   "샤프와 비교했더니 같더라"였는데 **비교 대상이 샤프가 아니었다.**

재현:
```
PYTHONPATH=. .venv/bin/python <scratchpad>/repro_d14.py
  → TypeError: pinnacle_gap() got an unexpected keyword argument 'sharp_absent'
```

## ① 이 함수/상태를 읽는 곳 **전부**

```
app/collectors/oddsportal.py  parse_books (정의)
app/engine/book_gap.py        pinnacle_gap
tests/test_book_gap.py        계약
```

## ② 만드는/바꾸는 상태

| 무엇 | 성격 |
|---|---|
| `parse_books` 반환 `top_payout`·`sharp_absent` | 칸 둘 |
| `pinnacle_gap(..., sharp_absent=)` | 반환에 플래그와 라벨이 붙는다 |

새 컬럼·새 요청 없다. **값은 그대로 계산한다** — 플래그는 해석을 막는
것이지 값을 지우는 것이 아니다.

## ③ 리그·종목·경로 분기가 생기는가

생기지 않는다. 임계(`SHARP_MIN_PAYOUT = 96.0`)는 사용자가 준 값 하나다.

## ④ 실패하면 "시끄럽게" 실패하는가

- `sharp_absent` 면 라벨이 `"샤프 부재 · …"` 로 바뀐다. 원장·카드가 그 문구를
  그대로 들고 다니므로, 나중에 이 표를 볼 사람이 **비교 대상이 소프트북이었다**
  는 것을 모를 수 없다.
- 수집 로그에 최고 환급률을 함께 찍는다.

## ⑤ 시스템에 이미 있는 사실을 다시 적고 있지 않은가

- 환급률은 이미 파싱한 `payout` 을 쓴다 — 다시 긁지 않는다.
- 임계는 상수 하나. 판정 문구는 `book_gap` 한 곳에서만 만든다.
