# W2 영향 지도 — 식별자 배선 (선수·팀·경기 매칭)

## 0. 재현 (실측 2026-09-21, 운영 Redis·DB)

### (a) 양쪽 복사의 원인은 **둘**이다

```
scout:soccer:11330   home.team = 'Club Atlético de Madrid'
                     away.team = 'Club Atlético de Madrid'   ← 같다
                     out 2명이 양쪽에 동일
scout:soccer:11334   home.team = 'SonderjyskE'
                     away.team = 'Randers FC'                ← 다르다
                     out 4명이 양쪽에 동일
```

앞은 **귀속 규칙**이 틀렸다:

```
_same_team('Club Atlético de Madrid', 'Real Madrid CF') → True
   공통 토큰 'madrid' 하나로 AT마드리드 카드가 레알에도 들어갔다.
```

뒤는 **LLM 이 한쪽 명단을 양쪽에 적었다**(덴마크 부상표). 자료로는 어느 쪽이
진짜인지 알 수 없다.

→ 고치는 곳이 다르다. 앞은 `assign_side`, 뒤는 `resolve_attribution`.

### (b) 🔴 지시문의 전제 하나가 사실이 아니었다 (D14b)

> D14b 타 팀 동명 선수 혼입 — 롯데 결장에 박건우(NC)

```
SELECT batter, team, count(*) … WHERE batter='박건우'
   박건우 · NC Dinos      26회 · 타순 5~6번
   박건우 · Lotte Giants   9회 · 타순 8번
g1723 (NC vs 롯데 · 09-08) 에 **양 팀 모두** 등장 — NC 2번 · 롯데 8번
둘 다 source='boxscore' · 타순이 일관된다
```

**동명이인이 실재한다.** 이름만으로 소속을 판정하면 **진짜 롯데 박건우가
지워진다** — 그것이 더 큰 결함이다. 같은 모양이 하나 더 있다(김민석 · 두산/KT).

→ 이름이 **한 팀으로만** 이어질 때만 불일치로 본다. 두 팀 이상이면
`ambiguous` 로 두고 **어느 쪽으로도 세지 않는다.**

## 1. 영향 지도 5문

**① 어디를 고치나.**

| 파일 | 무엇 |
|---|---|
| `app/collectors/satellite.py` | `assign_side`(신규 · 순수) · `split_rows_by_side` · `resolve_attribution` · `_same_team` 은 남기되 **귀속에는 쓰지 않는다** |
| `app/engine/performance.py` | `filter_by_roster`(신규 · 순수) — 이름이 **유일**할 때만 불일치 판정 |
| `app/ops/selfcheck.py` | 이미 `abs_same_both_sides`·`player_team_mismatch` 를 센다(W1) — 손대지 않는다 |

**② 새 테이블·새 수집기를 만드나.** 만들지 않는다. 로스터는 이미 쌓여 있는
`batter_appearances`·`pitcher_appearances`(17,461 + 8,859행, 전건 `boxscore`)
에서 **읽기만** 한다.

**③ 규칙은 어디에 한 번만 두나.**
- 일반 토큰 목록은 `pipeline._GENERIC_TEAM_TOKENS` 하나다(여기서 적지 않는다).
- "공유 토큰은 식별자가 아니다"는 `pipeline._shared_team_tokens` 의 규율을
  **그 경기 두 팀 사이**로 좁혀 쓴다 — 별칭표가 없는 리그에서도 통한다.
- 동점이면 `None` 은 `football.match_team_name` 과 같은 규약이다.

**④ 무엇이 깨질 수 있나.**
- 🔴 **정상 귀속까지 막는 것**이 최대 위험이다. 결장이 판정에 닿지 않게 되면
  고친 게 아니라 껐을 뿐이다. 그래서 반대 위험을 함께 잠근다 —
  고유 토큰이 있으면 귀속되고(`Machida Zelvia`), 명단이 서로 다르면 그대로 둔다.
- 🔴 **동명이인을 지우는 것**이 두 번째 위험이다(위 (b)). 유일할 때만 지운다.
- ⚠️ 못 정한 카드를 **버리지 않는다** — `unknown` 으로 모으고 `out_unknown` 에
  남긴다. 버리면 "그런 자료가 없었다"와 구분되지 않는다.

**⑤ 틀렸을 때 알려줄 테스트.** `tests/test_w2_attribution.py` — 11330·11334
재현 · 정상 귀속 보존 · 동명이인 보존 · 로스터 없음/빈손 보존 · 별칭 자동승격

## 2. 이번 범위 **밖**이라 못 닫는 것 (보고 후 지시를 기다린다)

지시문 1 은 *"선수 식별은 `player_id + team_id`"* 라고 못박는다. 그런데
**우리 DB 에 선수 id 가 없다**:

```
batter_appearances   … team, batter(이름)          — id 칸 없음
pitcher_appearances  … team, pitcher(이름)         — id 칸 없음
lineup_history       … team_id, player_id 있음     — 그러나 ⋈ games 0행
```

id 로 바꾸려면 **리그마다 id 원본**이 필요하다(MLB statsapi 는 있고, KBO·NPB 는
지금 쓰는 소스에 없다). 새 소스·새 칸·백필이 따르므로 **지시 없이 만들지
않는다.** 이번 커밋은 "이름이 유일할 때만 판정한다"까지다 —
그것만으로 09-21 실측의 오귀속 두 종류가 닫힌다.
