# SRCH-5 — 슬레이트 카드가 ORDER_V3 판정을 읽는다 (P0)

## 왜

실측 2026-09-12, ORDER_V3 를 운영에서 처음 켠 직후. 판정은 **4/4 성공**했다:

```
[v3] 롯데@키움  승자 Kiwoom Heroes · 확신 중 · 채택 11/20 · DB 확인
[v3] KIA@KT    승자 Kia Tigers   · 확신 중 · 채택 12/20 · DB 정정 🔴승자변경
[v3] LG@삼성    승자 LG Twins     · 확신 하 · 채택 11/20 · DB 확인
[v3] NC@두산    승자 Doosan Bears · 확신 중 · 채택 10/20 · DB 확인
```

그런데 카드는 이렇게 나갔다:

```
⚠️ 판정 실패 — 오늘 경기 판정을 받지 못해 분석을 완료하지 못했습니다.
판정 부착 0건 / 분석 대상 4경기 — judge 응답 확인 필요
```

원인 한 줄 (`pipeline.py` `_render_card`):

```python
judged = [g for g in scheduled if g.get("p_claude") is not None]
```

슬레이트 조립이 **확률이 있어야 판정으로 센다.** ORDER_V3 는 확률을 통째로
지운 경로다(ORD-3 "수치는 전부다 삭제"). 경기별 `render_form_card` 에는 v3
분기가 있지만 그 **앞 단계**에서 막힌다.

**카드가 틀린 값을 내보내는 P0** 다. 그날 스위치를 되돌려 막았고, 이 수정이
그것을 여는 조건이다.

⚠️ ORD-20 이 ORDER_V3 를 만들 때부터 있던 구멍이다. 운영에서 켠 적이 없어
   드러나지 않았다 — "켜 본 적 없는 경로는 없는 경로와 같다".

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "_render_card" app/ tools/
app/pipeline.py:4911  (정의)
app/pipeline.py:5065  generate_card → 카드 캐시에 저장 · 텔레그램 발송의 원본
$ grep -rn "p_claude" app/pipeline.py | wc -l
   (다수 — 전부 구 경로의 확률 사용처다. **건드리지 않는다**)
```

`_render_card` 안에서 새로 읽는 것: `g["order_v3"]` · `g["winner"]` ·
`g["matchup"]["확신"]`. 셋 다 `apply_winner` 가 쓰는 원본이고 이미 원장에 있다.

빌려 쓰는 원본 — 새로 만들지 않는다:
| 무엇 | 원본 |
|---|---|
| 경기별 v3 카드 | `engine/form_card.render_form_card` (이미 `order_v3` 분기 있음) |
| 확신 눈금 | `engine/verdict.LEVELS` |
| 헤더·한계 줄·coverage | `_render_card` 의 기존 상단부 그대로 |

## ② 만드는/바꾸는 상태

**상태를 만들지 않는다.** 읽기만 한다 — DB·Redis·env 모두 불변.

| 바꾸는 것 | 어떻게 |
|---|---|
| `_render_card` 의 반환 문자열 | v3 슬레이트일 때만 다른 본문 |
| 카드 캐시 `card:{sport}:{date}` | **키도 모양도 그대로**. 내용만 달라진다 |

🔴 **구 경로의 출력은 한 글자도 바뀌면 안 된다.** 운영은 지금도 구 경로로
   돈다. 계약 두 건이 이것을 지킨다(별점·자격·조합이 그대로 있는가,
   구 경로의 "판정 실패" 문구가 그대로인가).

## ③ 리그·종목·경로 분기

**설정이 아니라 데이터로 가른다** — `g["order_v3"]` 가 붙은 경기가 있는가.

🔴 설정(`s.order_v3`)을 읽으면 **스위치를 끈 뒤에도** 옛 원장이 새 카드로
   렌더되거나 그 반대가 된다. `form_card.py:338` 이 이미 같은 이유로
   데이터 분기를 쓴다(ORD-3 주석). 그 태도를 따른다. 계약으로 못 박는다.

⚠️ 종목 분기는 없다. kbo·npb·mlb 가 같은 `_judge_v3` 를 쓰므로 같은 카드다.
   축구는 이 경로를 타지 않는다(구 Judge).

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **게이트를 넓히다 진짜 판정 실패를 못 본다** | v3 경기가 **전부** 승자 없음이면 종전처럼 "판정 실패"를 쓴다(계약) |
| 판정 못 받은 경기가 조용히 빠진다 | 그 경기를 이름과 함께 남기고 몇 경기인지 쓴다(계약) |
| 수집·검색해 놓고 카드에 안 실린다 | 경기별 v3 카드가 상세에 들어가는지 단언. `자료` 의 문장이 실제로 보이는지까지 본다 |
| 확률·별점·조합이 v3 카드에 새어 나온다 | 금지 문자열 전수 단언(`★`·`승률`·`자격`·`조합`·`%`) |
| **구 경로가 바뀐다** ← 가장 큰 반대 위험 | 구 경로 슬레이트로 렌더해 별점·자격·조합이 그대로인지 단언 |
| 스위치를 껐는데 옛 v3 원장이 새 카드로 나온다 | 데이터 분기이므로 원장에 `order_v3` 가 있으면 새 카드가 맞다 — 의도한 동작 |

⚠️ **아직 못 재는 것**: 이 카드가 사용자에게 읽히는가. 발송 뒤 확인할 일이다.

## ⑤ 이미 있는 사실을 다시 적는가

- 경기별 카드 본문을 여기서 다시 만들지 않는다 — `render_form_card` 를 부른다.
  문구를 옮겨 적으면 그 순간 사본이다(`card.py:789` 가 같은 경고를 적어 뒀다).
- 확신 라벨(상·중·하)을 새로 정의하지 않는다 — 원장의 값을 그대로 싣는다.
- 헤더·한계 줄·coverage 줄은 기존 상단부를 그대로 지난다. 다시 쓰지 않는다.
