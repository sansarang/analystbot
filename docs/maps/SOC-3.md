# SOC-3 — 축구 일정 창이 KST 하루를 못 덮었다. 저녁 경기가 통째로 없었다.

## 왜

`FootballDataClient.fetch_matches` 의 독스트링은 맞게 적혀 있다 —
"KST 날짜에 걸치는 경기 (UTC로는 전날 15:00~당일 15:00)". 파라미터가 틀렸다:

```python
params={"dateFrom": (d - timedelta(days=1)).isoformat(), "dateTo": d.isoformat()}
```

실측 2026-09-12 (운영, 실호출) — API 는 `dateTo` 를 **그 날짜 00:00 시각까지**로 본다:

```
from=2026-09-12 to=2026-09-12  →  1건   (2026-09-12T00:00:00Z 하나)
from=2026-09-12 to=2026-09-13  → 49건   (09-12 UTC 48 + 09-13 00:00 1)
from=2026-09-11 to=2026-09-12  →  8건   (09-11 UTC 7 + 09-12 00:00 1)
```

그래서 우리는 **UTC D-1 하루만** 받았다. KST 날짜 D 는 UTC `[D-1 15:00, D 15:00)`
인데 뒤쪽 절반(`D 00:00~15:00` = **KST D 09:00~24:00**)이 빠졌다.

그날 실제로 놓친 것 — 요청받은 세 리그가 전부 그 구간에 있었다:

```
KST 22:00  세리에A  Frosinone @ Genoa
KST 22:30  분데스   5경기 (도르트문트·레버쿠젠·슈투트가르트·프랑크푸르트·묀헨글라트바흐)
KST 23:00  EPL     5경기 (리버풀·첼시·팰리스·본머스·아스톤빌라)
```

⚠️ **HTTP 200 이었다.** 상태값은 의도한 것이 동작한다는 증거가 아니다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "fetch_matches" app/
app/collectors/football.py:75   정의
app/collectors/football.py:107  upsert_games_from_football_data  ← 유일한 호출부
```

`upsert_games_from_football_data` 는 받은 것을 **KST 날짜로 한 번 더 거른다**
(`starts.astimezone(KST).strftime(...) != date_kst → continue`). 그러니 창을
넓혀도 다른 날 경기가 새지 않는다 — **거르는 일은 이미 거기서 한다.**

## ② 만드는/바꾸는 상태

| 상태 | 성격 | 다른 곳이 다른 규칙으로 갱신하나 |
|---|---|---|
| `dateTo` 파라미터 | `D` → `D+1` | 아니다. 호출부 하나 |

⚠️ DB·Redis·env·프롬프트를 건드리지 않는다. **한 줄이다.**

## ③ 리그·종목·경로 분기

분기 없음. football-data 를 쓰는 리그(EPL·라리가·세리에A·분데스리가) 전부
같은 창을 쓴다. J1·K리그1·덴마크는 이 경로가 아니다(Odds API).

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **다른 날 경기가 섞인다** ← 반대 위험 | 호출부의 KST 필터가 이미 거른다. 그 필터를 건드리지 않는다 |
| 경계를 또 손으로 적는다 | 계약이 KST 하루의 양 끝을 **계산해서** 창 안에 있는지 본다 |
| 응답이 커져 한도를 먹는다 | 하루치가 늘 뿐이다(실측 8건 → 56건). 호출 횟수는 그대로 1회 |
| 같은 실수가 다른 클라이언트에도 | ⚠️ **아직 못 쟀다** — Odds API 경로의 창은 이번에 안 봤다 |

## ⑤ 이미 있는 사실을 다시 적는가

- KST 필터를 여기서 또 만들지 않는다 — 호출부에 이미 있다.
- 경계 날짜를 상수로 적지 않는다 — 계약이 KST 자정 두 지점을 계산한다.
