# W3-8 — xfail 을 뗀다 (영향 지도 5문)

`wiring_first_0920` 의 남은 항목. 사용자 확인 2026-09-21: "w 배선은 마무리
안 된 것 같은데?"

## ① 🔴 계약이 **틀린 칸**을 보고 있었다

`tests/test_lga1b_feature_lock.py` 의 `_has_result_source` 는
`fd_names` 또는 **`fotmob_id`** 를 본다. 그런데 실측:

```
리그        fd_names  fotmob_id  result_source   features
j1          False     False      **fotmob**      judge·router·results
denmark     False     False      **fotmob**      judge·router·results
kleague1    False     False      **fotmob**      judge·router·results
acl         False     False      **fotmob**      judge·router·results
```

🔴 **`fotmob_id` 라는 칸은 없다.** W3-1(커밋 `b61d847`)이 적재 경로를
   **`result_source`** 로 만들었고, 계약은 그것을 따라가지 못했다.

**적재는 실제로 되고 있다** — 운영 DB:
```
K리그1            final 53 · 점수 53
덴마크 수페르리가   final 42 · 점수 42
J1 · ACL          final  0          ← 리그 휴식·일정 문제이지 경로 문제가 아니다
```

⚠️ **내가 처음에 DB 행 수로 판단한 것도 틀렸다.** 이 계약은 파일 머리에
   "**DB 행 수를 보지 않는다. 테스트가 DB 상태에 의존하면 그날그날 달라진다**"
   라고 적고 있다. 설정을 봐야 한다.

## ④ 되돌릴 수 있나

커밋 되돌리기. ⚠️ 다만 **되돌릴 이유가 없다** — 사실을 사실대로 적는 것이다.

## ⑤ 🔴 이 수정이 **막던 것을 계속 막는지** 확인한다

이 계약의 목적은 "**판정·라우터가 켜졌는데 결과 적재가 없는 리그**"를 막는
것이다(실측 2026-09-20: ACL 8건이 판정 8·채점 0·결과 0 이었다).

느슨하게 고치면 그 구멍이 다시 열린다. → **`result_source` 가 빈 리그를
만들면 여전히 실패**하는지 계약으로 확인한다.
