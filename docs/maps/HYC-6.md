# HYC-6 — 잴 수 없는 칸을 운영에 드러낸다

사용자 2026-09-23: "hyc 전부 다 해라"
계획서 `hyp_conditions_0920` §4 그대로다.

## 왜

HYC-3 로 `미실행`(볼 방법이 없다)이 생겼지만 **운영에서 볼 방법이 없다** —
⑥ 스냅샷과 ⑫ 글에만 있다. 그러면 "왜 이 변수는 영원히 비어 있나"를 사람이
DB 를 파야 안다.

```
실측 전 기간   weather            확인 0 / 등장 2,129
              travel_backtoback  확인 0 / 등장 2,129
실측 오늘      미실행 ['travel_backtoback', 'park_factor', 'weather']  NPB 3경기
              미실행 ['travel_backtoback', 'weather']                 KBO
```

## 영향 지도 5문

① **파일** — 신규 `app/flow/coverage.py`(순수 함수) + `app/health.py` 한 줄 +
   `app/export/for_fable.py` 블록 + 계약 1.

② **테이블·잡** — 없음. DB 스키마·주기 변화 0. 읽기만 한다.

③ **깨질 테스트** — `/health`·export 의 출력 모양을 고정한 계약이 있으면
   길이가 늘어 깨질 수 있다. 전체 스위트로 확인한다.

④ **되돌릴 길** — `coverage.line()` 호출 두 줄을 빼면 종전과 같다.
   모듈은 순수 함수라 아무것도 건드리지 않는다.

⑤ **완료 조건** — `always_unrun` 이 "한 번도 못 잰 칸"만 센다 ·
   `/health` 에 한 줄 · export 에 `coverage` 블록 · **⑦이 이 모듈을 안 읽는다**.

## 규약

🔴 **관측 장치는 판정을 건드리지 않는다**(감시 3층 규약: "발송 뒤에 돌고,
   카드 텍스트를 바꾸지 않으며, 결과가 판정·게이트로 되돌아가지 않는다").
   계약이 `n07_adjust` 에 `coverage` 가 없음을 잠근다.

🔴 **한 번이라도 잰 칸은 빼야 한다.** 가끔 되는 칸(`park_factor` 는 KBO·MLB
   에서 된다)을 "영원히 안 됨"으로 적으면 거짓이다 — 등장했고 **전건이**
   미실행인 것만 센다.

⚠️ 이름은 사람 말로(VIS-1) · 원본은 `config/rules.yaml` 의 `flow.var_names`.
⚠️ `/health` 를 길게 만들지 않는다 — 한 줄이고 상세는 export 다(계획서 규율).

## 안 한 것

🔴 **HYC-5(⑤ 기사 질의응답)는 안 했다.** 그것은 LLM 호출이 본체인데
   (`prompts/qa_conditions.txt` · 경기당 조건수×2 호출) 사용자 지시
   "llm 완전히 0으로 만들어라"(2026-09-22)와 **동시에 성립하지 않는다.**
   둘 중 무엇을 살릴지는 사용자 결정 사항이다.

⚠️ 계획서의 "조건별" 집계는 **변수별**로 했다 — HYC-4 의 경기별 조건
   (`{id, team, question, breaks_pick_if}`)이 아직 절반이라 조건이 없다.
