# D27F — `llm.daily_call_cap` 을 config 에서 읽는다 (영향 지도 5문)

## ① 무엇이 틀렸나 (실측 2026-09-22 · 운영 컨테이너)

```
flow.rules.get("llm.daily_call_cap")   → None
engine.rules.get("llm.daily_call_cap") → 200
engine.rules.get("llm")                → {'daily_call_cap': 200}
engine.rules.get("flow.llm")           → None
```

`app/flow/rules.py:15` 이 경로에 **`flow.` 접두사를 붙인다.** `_llm_budget_ok`
는 그 모듈로 `llm.daily_call_cap` 을 찾으므로 실제로는 `flow.llm.daily_call_cap`
을 찾고, 그런 블록은 없다. 값은 **코드 폴백 200** 이었다.

🔴 **증상이 없던 이유가 위험하다.** 폴백 200 이 config 값 200 과 우연히 같았다.
   `config/rules.yaml` 의 상한을 내려도 **LLM 호출은 줄지 않는다.**

## ② 판정을 건드리나

건드리지 않는다. 바뀌는 것은 **LLM 추출 호출 상한을 어디서 읽는지**뿐이고,
지금 config 값이 200 · 폴백도 200 이므로 **오늘 동작은 바뀌지 않는다.**
바뀌는 것은 "앞으로 설정을 고치면 반영된다"는 것이다.

## ③ 규칙은 어디에 한 번만 두나

`config/rules.yaml` 의 최상위 `llm.daily_call_cap` 하나. 코드는 읽기만 한다.

## ④ 무엇이 깨질 수 있나

⚠️ 🔴 **같은 파일의 `get_depth`·`_article_cap` 은 `app.flow.rules` 가 맞다.**
   실측: `flow.get("depth_fallback")` → `'normal'` ·
   `flow.get("depth_articles")` → `{'shallow':0,'normal':2,'deep':5}` ·
   `engine.get("depth_fallback")` → **None**.
   세 곳을 한꺼번에 engine 으로 옮기면 그 둘이 None 이 되어 **조용히 폴백**으로
   돈다(기사 수가 2로 고정되고 shallow·deep 이 사라진다).
   **그래서 `_llm_budget_ok` 한 함수만 바꾼다.** 계약이 이 방향을 잠근다.

## ⑤ 되돌릴 수 있나

임포트 한 줄이다.

## ⑥ 틀렸을 때 누가 알려주나

계약 4건: config 50 · 사용 100 → **막는다**(HEAD 에서는 통과했다) ·
상한 안이면 통과 · redis 없으면 막지 않는다 ·
**`depth_*` 는 여전히 `flow.rules` 다**(같이 옮기는 것을 막는다).
