# NOLLM — 판정은 코드가, 서술은 템플릿이 (영향 지도 5문)

사용자 2026-09-22: **"판정은 원래 코드에서 낸다… 서술도 템플릿으로 바꿔라"**

## ⓪ 왜 — 실측으로 확인된 낭비

LLM 호출 자리 9곳 중 **판정 3곳은 결과가 버려진다**:
```
verdict.decide(verdict.py:141)  → 승자   ┐
matchup 재질의(matchup.py:1543) → 승자   ├→ apply_winner 로 카드에 붙었다가
dbref.recheck(dbref.py:172)     → 승자   ┘   apply_code_verdict 가 **덮어쓴다**(P0-1)
```
세 번 묻고 세 번 버린다. 그러면서 **그 실패로 경기가 통째로 탈락**했다 —
오늘 실측: LLM 사슬 소진으로 KBO 0/8 · NPB 0/5 판정 전멸.

## ① 파일

| 파일 | 무엇 |
|---|---|
| `config/rules.yaml` | `judge.llm_verdict: false` — **스위치 하나** |
| `app/engine/matchup.py` | 꺼져 있으면 `verdict.decide`·`dbref.recheck` 의 **LLM 호출을 건너뛴다** |
| `app/engine/narrate.py` (신규) | **템플릿 서술** — 순수 함수, LLM·HTTP·DB 0 |
| `tests/test_nollm.py` | 계약 |

🔴 **코드를 지우지 않는다.** 스위치로 끈다 — 이 저장소의 확립된 방식이다
   (`source_gate`·`DISABLED_PROVIDERS`). 되돌리려면 한 줄이다.

## ② 테이블 / 잡

없다. 새 테이블 0 · 새 잡 0.

## ③ 무엇이 깨질 수 있나

- 🔴 **`서술` 이 사라지면 카드의 `🧠 분석` 블록이 빈다.** 그래서 템플릿을
  **같이** 넣는다 — 빼기만 하면 카드가 얇아진다.
- 🔴 **`dbref.recheck` 의 `있음`·`없음`·`본것` 은 DB 사실**이다(LLM 아님).
  그건 **그대로 둔다.** 끄는 것은 그 뒤의 재판정 질의뿐이다.
- ⚠️ `승자변경`·`DB사유` 는 LLM 재판정에서 나오던 값이다 — 꺼지면 항상
  `False`/빈 문자열이다. 카드가 그 자리를 조용히 비우는지 확인한다.
- ⚠️ 판정 경로 계약이 많다. 전체 스위트로 확인한다(현재 5,620).

## ④ 롤백

`config/rules.yaml` 한 줄(`judge.llm_verdict: true`). 코드는 남는다.

## ⑤ 완료 조건

1. 스위치 off 에서 **LLM 판정 호출 0회**로 카드가 나온다(승자·확신·서술 전부)
2. 스위치 on 에서 종전과 같다(되돌릴 길을 막지 않는다)
3. 서술이 **템플릿**으로 채워진다 — 갈림길·조사 결과·승자에서 문장을 만든다
4. 전체 스위트 통과 · 발송 0건

## ⚠️ 이 단위가 **하지 않는 것**

- 딥서치(`council`·`deepsearch`)의 LLM 은 **끄지 않는다.** 그건 재료를 찾는
  일이고 대체가 없다(사용자가 "딥서치는 LLM 이 하는 걸로 안다"고 확인).
- `team_form`·`analyze` 의 서술 LLM 은 **이번에 안 건드린다** — 판정 경로가
  아니고, 한 번에 하나씩 간다.
