# MBM-1 — 야구 기본 모델 (야구 모델 지시문 3단계)

## 왜

자료13의 실체다. `dbref` 가 Gemini 에게 **낱개로** 주는 재료(선발 최근 등판·
타순·불펜 가용성)를 코드가 **하나의 확률로** 합친다. 지시문의 기대치:

> 야구는 선발 하나가 승률을 10%p 넘게 움직이는 종목이라 자료13의 가치는
> "예측"보다 **선발 변경·타순 결장 시 즉시 재계산되는 숫자**에 있다.

기준선은 현행 `team_elo` 다. 부록 진단(2026-09-13, MLB 452경기) 결과
Elo 는 버그가 아니라 **무신호**였다:
```
현행(decay 0.9)  AUC 0.5074 · 브라이어 0.2489 · 확률폭 0.164
감쇠 없음        AUC 0.5188 · 브라이어 0.2506 · 확률폭 0.352
```
→ "A > D" 는 낮은 문턱이다. 그래도 못 넘으면 설계가 틀린 것이다(지시문).

## ① 이 함수/상태를 읽는 곳 **전부**

```
app/model_baseball/model.py — 읽는 곳은 4단계 backtest(아직 없다)
입력은 2단계 SQLite(games·pitch_app·bat_app) 뿐
운영 경로(app/engine·app/collectors)를 건드리지 않는다
```
빌려 쓰는 원본:
| 무엇 | 원본 |
|---|---|
| 경기·투구·타격 원자료 | `data/model_baseball.sqlite` (MBL-1·2) |
| 리그 평균(wOBA·RPG) | **DB 에서 계산한다.** 상수로 적지 않는다 |
| 피타고리안 지수 1.83 | 지시문 3-6 |

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `model.py` 순수 함수 | `shrink` · `sp_axis` · `bp_axis` · `off_axis` · `expected_runs` · `pythag` · `win_prob` · `predict` |
| `season_frame(con, season)` | SQLite → 경기별 입력 조립(누수 없이) |

🔴 **사전값은 시즌 누적을 써도 된다**(지시문 5번 예외) — 다만 용도는
   "최근 3~5경기를 얼마나 믿을지 정하는 축소 계수"뿐이다. Gemini 에게는
   사전값이 아니라 **합쳐진 확률만** 간다.
🔴 **LLM 을 부르지 않는다.** 계약이 소스에 `gemini`·`prompt` 부재를 단언한다.

## ③ 리그·종목·경로 분기

분기를 만들지 않는다. 리그 평균·홈이점·K 값을 **인자로 받는다** — MLB 로 적합한
값을 KBO·NPB 가 그대로 쓰거나(표본 부족 시) 각자 적합한다(6단계).

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **누수** — t 이후 정보가 입력에 든다 | `season_frame` 이 경기 시각 **이전** 행만 모은다. 4단계가 assert |
| 🔴 홈승률이 현실과 어긋난다 | 2024 실행에서 0.52~0.55 밖이면 **구현 오류로 멈춘다**(지시문) |
| 이닝 표기를 소수로 읽는다 | 2단계 `parse_ip` 가 이미 처리. 여기서 다시 하지 않는다 |
| 리그 평균을 손으로 적는다 | DB 계산. 계약이 상수 부재를 단언 |
| 표본 없는 선발이 리그 평균으로 조용히 대체 | `shrink` 가 사전값을 쓰되 `n_ip` 를 함께 낸다 |

⚠️ **아직 못 잰 것**: 모델 AUC. 4단계에서 잰다. 이 단계는 **분포 검증**까지다.
