# ADJ-1 영향 지도 — ⑦ 부호가 근거의 내용을 안 봤다 (내 버그)

## 1. 무엇이 틀렸나 (실측 원문)

오늘 MLB 네 경기의 ⑦이 **전부 같았다**:

```
WSH@STL  starter_recent3  pp=3.0 sign=1.0   매그리비 6.0이닝 1자책 (잘 던짐)
NYY@ARI  starter_recent3  pp=3.0 sign=1.0   파트   6.7이닝 6자책 (무너짐)
MIA@SD   starter_recent3  pp=3.0 sign=1.0   페레스 4.0이닝 5자책 (무너짐)
MIN@LAA  starter_recent3  pp=3.0 sign=1.0   라이언 4.0이닝 4자책 (무너짐)
```

**잘 던진 선발과 무너진 선발에 같은 부호·같은 크기를 줬다.**

원인은 오늘 내가 쓴 STR-2 다. `sides` 의 뜻은 "**악재가 어느 쪽인가**"인데
나는 "이 사실이 누구 얘기인가"로 읽고 `sides={opp: n}` 을 고정으로 넣었다.
`n07._direction` 은 그것을 보고 언제나 `+1.0` 을 냈다.

⚠️ `_direction` 머리말이 **이미 경고하고 있었다**:

> 한쪽으로 고정하면 근거와 **반대로** 확률이 움직인다. 실제 픽스처가 그것을
> 잡았다 — "한화 선발 ERA 6.10"은 삼성(픽)에게 **유리**하다.

그 경고를 읽고도 같은 실수를 했다.

## 2. 어디를 고치나

`app/flow/nodes/n05_evidence.py` — `starter_recent3` 의 `sides` 를 정하는 자리.
⚠️ `n07_adjust.py` 는 **건드리지 않는다.** 거기 규칙은 맞다 — 입력이 틀렸다.

## 3. 영향 지도 5문

**① 방향을 무엇으로 가르나.**
**최근 3등판 방어율 vs 리그 평균**이다. 상대 선발이 리그 평균보다 나쁘면
상대 악재(우리 유리), 좋으면 우리 악재(불리).
🔴 **새 상수를 만들지 않는다** — `settings.league_era`(MLB 4.20) ·
`kbo_league_era`(4.66) · `npb_league_era`(3.34) 가 이미 있고
`scoring._suppression` 이 같은 값을 쓴다.

**② 방어율을 못 구하면.**
`sides` 를 **비운다**. `_direction` 은 빈 dict 에 `-1.0`(보수적으로 불리)을
낸다 — 그게 맞다. 유리하게 지어내지 않는다.

**③ 이닝도 봐야 하지 않나.**
조기 강판은 불펜을 끌어내므로 총점 쪽에 별도로 작용한다. 그러나 여기서
**두 개의 규칙을 한 칸에 담지 않는다** — 방어율 하나로 방향을 정하고,
이닝은 ⑪의 λ 가 이미 본다(`mlb_lambdas` 의 선발 억제력).

**④ 크기(`strength`)는.**
건드리지 않는다. 지금은 "수치 근거면 1.0"이고 그 규칙은 ⑦의 것이다.
크기까지 내가 정하면 범위를 넘는다.

**⑤ 무엇이 바뀌나 — 숨기지 않고 적는다.**
오늘 네 경기의 `p_code` 가 **전부 바뀐다.** 특히 WSH@STL 은 `+3.0` 이
`−3.0` 으로 뒤집혀 픽 확률이 내려간다. 그게 맞는 방향이다.

## 4. 안 하는 것

- `n07_adjust.py` 의 규칙을 바꾸지 않는다.
- `max_abs`·`strength` 값을 만지지 않는다(30건 채점 전 동결).
- 다른 변수(`bullpen_3d`·`lineup_out`)의 `sides` 는 그대로 둔다 —
  그쪽은 "누가 빠졌나"가 곧 악재의 주체라 뜻이 맞다.
