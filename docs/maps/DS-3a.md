# DS-3a — 검색 경로를 갈아 끼울 수 있게 (영향 지도 5문)

사용자 지시 2026-09-21: "순서대로 해라" · **"체인은 bing으로"**

## ① 무엇이 틀렸나

기사 검색의 기본 경로 `news.google.com/rss/search` 가 **robots 거부**다.
`*` 블록이 `Disallow: /` 이고 `/rss/` 를 여는 Allow 줄이 없다. 게다가
`ClaudeBot`·`anthropic-ai`·`GPTBot`·`PerplexityBot` 을 **이름으로 지목해**
전면 거부한다(원문 직접 수신 2026-09-21 14:16).

## ③ 🔴 질의를 자르는 규칙을 **넣지 않았다** — 실측이 내 규칙을 뒤집었다

처음엔 "짧을수록 좋다"로 보고 시장별 단어 상한을 넣으려 했다.
2×2 절제(2026-09-21 Bing, 같은 시각)가 그 방향을 지지하는 듯했다:

```
한/일 긴→짧   한화 선발 1→8 · 中日 予告先発 2→5 · KBO 타순 1→6
영/스 긴→짧   EPL 확정XI 9→2  ← 긴 쪽 압승 (반대다)
```

영어 매체는 제목에 `confirmed lineups` 를 쓰고, 한/일 야구 매체는
`내일의 선발투수` 를 안 쓴다. 그래서 "시장별 상한"으로 가려 했는데,
한 번 더 좁혀 재자 **더 뒤집혔다**:

```
川崎フロンターレ        11항목/8최근 → 최신 「감독이 반성한 후반 23분 교체책」(쓸모없음)
川崎フロンターレ スタメン  5항목/2최근 → 최신 「【川崎vs鹿島】スタメン発表」(찾던 것)
한화 이글스            12항목/8최근
한화 이글스 선발        12항목/10최근  ← 좁혔는데 최근 기사가 **늘었다**
포항 스틸러스 라인업     5항목/0최근
```

🔴 **좁히면 수는 줄고 정확도는 오른다.** 그러면 "당일 기사 회수 수"는
   **잘못된 지표**다 — 그것만 보면 쓸모없는 기사를 많이 받는 쪽이 이긴다.
   ⚠️ 지시문 DS-3a 4 가 회수율을 1순위로 두는데 실측이 반대를 가리킨다.
      **오디션의 1순위 지표를 `검증 통과 사실 수` 로 바꿔야 한다.**

그래서 규칙을 **짓지 않고** 오디션에 넘겼다. 공급자는 받은 질의를 그대로
보낸다. 질의의 원본은 `config/search_terms.yaml` 하나다.
계약 2건이 이 방향을 잠근다(`max_query_words`·`trim_query`·`split()[:` 금지 ·
보낸 질의 == 받은 질의).

## ④ 사본이 생기나

- 요청: 전부 DS-1 런타임.
- 공급자 이름·순서: `config` 의 `search.chain` 하나. 코드에는 등록표만 있고
  **순서가 없다**.
- 검증: `situation.is_recap` · `situation.published_before` 를 **부른다.**
  계약이 `verify` 본문에 그 두 이름이 있는지 확인한다.
