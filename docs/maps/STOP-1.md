# STOP-1 영향 지도 — 멈춤 사유가 ⑬ 에 안 남는다 (STEP 1-b)

## 0. 재현 (실측 2026-09-20)

```
⑬ why 분포: {}                       ← n13_send 스냅샷 0행
최근 24h ⑬ 스냅샷 0 행
흐름 결과: {"games": 32, "stopped": {"n03_freeze":21, "n06_unknown":9, "n11_no_value":2}}
```

32경기 중 ⑬ 까지 간 경기가 **0건**이라 `n13_send` **행 자체가 없다.**
"안 보냈다"와 "거기까지 못 갔다"가 구분되지 않는다.

그리고 `stop_reason` 은 `finish` 스냅샷의 **JSON 안에만** 있다 —
`analysis_runs` 에 칸이 없어 집계하려면 전 행을 파싱해야 한다.

## 1. 영향 지도 5문

**① 어디를 고치나.**

| 파일 | 무엇 |
|---|---|
| `db/schema.sql` | `analysis_runs` 에 `stopped_at`·`stop_reason` 칸 |
| `app/flow/state.py` | `stopped_at` 필드 |
| `app/flow/run.py` | `finish` 가 ⑬ 를 채우고 그 run 의 행 전체를 갱신 |

**② `stopped_at` 을 무엇으로 정하나.**
🔴 **새로 짓지 않는다.** `state.trace` 의 **마지막 노드**다 — `snapshot()` 이
이미 노드를 순서대로 쌓고 있다. `stop_reason` 코드("n03_freeze")에서 노드
이름을 파싱하면 그게 사본이고, 코드와 노드 이름이 어긋나는 날 조용히 깨진다.

**③ ⑬ 를 어떻게 채우나.**
`state.n13_send` 가 **비어 있을 때만** `{"sent": False, "why": "미도달:<노드>"}`
로 채운다. ⚠️ ⑬ 가 이미 적은 사유(`섀도`·`보드`·`등급미달`·`중복`)는
**덮지 않는다** — 그게 이 수정의 반대 위험이다.

**④ 칸을 어떻게 채우나.**
`finish` 가 그 `run_id` 의 **행 전체를 한 번 UPDATE** 한다. 멈춤은 run 단위
사실이라 행마다 다를 수 없고, 한 번의 UPDATE 로 끝난다.
⚠️ **기록 실패가 판정을 막지 않는다** — `snapshot()` 과 같은 규약으로 감싼다.

**⑤ 무엇이 깨질 수 있나.**
`analysis_runs` 에 UPDATE 가 는다(run 당 1회). 🔴 진짜 위험은 **조용한 덮어
쓰기**뿐인데, ⑬ 가 적은 사유를 보존하는 테스트가 그것을 막는다.

## 2. 틀렸을 때 알려줄 테스트

`tests/pipeline/test_stop1_stop_reason.py` 4건 —
칸이 스키마에 있는가 · ⑬ 에 못 가면 `미도달:<노드>` 가 남는가 ·
**⑬ 가 적은 사유를 덮지 않는가**(반대 위험) · `finish` 가 칸을 실제로 쓰는가.
