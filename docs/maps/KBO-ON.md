# KBO-ON — 사용자가 수집 규칙을 바꿨다

**사용자 지시 2026-09-23 원문:**
> "자동수집.크롤링 복제하는 행위를 허용한다...kbo도 해야한다.."

## 무엇이 바뀌었나 — **사실이 아니라 결정**이다

robots 실측은 그대로 사실이고 **지우지 않았다**:

```
koreabaseball.com/robots.txt (2026-09-21 13:04 · HTTP 200 · EUC-KR)
  # 본 사이트의 데이터를 사전 승인 없이 자동 수집·크롤링·복제하는 행위를 금지합니다.
  User-agent: *   Disallow: /
```

⚠️ **그 고지는 KBO 가 건 것이다.** 운영자가 "허용한다"고 해도 그쪽의 *사전
승인*이 되지는 않는다. 이 문서는 결정을 **기록**할 뿐 정당화하지 않는다.
위험은 운영자에게 귀속된다. `enabled: false` 한 줄이면 종전 상태다.

## 바꾸지 않은 것 — 서버를 속이는 쪽

🔴 지시가 바꾼 것은 **"수집하느냐"**이지 **"봇임을 숨기느냐"**가 아니다.
   그래서 UA 위장·프록시 회전·쿠키 주입·CAPTCHA 우회·429 무시는 **그대로
   금지**이고, 계약이 잠근다.

그러다 보니 종전 코드가 이미 위장하고 있었다는 것이 드러났다:

```
kbo.py:94 · kbo_boxscore.py:32 · kbo_roster.py:28 · kbo_stats.py:110
  "User-Agent": "Mozilla/5.0"      ← 브라우저 위장. 네 곳에 손으로 적혀 있었다
```

→ **`app.collectors.kbo.UA` 한 곳**으로 모으고 `AnalystBot/1.0 (sports
analysis bot)` 으로 바꿨다. 네 모듈이 그것을 import 한다(사본 금지).
⚠️ 봇임을 밝히면 차단당할 수 있다. 그건 **정직한 결과**다.

그리고 간격이 **하나도 없었다** — `polite_gap()` 을 HTTP 진입점 앞에 붙였고
값의 원본은 `config/rules.yaml` 의 `sources.koreabaseball.min_interval_sec`
(1.0초)다. 코드에 숫자를 박지 않았다.

## 영향 지도 5문

① 파일 — `config/rules.yaml` · `kbo.py`(UA·간격) · `kbo_boxscore`·
   `kbo_roster`·`kbo_stats`(UA import) · 계약 2.
② 테이블·잡 — 없음. 기존 백필 잡(`KBO 라인업 이력`)이 다시 성공하기 시작한다.
③ 깨질 테스트 — 6건. **한 건도 약화시키지 않았다**(아래).
④ 되돌릴 길 — `enabled: false` 한 줄. `require()` 자리를 지우지 않았다.
⑤ 완료 조건 — `pitcher_appearances` KBO 최신 날짜가 09-12 에서 전진 ·
   `lineups` KBO 행 > 0 · UA 가 요청에 실제로 실림.

## 계약을 약화시키지 않았다 — 잠그는 **대상**이 바뀌었다

| 종전 | 지금 |
|---|---|
| "치지 않는다"(3건) | "**정직하게** 친다"(6건) |
| `enabled is False` | `enabled is True` + **되돌릴 스위치가 산다** |
| 요청이 안 나간다 | 봇임을 밝힌다 · UA 원본 한 곳 · 간격을 둔다 · 게이트 자리를 안 지웠다 |

약화였다면 단언을 지웠을 것이다. **개수가 8 → 10 으로 늘었다.**
`/health` 의 제한 줄도 `D33·D40 → D40` 으로 줄었다 — 켜고 끈 것이 그대로
비치는 것이 그 계약의 값어치다.
