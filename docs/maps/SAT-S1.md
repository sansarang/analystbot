# SAT-S1 — 축구 전용 인공위성 어댑터

사용자 지시 2026-09-12: "단계별로 하자...우선 축구전용 인공위성을 만들어라"

## 왜

`satellite._ADAPTERS` 는 `{mlb, kbo, npb}` 뿐이라 축구는 `gather` 가
**0 을 반환하고 끝난다**(`satellite.py:548`). v3 수집의 주력이 위성인데
(야구 경기당 12건) 축구는 그 축이 통째로 비어 있다.

오늘 수동 예측에서 드러난 것: 축구는 **안트로픽이 주력이 돼 버렸고**
(J1 경기당 8건 vs 위성 4건), 그래서 안트로픽 크레딧이 소진되자
K리그1 은 위성·제미니 **두 축만으로** 판정해야 했다. 야구는 위성이 공짜로
주력이라 유료 검색이 0건인 날이 많다 — **축구도 그 구조로 돌려놔야 한다.**

### 검색어를 실측으로 골랐다 (2026-09-12, 운영 컨테이너)

같은 팀·같은 소스인데 **검색어 한 단어로 결과가 완전히 갈린다.**
`横浜F・マリノス スタメン 負傷 出場停止 コンディション 直近` 는 맥도날드·
프로야구·연예 기사를 물어왔다(6건 전부 무관).

상위 8건 중 축구 기사 수:

```
K리그1 · 다음 (울산·전북·서울·포항·대전 5팀 = 40건 만점)
  (팀명만)     39   ← 최선
  K리그 선발    37
  부상 결장     34
  선발 라인업   32 · 축구 라인업 32
  라인업       30

J1 · 야후 (팀명만, 8건 만점)
  横浜F・マリノス 8 · ガンバ大阪 8 · サンフレッチェ広島 8
  FC東京 8 · セレッソ大阪 8 · V・ファーレン長崎 8
  → 검색어를 붙이면 다른 종목으로 샌다
```

🔴 **야구와 반대다.** KBO 는 `_KBO_TERMS_LIST` 4개를 돌지만 축구는
   **팀명만이 가장 정확하다.** 그래서 `_SOCCER_TERMS = ""` 다.

⚠️ 측정 중 내 판정 함수에 버그가 있어 J1 을 한 번 0 으로 잘못 읽었다
   (팀 키를 `横浜マ` 로 잘라 제목의 `マリノス`·`横浜FM` 과 안 맞았다).
   **표기 변형 실측으로 정정했다** — 여섯 표기 전부 8/8 이었다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "_ADAPTERS\|satellite.gather" app/
app/collectors/satellite.py:497  _ADAPTERS 정의
app/collectors/satellite.py:548  adapter = _ADAPTERS.get(sport) → None 이면 0 반환
app/engine/gather.py             _satellite → satellite.read_cache (v3 수집)
app/pipeline.py                  satellite_job → gather (프리페치)
```

새로 만드는 `gather_soccer`·`soccer_query`·`_SOCCER_TERMS` 를 읽는 곳은
`_ADAPTERS` 하나다. **기존 세 어댑터는 건드리지 않는다**(계약이 단언).

빌려 쓰는 원본 — 새로 만들지 않는다:
| 무엇 | 원본 |
|---|---|
| 다음 검색·파싱 | `satellite._daum_fetch` · `parse_daum_news` |
| 야후 검색·파싱 | `satellite._yahoo_fetch` · `parse_yahoo_news` |
| 본문 수집 | `satellite._fetch_article_body` |
| 기사 모양 | `satellite._article` |
| 리그 라벨 | `app/leagues.py` 의 `LEAGUES[...]["label"]` |

## ② 만드는/바꾸는 상태

| 상태 | 성격 | 다른 곳이 다른 규칙으로 갱신하나 |
|---|---|---|
| `_ADAPTERS["soccer"]` | 표에 행 추가 | 아니다 |
| `_SOCCER_TERMS` · `_SOCCER_TOP_N` | 새 상수 | 아니다 |
| `SOCCER_ALIAS` (영어→한/일) | 새 표 | 🔴 `news_rss.QUERY_ALIAS` 와 **같은 역할**이다 — 아래 |
| `ScoutSport("soccer", active=True)` | **기존 값을 뒤집는다** | 🔴 아래 |

🔴 **별칭표를 `QUERY_ALIAS` 에 섞지 않는다.** 그쪽은 야구 팀이고
   `news_rss` 의 RSS 질의가 쓴다. 축구를 섞으면 두 경로가 한 표를 공유해
   한쪽을 고칠 때 다른 쪽이 깨진다. **같은 모양의 다른 표**로 둔다.

🔴 **`ScoutSport("soccer", active=False)` 를 켠다.** 끄기로 한 이유가
   `registry.py:138` 에 적혀 있다 — "`soccer_trial` 경로가 야구와 달리
   실전 검증을 못 거쳤고, 라인업 공시 리드타임·소스 신뢰도 실측이 없다".
   **그중 소스 신뢰도는 이번에 쟀다**(위 표). 리드타임은 아직이다.
   ⚠️ 켜면 프리페치가 축구 위성을 돌린다 — **호출이 는다**(무료지만 시간은 든다).

## ③ 리그·종목·경로 분기

**생긴다. 이번엔 불가피하다.**

| 리그 | 소스 | 언어 |
|---|---|---|
| K리그1 | 다음 뉴스검색 | 한국어 |
| J1 리그 | 야후재팬 뉴스검색 | 일본어 |
| EPL·라리가·세리에A·분데스리가·덴마크 | **없음** | 영어 등 |

🔴 **유럽 5리그는 소스가 없다.** 빈손으로 돌려주되 **로그를 남긴다** —
   "소스가 없다"와 "긁었는데 0건"은 다르다(계약이 단언).
   ⚠️ 이번 단위의 범위는 **K리그1·J1 둘**이다. 유럽은 별도 단위로,
     영어 소스를 실측한 뒤에 붙인다. 여기서 추측으로 붙이지 않는다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **기존 세 어댑터가 바뀐다** ← 가장 큰 반대 위험 | `_ADAPTERS` 의 셋이 그대로인지 단언 |
| 소스 없는 리그가 조용히 0 | 리그 이름과 함께 로그. 계약이 단언 |
| 별칭이 없는 팀이 조용히 빠진다 | **영어 이름 그대로 검색**하고 "별칭 없음"을 센다. 버리지 않는다 |
| 한 팀 검색이 터져 경기 전체가 빈손 | 팀별 `try` — 나머지는 산다(계약) |
| 같은 기사가 두 번 실린다 | `url` 기준 dedupe(계약) |
| 어댑터만 만들고 아무도 안 부른다 | `ScoutSport.active` 를 켜고 계약이 단언(PGP-2) |
| 검색어를 바꿔 수율이 무너진다 | 실측 표를 주석에 남기고, 계약이 `_SOCCER_TERMS == ""` 와 근거 숫자를 단언 |

⚠️ **아직 못 재는 것**: 긁어 온 것 중 **오늘 이 경기 것**이 몇 %인가.
   야구는 33~67% 였다. 거르는 일은 2단계(제미니)가 하므로 이번 합격 기준은
   "긁어 온다 · 조용히 0 이 되지 않는다"까지다. 경기 관련도는 다음 단계에서.

## ⑤ 이미 있는 사실을 다시 적는가

- 검색·파싱·본문·기사 모양은 전부 기존 함수를 **부른다**.
- 리그 라벨을 손으로 적지 않는다 — `leagues.LEAGUES[...]["label"]` 을 쓴다.
- 상위 N 은 야구와 같은 자리(`_KBO_TOP_N`=6)에 맞춰 `_SOCCER_TOP_N` 을 둔다.
  값을 공유하지 않는 이유는 **수율이 다르기 때문**이고, 그 근거가 주석에 있다.
