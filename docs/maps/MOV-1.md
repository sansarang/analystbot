# MOV-1 — 배당 이동 분석 (Part 1 / Phase 1-B)

## 왜

배당을 확률로 바꾸는 것(Phase 1)만으로는 부족하다. 배당이 **어디로, 왜**
움직이는지를 사전값 산출 전에 읽는다. 라인업 발표 직후 돈이 어느 쪽으로
갔는지가 **시장이 그 뉴스를 어떻게 평가했는지**를 알려준다.

## 🔴 라인 이동은 만들지 않는다 — 지시문이 정한 멈춤 조건

지시문 Part 1 허가 범위:
> 배당 크롤 자체는 수정하지 않는다. 핸디·U/O 라인이 크롤에 없으면
> **멈추고 보고**(별도 승인).

Phase 1 에서 이미 측정했다:
```
oddsportal 리그 페이지   handicapValue 0건 (KBO·EPL·라리가 전수)
theodds(유일한 파생 소스) 08-27 이후 정지 · 10개 북 동시
```
→ `move_line_hcp`·`move_line_ou` 는 **원자료가 없다.** 만들면 영원히 NULL 인
   칸이 되고, 그 칸이 있다는 사실이 "재고 있다"는 착각을 만든다.
   **승패·언더오버 확률 이동은 h2h 만으로 되므로 그것만 만든다.**

## ① 이 함수/상태를 읽는 곳 **전부**

새 모듈이라 지금은 없다. 앞으로 읽는 곳:
```
Part 1-B-4 판정 연결   confirm() · cancels()
Part 4 조건 B-3        move_class 가 news|none 이어야 최종
카드 표 · 원장         move_class · move_reason
```
빌려 쓰는 원본:
| 무엇 | 원본 |
|---|---|
| 디빅 확률 | `pipeline._market_probs` |
| 스냅샷 태그 이름 | `triggers.KINDS` (open·pre·lineup·late·close) — **같은 이름** |

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `odds_snapshots.snap_tag` | 한 칸 |
| 원장 `odds_open`·`move_class`·`move_reason` | 세 칸 (라인 둘은 **없다**) |
| `app/engine/odds_move.py` | 새 **순수 함수** 모듈 |

🔴 **소스를 섞어 계산하지 않는다**(지시문 1-B-1). 북마다 마진이 달라 소스를
   건너뛰면 이동이 아니라 소스 차이를 잰다. 계약이 그 격리를 단언한다.
🔴 **없는 값을 0 으로 읽지 않는다.** "안 움직였다"와 "모른다"는 다른 말이다.

## ③ 리그·종목·경로 분기

없다. 확률 시계열 하나를 본다. 축구 무승부 이동(`move_draw`)도 같은 함수다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 없는 스냅샷을 0 으로 읽어 "이동 없음" | `None` 반환 + 계약 |
| 🔴 소스를 건너뛰어 마진 차를 이동으로 읽는다 | `provider` 격리 + 계약 |
| 딥서치 없는 경기에 `news` 가 붙는다 | 뉴스 없으면 `money`/`none` 만 — 계약이 전 구간 단언 |
| 임계가 흔들린다 | 이동 2%p · contra 3%p 를 값으로 단언 |
| 기준선이 없을 때 조용히 최신끼리 비교 | `open` 없으면 **가장 이른 것** + 계약 |
| 라인 이동 칸이 영원히 NULL | **만들지 않는다** + 부재를 계약이 단언 |

⚠️ **아직 못 잰 것**: 완료 조건(헤이렌베인 `move_line_hcp=+1.0`)은 **라인이
   없어서** 못 잰다. 셀타 `money` · 언더 `news` 도 축구 배당이 어제까지 0건이라
   시계열이 없다 — ODP-1 배포 뒤 하루가 지나야 `open→lineup` 이 생긴다.

## ⑤ 사본

스냅샷 태그 이름을 다시 정의하지 않는다 — `triggers.KINDS` 와 같은 이름을 쓴다.
디빅을 다시 구현하지 않는다.
