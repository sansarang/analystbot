# ANL-7 — 반려당한 **문장**이 원장에 안 남는다 (ANL-4 의 반쪽)

## 왜

ANL-4 로 반려 **사유**는 남겼다:
```
analyze_check = {"l1": false, "l1_why": "결정축_근거가 입력 블록에 없는 사실이다"}
```
그런데 **무엇이 반려당했는지**(`결정축_근거` 본문)는 어디에도 없다. 원장에는
`main_axis`(결정축)만 남는다 — **검사 대상과 다른 문장**이다.

실측 2026-09-17: 오늘 밤 3건의 L1 반려 원인을 찾으려는데 검사 대상을 볼 수
없어 **결정축으로 대신 재야 했다.** 사유만 있고 대상이 없으면 못 고친다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
analyze.check_row           ← 칸 하나(reason)를 더한다
analyze.run                 ← 그 값을 넘긴다(정상 · 실패 두 길)
pick_ledger._ANALYZE_SAVE   ← **안 바뀐다**. analyze_check 안에 들어간다
db/schema.sql               ← **안 바뀐다**. 새 칸을 만들지 않는다
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **새 칸을 만들지 않는다.** `analyze_check` 안에 담는다 — 자리표를 또
  늘리면 PA-23 의 사고 자리가 하나 더 생긴다. 계약이 `$` 최대값이 10 그대로인지
  잰다.
- 🔴 **검사 결과를 안 바꾼다.** 담을 뿐이다 — `l1`·`l2` 는 안 건드린다.
- 🔴 **실패 가지에서는 비어 있다.** 호출 실패·JSON 아님이면 근거 자체가 없다 —
  `None` 이다. 빈 문자열로 채우지 않는다.
- ⚠️ 서술 전문을 담지 않는다. **검사 대상 한 문장**만이다. 원장을 글 저장소로
  만들지 않는다 — 카드 서술은 다른 경로(`order_v3`)가 이미 들고 있다.

## ③ 되돌리기

커밋 1개 revert. 인자 하나와 키 하나.

## ④ 측정

①과 **같은 명령**이 통과한다. 배포 뒤 오늘 밤 분석에서 `analyze_check.reason`
이 채워지는지 원장으로 본다(⑨).

자리표 수 불변(10) · 스키마 칸 추가 없음 · 검사 결과 불변.
