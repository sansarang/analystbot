# GATE-1 — 괴리 게이트. 딥서치를 **어디에 쓸지** 고른다.

지시문 Phase 3. 허가 범위: `app/engine/gate.py`(신설) · 테스트 · 원장 한 칸.

## 왜

딥서치는 비싸고 느리다. 전 경기에 돌리면 예산이 터지고, 안 돌리면 시장이
모르는 사실을 못 찾는다. 지시문은 **사전값과 시장이 갈린 경기에만** 쓰라고
정했다 — 둘이 같게 보는 경기는 더 알아낼 것이 적기 때문이다.

## ① 이 함수/상태를 읽는 곳 **전부**

새 모듈이라 지금은 없다. 앞으로 읽는 곳은 둘이다:
```
Phase 4 딥서치 대상 선정   select(...)
카드 표 · 원장            label · gap_pp · reason
```
빌려 쓰는 원본:
| 무엇 | 원본 |
|---|---|
| 사전값 | `prior.soccer_prior` · `prior.baseball_prior` (PRI-1) |
| 시장 확률 | `prob.p_market` · `prob.market_triple` |

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `app/engine/gate.py` | 새 **순수 함수** 모듈. DB·HTTP 없음 |
| 원장 `gate_reason` | 한 칸 (`gate_result` 는 이미 있다) |

🔴 **게이트는 확률을 바꾸지 않는다.** 고르는 일만 한다. `p_code` 를 건드리면
   조정이 이중으로 반영된다. 계약이 소스에 `p_code`·`p_send`·`adjustments(`
   부재를 단언한다.

## ③ 리그·종목·경로 분기

야구는 스칼라(홈 승 확률) 하나, 축구는 3-way 다. **같은 함수가 입력 모양으로
가른다** — 튜플이면 세 칸을 비교하고 스칼라면 한 칸이다. 종목 이름으로 분기하지
않는다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 경계값이 한 칸 어긋난다 | `<4` / `≥4` / `≤−4` 를 3.99·4.00 으로 단언 |
| 🔴 축구 빈 칸을 0 으로 읽어 그 칸이 최대 괴리가 된다 | `None` 칸은 건너뛴다 + 계약 |
| 시장·사전값이 없는데 조용히 동의로 샌다 | 둘 중 하나라도 없으면 `보드 고정` + 계약 |
| 예산이 터진다 | 상위 30% · 최소 2 · **최대 8** 을 계약이 단언 |
| 대상이 아닌 경기가 딥서치로 간다 | `동의`·`보드 고정` 제외를 계약이 단언 |
| "최소 2" 가 없는 대상을 만들어낸다 | 대상이 1건이면 1건만 — 계약 |

⚠️ **아직 못 잰 것**: 지시문 완료 조건(오늘 축구 6경기에서 셀타·헤이렌·
   브라이턴 3경기가 대상)은 **지금 잴 수 없다.**
   - 티어가 전부 `null` 이라 사전값이 전 팀 동일하다 → gap 이 시장 편차만 남는다
   - **헤이렌베인은 에레디비시**라 우리 시스템에 리그가 없다
   티어가 채워진 뒤 다시 잰다.

## ⑤ 사본

경계값(4%p)·예산(30%·2·8)을 이 파일 한 곳에만 둔다. 사전값·시장 계산을
다시 구현하지 않는다 — 호출부가 넘긴 값을 비교할 뿐이다.
