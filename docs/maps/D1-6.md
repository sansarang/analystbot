# D1-6 — ESPN 축구 호출부 + `gap_vs_median` (사용자 지시)

## 왜

D1-5 가 수집 함수를 만들었지만 **부르는 곳이 0** 이다. 그리고 `sharp_proxy`
가 샤프가 아니라는 것이 드러났으므로(D1-4: 최고 환급률 94.8~95.9%) 비교
기준을 바꿔야 한다.

사용자 지시:
1. 배당 스냅샷 잡이 **게이트 결과**(시장 과대·가치 의심·빅매치)를
   `only_names` 로 넘긴다. 5시점 각각 호출, 예산 카운터에 `espn_soccer`.
2. 샤프 부재 상태에서는 `draftkings` vs **오즈포털 4북 중앙값** 차이를
   `pinnacle_gap_dk` 로 쓰고, **샤프 비교가 아님을 라벨에 명시**한다.
3. 진짜 샤프 값은 **지금 어느 통로에도 없다** — 원장에 그렇게 남긴다.

재현:
```
PYTHONPATH=. .venv/bin/python <scratchpad>/repro_d16.py
  → gap_vs_median 없음 · 스냅샷 잡이 fetch_soccer 를 안 부른다
```

## ① 이 함수/상태를 읽는 곳 **전부**

```
app/collectors/espn_odds.py   fetch_soccer(D1-5) → 호출부 0
app/engine/book_gap.py        pinnacle_gap · SOFT_BOOK…
app/scheduler.py              _free_odds_snapshot — 배당 스냅샷 잡(유일한 자리)
app/engine/pick_ledger.py     gate_reason — 게이트 결과가 적히는 곳(GATE-2)
app/engine/bigmatch.py        is_big_match — 빅매치(BIG-1)
```

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `odds_snapshots` `book='draftkings'`(축구) | 행이 는다 |
| Redis `api_calls:{날짜}` 해시 `espn_soccer` | **새 키.** 기존 `llm_calls:{날짜}` 와 같은 방식 |

새 컬럼 없다. `pinnacle_gap_dk` 는 계산값이다.

🔴 **게이트 대상이 없으면 요청 0.** 대상 선정은 원장(`gate_reason`)과
   더비표에서 읽는다 — 새 기준을 만들지 않는다.

## ③ 리그·종목·경로 분기가 생기는가

축구만이다. 야구는 ESPN 을 이미 다른 경로로 쓴다(`parse_odds`, decimal).

## ④ 실패하면 "시끄럽게" 실패하는가

- 대상 0이면 `대상 없음(요청 0)` 을 남긴다.
- 요청 수를 세어 카운터와 로그에 남긴다 — 예산(경기당 10)이 지켜지는지
  다음 사이클에서 바로 보인다.
- `gap_vs_median` 은 **라벨에 "샤프 비교 아님"** 을 박는다. 값만 보고
  샤프 대비로 읽는 것을 막는다.

## ⑤ 시스템에 이미 있는 사실을 다시 적고 있지 않은가

- 카운터 형식은 `llm/ledger.record_call` 의 방식을 따른다(일자 해시 + TTL).
- 게이트 라벨 문자열은 `gate` 모듈 상수를 읽는다 — 문자열을 베끼지 않는다.
- 디빅은 `market_edge.implied_probs` 원본.
