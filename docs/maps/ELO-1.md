# ELO-1 영향 지도 — ①사전값이 슬레이트마다 서게 한다

## 1. 무엇이 틀렸나 (원인 사슬 — 전부 실측)

```
운영 Redis:   elo:kbo:2026-09-18 · elo:mlb:2026-09-18 · elo:npb:2026-09-18
              (축구 0개 · 오늘 날짜 0개)

최근 사이클:  [flow] 슬레이트 36경기 · 멈춤 {'n03_freeze': 36} · 발송 0
              [flow:n01] game=10325 elo 미기입 [...] — 사전값 없음
24시간 게이트: 보드고정 164 / 시장과대 6 / 가치의심 5 / 동의 3
```

사슬은 넷이다.

**① `team_elo` 캐시에는 전용 갱신 잡이 없다.** 쓰는 곳은 옛 파이프라인의
게으른 폴백 하나뿐이다:

```python
# app/pipeline.py:2913-2915
_elo_map = await _team_elo.load(redis, _sport, date)
if not _elo_map:
    _elo_map = await _team_elo.refresh(pool, redis, _sport, date)
```

⚠️ `elo_refresh_weekly` 는 **다른 물건이다** — `app/models/soccer_elo.refresh`
(football-data.co.uk CSV 재피팅)이고 `team_elo` 를 건드리지 않는다.
이름이 비슷해서 "갱신 잡이 있다"고 읽히는 자리다.

**② `PIPELINE_V14=True` 가 그 옛 경로를 지나친다.** 그래서 새 키가 안 생긴다.

**③ `n01_prior` 는 읽기만 한다** — `TE.load` 뿐이고 폴백이 없다.

**④ 캐시 키가 킥오프 UTC 날짜다.** 오늘 KST 슬레이트는 UTC `2026-09-19` 인데
그 키가 없다.

이 사슬은 숫자로 교차검증된다 — 킥오프 UTC 가 `09-18` 인 MLB **7경기**만
사전값이 섰고, 그 7경기가 정확히 `n04_hyp` 가 돈 7경기이며, 내보내기의
게이트 분포(보드고정 8 · 나머지 7)와도 같다.

## 2. 어디를 고치나

| 파일 | 무엇 |
|---|---|
| `app/flow/bridge.py` | `ensure_elo()` — 슬레이트 앞에서 **한 번** 보장 |
| `app/flow/nodes/n01_prior.py` | 뒤로 걸어가는 폴백 + `asof` 기록 |

## 3. 영향 지도 5문

**① 왜 슬레이트 단위인가.**
`TE.refresh` 는 그 종목 종료 경기를 전부 읽어 재계산한다. 경기마다 부르면
36배다. 슬레이트 앞에서 (종목, 날짜)마다 한 번이면 오늘 기준 **3콜**이다.

**② 왜 n01 에도 폴백을 두나 — 두 겹이 필요한가.**
그렇다. `ensure_elo` 는 DB 풀이 있을 때만 돈다(드라이런·테스트에는 없다).
갱신을 한 번 놓쳤을 때 슬레이트 전체가 보드고정이 되면 안 되므로, n01 은
**최대 3일 뒤로 걸어가** 최신 값을 찾는다. 이것은 내보내기가 이미 하는 것과
같은 규약이다(`for_fable.py:777`) — 한 저장소에 두 정책이 있던 것을 하나로
맞춘다(→ FORKS F-18 의 미해결 잔가지).

**③ 오래된 값을 쓰면 그것이 보이나.**
보여야 한다. 그래서 `asof` 를 스냅샷에 남긴다. 없으면 "오래된 레이팅으로
판정했다"를 영영 못 잡는다. 내보내기는 이미 `elo_asof` 를 적고 있다.

**④ n01 이 읽는 것이 늘어나나.**
아니다. **elo 와 HFA 뿐**이다(2-2 통과 조건). 계약이 `pick_ledger`·`odds`·
`n02`·`market`·`devig` 문자열이 n01 에 나타나면 실패한다.

**⑤ 축구는 풀리나.**
아니다. `team_elo.refresh` 는 `WHERE sport = $1` 로 질의하는데 축구 캐시 키는
**리그 코드**다(`elo:라리가:…`). 종목으로 긁으면 리그 간 비교가 되어
`team_elo` 머리말이 금지한 것이 된다("리그 안에서만 의미가 있다").
그리고 `MIN_GAMES=10` 을 리그별로 넘는지도 재지 않았다.
**이 단위는 야구만 고친다** — 축구는 표본부터 재야 하고, 그건 별건이다.

## 4. 안 하는 것

- 축구 elo 를 만들지 않는다(표본 측정이 먼저다).
- `elo_refresh_weekly`(축구 CSV)를 건드리지 않는다.
- 옛 파이프라인의 폴백을 지우지 않는다 — `PIPELINE_V14` 를 끄면 그쪽이 다시 돈다.
