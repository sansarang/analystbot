# PA-24 — 조정 전 기본 확률(`p_base`)이 원장에 안 남는다 (지시문 8단계)

## 왜

지시문 8단계 출력 스키마:
```json
"p_base":  {"h":49,"d":23.5,"a":27.5},
"p_final": {"h":29,"d":26,"a":45},
```
`record_prior` 는 `pri = P.soccer_prior(th, ta)` 로 3-way 를 만들어 놓고
**`p_home = pri[0]`** 로 홈만 남긴다 — 무·원정이 그 줄에서 사라진다.
원장에 `p_base` 칸도 없다.

🔴 그래서 **"조정이 얼마나 움직였나"를 원장만 보고 못 답한다.** 10단계
   변수별 채점("delta 방향이 결과와 맞았는가")의 **전제가 없다.**
⚠️ 계산 자체는 정확하다: `soccer_prior(1653, 1553) → 56.2 / 21.4 / 22.4`
   (3단계 실측 예시 PSG·브레스트 격차 100 과 같은 자리).

## ① 이 함수/상태를 읽는 곳 **전부**

```
prior.soccer_prior / baseball_prior   ← 4단계 원본. 여기서 다시 계산하지 않는다
pick_ledger.record_prior              ← 고치는 곳(:823)
  ├ _PRIOR_SAVE                       ← $8 로 p_base 추가
  └ 반환 dict                          ← 호출부가 쓸 수 있게 함께 싣는다
p_prior (홈 확률)                      ← **안 건드린다.** 읽는 곳이 여럿이다
p_code                                ← 조정 **후** 값. p_base 와 다른 것이다
db/schema.sql p_base JSONB            ← 신규 칸
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **`p_prior` 를 안 건드린다.** 이 칸은 **추가**다 — 기존 소비자
  (게이트·리포트·카드)가 읽는 값은 그대로다. 계약이 잰다.
- 🔴 **야구는 홈만이다.** 2-way 라 무 칸을 만들지 않는다 — 없는 값을
  0 으로 채우면 3-way 인 척하게 된다.
- 🔴 **티어 미기입이면 `p_base` 도 NULL 이다.** 사전값이 없는데 기본 확률을
  지어내면 U3 을 되돌리는 것이다.
- 🔴 **조정 값이 섞이면 안 된다.** `p_base` 는 4단계 결과이고 `adj`·`shrink`
  를 거치지 않는다. 계약이 그 블록에 조정 단어가 없는지 본다.
- ⚠️ 새 칸은 NULL 허용 — 기존 행은 그대로다.

## ③ 되돌리기

커밋 1개 revert. 칸은 NULL 허용이라 남겨도 무해하다. `_PRIOR_SAVE` 의 $8 과
`p_base` 조립 두 줄이 빠지면 종전과 같다.

## ④ 측정

①과 **같은 명령**이 통과한다. 배포 뒤 원장 `p_base` 에 `{"h","d","a"}` 가
찍히고, `p_code` 와 값이 **다른** 것을 확인한다(조정이 움직인 폭).

## ⑤ 계약

```
test_축구는_3way를_남긴다
test_야구는_홈만이다                      ← 반대 위험(없는 칸 만들기)
test_원장_저장에_p_base가_실린다
test_티어_미기입이면_p_base도_없다         ← 반대 위험(지어내기 · U3)
test_p_prior를_안_건드린다                ← 반대 위험(기존 소비자)
test_p_base는_조정_전_값이다              ← 반대 위험(조정 혼입)
```
