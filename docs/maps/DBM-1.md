# DBM-1 — 축구 칸 이름이 야구 칸을 가렸다. 선발·타순이 전달되지 않았다.

## 왜

실측 2026-09-13 (운영, Seattle Mariners @ Athletics, game 6003). DB에는 다 있었다:
```
games.home_pitcher = Gage Jump · away_pitcher = Bryan Woo
games.lineup_status = confirmed (22:02Z)
lineups 4행 — 양 팀 타순 9명 + 선발 이름 (statsapi)
```
그런데 제미니는 **"양 팀 모두 선발 투수와 확정 라인업이 공개되지 않아"** 라고 썼다.

```
[triage] DB요청 2
[dbref] DB로 못 채운 요청 1개: ['오늘 선발 라인업']
DB있음: ['오늘 타순', '선발 최근 등판', '불펜 최근 폼과 가용성', '일정·이동·환경']
```

야구 값이 든 칸은 `오늘 타순`인데, SOC-10 에서 **내가 추가한 축구 칸 이름이
`오늘 선발 라인업`** 이라 같은 것을 가리키는 이름이 둘이 됐다. 제미니가 축구
이름을 골랐고 야구 경기라 빈손이 됐다. **내가 만든 결함이다.**

## ① 읽는 곳 전부
```
dbref.ITEMS → bundle → matchup.<fn>    이름이 곧 프롬프트 메뉴(DB_MENU)
dbref.fetch 가 이름으로 매칭한다 (_norm 비교)
```

## ② 상태
| 상태 | 성격 |
|---|---|
| `오늘 선발 라인업` → `축구 선발 라인업` | 이름만 바꾼다 |
| `부상·결장자` → `축구 부상·결장자` | 같은 부류 예방 |

🔴 **야구 9종 이름은 건드리지 않는다.** 프롬프트·원장이 그대로 쓴다.
🔴 함수·로직은 그대로다. **이름만** 바꾼다.

## ③ 분기
없음.

## ④ 조용히 실패하는가
| 위험 | 대응 |
|---|---|
| 🔴 야구 이름이 바뀐다 | 9종 전수를 계약으로 고정 |
| 또 겹친다 | 이름 중복 0 + "라인업"이 든 이름은 종목이 붙어야 한다는 계약 |
| 축구가 그 칸을 못 찾는다 | 새 이름이 메뉴에 있는지 계약 + 축구 경기 재실행으로 확인 |

⚠️ 못 잰 것: 이름을 바꾼 뒤 제미니가 야구에서 `오늘 타순`을 부르는가.
   같은 경기(6003) 재분석으로 잰다.

## ⑤ 사본
- 메뉴 문자열을 프롬프트에 손으로 적지 않는다 — `ITEMS` 가 원본이다.
