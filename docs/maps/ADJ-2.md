# ADJ-2 — 이동연전이 구조적으로 발생할 수 없었다

## 왜 (실측 2026-09-13)

오늘 KBO·NPB 9경기 전부 `연속원정 = 0` · `trip_day = 0` 이었다. 표본이
나빠서가 아니라 **셀 수 없는 쿼리**였다:

```sql
WHERE g.sport = $1 AND (g.home = $2 OR g.away = $2) AND g.starts_at <= $3
ORDER BY g.starts_at DESC LIMIT 8
```

`$3` 는 **오늘 경기의 시작 시각**이고 `<=` 다. 그래서 첫 행이 **오늘 경기
자신**이다. 홈팀은 오늘 홈경기이므로 `r["away"] == jg["home"]` 이 거짓이 되고
첫 바퀴에서 `break` — `streak` 는 항상 0 이다.

3연전 이상 원정을 돌고 돌아온 홈팀이어도 조정이 붙지 않는다. 변수가 있는
것처럼 보였을 뿐 **한 번도 발생한 적이 없다.**

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "_TRIP\|trip_day" app/
app/engine/adjust.py   _TRIP 정의 · attach 안 1회       ← 유일한 사용처
app/engine/prob.py     ADJ_RULES["baseball"]["이동연전"] = ("trip_day", -1.0, -1.0)
                       → adjustments() 가 jg["trip_day"] 를 읽는다
```
`trip_day` 를 쓰는 곳은 `prob.adjustments` 하나다. 값이 0→1 이 되면
`adj["이동연전"] = -1.0` 이 생기고, `shrink_and_cap` 이 절반으로 줄여
**−0.5%p** 가 `p_code` 에 들어간다.

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `_TRIP` 의 `<=` → `<` | **부등호 한 글자**. 새 컬럼·새 함수 없음 |
| `jg["trip_day"]` | 0 만 나오던 값이 0/1 로 |

🔴 **발송 숫자가 바뀐다.** 지금까지 0 이던 조정이 실제로 붙는다 —
   해당 경기의 `p_code` 가 시장 대비 **−0.5%p** 움직인다.
   ⚠️ 다만 `p_code` 는 **아직 카드가 읽지 않는다**(원장 전용). 그래서 오늘
      당장 사용자에게 보이는 숫자는 안 바뀐다. 카드 배선은 별건이다.

## ③ 리그·종목·경로 분기

없다. `_TRIP` 은 `sport` 를 파라미터로 받아 종목 구분 없이 같은 규칙을 쓴다.
축구에는 `ADJ_RULES["soccer"]` 에 `이동연전` 이 없어 무해하다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **고쳐도 여전히 0 이다** | 3연속 원정 이력을 준 가짜 풀로 `streak == 3` 단언 |
| 🔴 **반대 위험 — 멀쩡한 홈팀에 벌점** | 홈경기만 이어온 팀에서 `trip_day == 0` 단언 |
| 문자열만 보는 무딘 계약 | 가짜 풀이 **SQL 의 부등호를 실제로 지킨다** — `<` 면 오늘 경기를 빼고, `<=` 면 넣는다. 그래서 이 계약은 HEAD 에서 실패한다 |
| 임계 3 이 흔들린다 | `trip_flag` 는 안 건드린다. 기존 계약 유지 |

⚠️ **아직 못 잰 것**: 실제 슬레이트에서 몇 경기나 발생하는가. 오늘은
   0/9 였다. 고친 뒤 첫 사이클에서 `adj_inputs.이동연전.연속원정` 분포를 본다.
⚠️ **이 수정이 묻지 않는 것**: "홈팀의 원정 연전"이 옳은 방향인지.
   지금 표는 홈팀이 원정을 돌고 왔으면 홈에 **불리**(−1.0)로 본다. 그 부호가
   맞는지는 CLV 로 사후 검증할 일이고(결정 B), 여기서 바꾸지 않는다.

## ⑤ 사본

임계값(3연전)·크기(−1.0%p)를 다시 적지 않는다 — `ADJ_DEFS`·`ADJ_RULES` 가 원본이다.
