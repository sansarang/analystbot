# PA-14 — `book_gap`(D1)이 만들어져 있는데 아무도 안 부른다

## 왜

「딥서치 2단계」Phase D1 원문:
> `pinnacle_gap = p_soft(강팀) − p_sharp(강팀)` (%p)
> `≥ +3` → 사설이 강팀을 샤프보다 후하게 부름 = **약팀 파생 시장 후보**
> **변수 대장에 `pinnacle_gap`.**
> 완료 조건: 슬레이트의 `pinnacle_gap` 표.

재현 3건:
```
· 원장에 pinnacle_gap 칸이 없다 — D1 완료 조건(표)을 낼 수 없다
· book_gap 을 부르는 코드가 app/ 전체에 0건 — 만들고 안 이었다
· pinnacle_gap 을 원장에 남기는 진입점이 없다
```
계산 자체는 정확하다(전제 확인):
```
pinnacle_gap({home:1.50, away:2.80}, {home:1.65, away:2.40})
  → {'gap_pp': 5.86, 'side': 'home', 'label': '사설 후함(약팀 파생 후보)'}
```

🔴 **같은 병 다섯 번째다** — `analyze`·`gate.select`·U9 흐름·U10 구조·
   `book_gap`. 전부 함수와 테스트는 있고 **운영 호출이 0건**이었다.
⚠️ 자료는 있다. 실측 2026-09-16: 48시간 안에 `sharp_proxy`·`soft_proxy` 가
   둘 다 있는 경기 **12건**(24시간 기준 6/30경기 — 커버리지는 얇다).

## ① 이 함수/상태를 읽는 곳 **전부**

```
book_gap.pinnacle_gap(soft, sharp)   ← 계산 원본. 여기서 다시 만들지 않는다
book_gap.SHARP_BOOK ("sharp_proxy")  ← 북 이름 원본. 문자열을 베끼지 않는다
book_gap.GAP_STRONG_PP (3.0)         ← 문턱 원본
odds_snapshots(book, market, side, odds)
pick_ledger.record_analysis 루프      ← CLV·이동·사전값과 **같은 자리**에 붙인다
db/schema.sql                        ← pinnacle_gap DOUBLE PRECISION (신규 칸)
(신규) pick_ledger.record_book_gap    ← 저장 전용 진입점
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **저장 전용이다. 판정을 건드리지 않는다.** D1 은 "괴리 기준선을
  `p_market`에서 `p_sharp`로 교체"까지 말하지만 **이 단위는 거기까지 가지
  않는다** — 기준선 교체는 게이트를 바꾸는 일이라 별도 단위다(한 단위 한 변경).
  먼저 값을 쌓고 표를 봐야 교체가 옳은지 안다.
- 🔴 **실패해도 판정을 막지 않는다** — CLV·이동과 같은 규약(`try/except` + 로그).
- 🔴 **사설 평균으로 샤프를 대체하지 않는다.** 지시문 "하지 말 것" 원문:
  *"피나클 값이 없다고 사설 평균으로 대체하기 — NULL 로 두고 게이트는
  사전값 기준으로 폴백."* 한쪽이 없으면 **NULL** 이다.
- 🔴 **북 이름·문턱을 손으로 적지 않는다.** `book_gap` 상수가 원본이다.
- ⚠️ 커버리지가 얇다(24h 6/30경기). 표가 얇게 나오는 것은 **결함이 아니라
  사실**이고, 그 사실이 다음 결정의 입력이다.
- ⚠️ 새 칸은 NULL 허용 — 기존 행은 그대로다.

## ③ 되돌리기

커밋 1개 revert. 새 칸은 NULL 허용이라 남겨도 무해하다. 저장 호출 한 줄과
진입점 함수가 빠지면 종전과 같다. 판정·발송 경로를 안 건드렸다.

## ④ 측정

①과 **같은 명령**이 통과한다. 그리고 배포 뒤 원장에 `pinnacle_gap` 이 실제로
찍히는 원문 + 오늘 슬레이트 표(D1 완료 조건).
