# D1-2 — 포지션마다 `odds` 모양이 다르다 (북별 파싱 0건의 원인)

## 왜

D1-1 배포 뒤 완료 조건을 재니 **3경기 모두 북별 줄이 0** 이었다
(`sharp_proxy 있음: False`). 단계별로 재서 원인을 확정했다 — 실측 원문:
```
위치 0: {"549":{"odds":[5.25],      "highestPayout":94.4}, …}   ← 배열
위치 1: {"549":{"odds":{"1":3.8},   "highestPayout":94.4}, …}   ← 객체
위치 2: {"549":{"odds":{"2":1.65},  "highestPayout":94.4}, …}   ← 객체
```
내 정규식이 `"odds":\[…\]`(배열)만 받아 **무·원정 칸이 통째로 비었고**,
"세 칸 다 찬 북"이 0이 되어 `sharp_id` 도 서지 않았다.

재현:
```
PYTHONPATH=. .venv/bin/python <scratchpad>/repro_d12.py
  → 🔴 객체형 odds 를 못 읽는다 (파싱 {})
```

## ① 이 함수/상태를 읽는 곳 **전부**

```
app/collectors/oddsportal.py   parse_books(정의) · fetch_soccer_league · fetch_league
tests/test_book_gap.py         계약
```
바뀌는 것은 `parse_books` 안의 정규식 하나다. 반환 모양·호출부는 그대로.

## ② 만드는/바꾸는 상태

**없다.** 같은 응답에서 **읽히는 칸이 늘 뿐**이다(무·원정). 요청도 늘지 않는다.

## ③ 리그·종목·경로 분기가 생기는가

생기지 않는다. 야구(2-way)는 위치 0·1 이고 같은 규칙으로 읽힌다.

## ④ 실패하면 "시끄럽게" 실패하는가

- 이미 로그가 `북별 N경기(샤프대용 M · 최소 3북)` 를 찍는다. 0이면 그 자리에서
  드러난다 — **이번 결함이 바로 그 줄로 잡혔다.**
- 계약에 **실측 원문 모양**(배열 + 객체 혼합)을 그대로 넣어 재발을 막는다.

## ⑤ 시스템에 이미 있는 사실을 다시 적고 있지 않은가

- 위치→칸 대응(0=홈·1=무·2=원정)은 D1-1 이 정한 것을 그대로 쓴다.
- 값 검증(1.0 이하 버림)·세 칸 필터도 그대로다.
