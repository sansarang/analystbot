# PA-17 — U10 구조 픽이 계산만 되고 버려진다

## 왜

U10 은 `structure.candidates`(edge ≥ 6%p · 상관 픽 하나)와 `grade`(≥8 상 /
≥6 중)를 만들었다. 그런데 **운영 호출 0건**이고 원장 `structure_pick` 은
PART A 실측에서 **0/2경기**였다. `record_confirm_and_analysis` 가 이미
`attach_derived` 로 파생 디빅을 만들어 두는데 거기서 후보를 안 뽑고 버렸다.

계산 자체는 정확하다(전제 확인):
```
candidates(p_code=0.62, away -1.5 @ 30%) → [('spreads','away', 20.0%p)]
grade(8.5) → 상 · grade(6.5) → 중
```

🔴 **같은 병 여덟 번째다** — analyze · gate.select · U9 · U10 · book_gap ·
   예산 · 흐름 · 이번.

## ① 이 함수/상태를 읽는 곳 **전부**

```
structure.candidates / grade / EDGE_MIN_PP    ← 원본. 숫자를 베끼지 않는다
structure.attach_derived / derived_probs      ← 이미 부르는 자리
pick_ledger.record_confirm_and_analysis       ← 고치는 곳(같은 try 블록)
odds_snapshots(market in spreads/totals)      ← 입력. 이미 읽고 있다
pick_ledger.structure_pick                    ← 칸은 이미 있다(U10 스키마)
confidence.py:257                             ← grade 를 "원본은 structure" 라고
                                                 적어 두고 숫자는 안 적었다(그대로)
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **저장 전용이다.** 승패 판정·확신을 건드리지 않는다. 구조 픽은 파생
  시장 후보일 뿐이고 발송 여부는 조건 B 의 몫이다.
- 🔴 **후보가 없으면 쓰지 않는다.** `edge < 6%p` 면 `structure_pick` 은 NULL
  이고 그 사실이 로그에 남는다 — 0 으로 채우지 않는다.
- 🔴 **상위 1건만 남긴다.** `candidates` 가 이미 상관 픽을 하나로 줄이지만,
  원장에는 edge 최대 1건 + 후보 수를 적는다(카드가 여러 줄을 못 받는다).
- 🔴 **실패해도 판정을 막지 않는다** — 기존 파생 디빅 try 블록 안이다.
- ⚠️ **PA-17-b 로 등록: 부호 규약을 생산자와 대조하지 않았다.**
  이 코드는 **음수 라인 = 받는다**로 읽는다(`away -1.5` → 우리 확률 +12%p).
  그런데 `espn_odds.parse_soccer_odds` 는 "홈 라인 그대로 · 원정 부호 반전"
  으로 저장한다. 둘이 맞는지 **아직 안 쟀다.** 어긋나면 구조 픽이 반대로
  선다 — U10 의 `abs(line)` 버킷 사고와 같은 종류다.

## ③ 되돌리기

커밋 1개 revert. 같은 try 블록에서 후보 계산과 UPDATE 가 빠지면 종전처럼
파생 디빅만 만들고 버린다. 판정·발송 경로는 안 건드렸다.

## ④ 측정

①과 **같은 명령**이 통과한다. 배포 뒤 원장 `structure_pick` 에
`market·side·line·edge_pp·grade` 가 찍히는 원문, 또는 `구조 후보 없음` 로그.
