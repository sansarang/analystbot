# PA-15 — 위성 추출에 상한이 없다. 지시문 §3 의 예산이 안 걸린다

## 왜

지시문 §3 원문:
> 상한 슬레이트 **30%(최소 2, 최대 8)**, 우선순위 **|gap| 큰 순**.

PA-13 이 "게이트 대상이면 추출"을 열었는데 **몇 건까지인지는 안 걸었다.**
`gate.select` 가 §3 을 글자 그대로 구현해 놓고 여전히 **호출 0건**이다.
게이트 대상이 많은 날이면 무료 한도(groq 분당 8,000 토큰)가 그대로 터진다 —
오늘 아침 잔량이 175까지 내려간 전례가 있다.

재현 2건:
```
· 원장에 gate_gap_pp 칸이 없다 — |gap| 큰 순으로 못 고른다
· 위성에 대상 선별 함수가 없다 — gate.select(30%·2·8) 호출 0건
```
수정 후: `게이트 대상 12경기 → 선별 4건 [0,1,2,3]` (30% · |gap| 상위)

## ① 이 함수/상태를 읽는 곳 **전부**

```
gate.select(rows)                    ← 예산 원본(30%·2·8). 값을 베끼지 않는다
gate.BUDGET_RATIO / MIN / MAX        ← 상수 원본
pick_ledger._PRIOR_SAVE              ← gate_gap_pp 를 함께 쓴다($7)
  └ PA-6 보드 분기는 None (gap 이 없다)
satellite._DUE_SQL                   ← l.gate_gap_pp 를 실어 온다
(신규) satellite.select_search_targets
satellite.run_satellite 루프          ← 예산 밖이면 jg["gate_label"] 을 안 싣는다
extract_game_facts                   ← 라벨이 없으면 빅매치 판정으로(PA-13)
db/schema.sql                        ← gate_gap_pp DOUBLE PRECISION
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **수집 자체는 막지 않는다.** §3 의 상한은 **검색·추출** 예산이고,
  층1 수집(기사·Transfermarkt·Flashscore)은 전 경기가 그대로 받는다.
  계약이 루프에서 `continue` 가 안 생겼는지 잰다.
- 🔴 **빅매치 경로를 없애지 않는다.** 예산 밖 경기는 라벨만 빠지고,
  빅매치면 종전대로 추출된다(PA-13 경로).
- 🔴 **예산 숫자를 손으로 적지 않는다.** `gate` 상수가 원본 — 계약이 잰다.
- 🔴 **"최소 2"는 대상 안에서 최소다.** 대상이 1건이면 1건이다. 없는 것을
  만들어 예산을 채우지 않는다(`gate.select` 주석 그대로).
- ⚠️ 라벨이 없는 경기(판정 전)는 예산에서 안 뽑힌다 — 위성이 판정보다 먼저
  도는 사이클에서는 종전과 같다. 예산은 **게이트 대상에만** 건다.
- ⚠️ §3 은 "원장에 `search_selected`와 사유"도 요구한다. **이 단위는 로그까지다** —
  선별은 `(gate_label, gate_gap_pp, 슬레이트)` 로 재현 가능하므로 칸을
  늘리지 않았다. 필요하면 별도 단위.

## ③ 되돌리기

커밋 1개 revert. 새 칸은 NULL 허용. 선별 함수와 라벨 마스킹이 빠지면
PA-13 상태(상한 없음)로 돌아간다. 판정·발송 경로는 안 건드렸다.

## ④ 측정

①과 **같은 명령**이 통과한다(12경기 → 4건). 배포 뒤 첫 사이클에서
`[satellite] §3 대상 선별 — 슬레이트 N · 게이트 대상 M · 선별 K` 로그 원문과
`[quota]` 잔량.
