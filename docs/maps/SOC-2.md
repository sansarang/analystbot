# SOC-2 — 축구 3-way(홈승·무·원정승). 야구는 한 글자도 안 바뀐다.

## 왜

`apply_winner` 는 **팀 이름 하나**를 받아 홈/원정에 맞춘다:

```python
w = verdict["승자"]
hit_h, hit_a = _name_hits(w, home), _name_hits(w, away)
if hit_h == hit_a:           # 둘 다거나 둘 다 아니다
    return False             # 판정을 버린다
```

축구는 **무승부가 정상 결과**인데 표현할 칸이 없다. `"무"` 를 승자로 주면
두 팀 다 안 맞아 `False` 가 되고 **판정이 통째로 버려진다.**

인계 문서(§6)에 "3-way 가 진짜 난점이다 … 야구 코드를 건드리지 않고 확장할
수 있는지가 갈린다"고 적어 둔 그 자리다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "apply_winner" app/
app/engine/matchup.py:559  정의
app/engine/matchup.py      _judge_v2 · _judge_v3 에서 각 1회  ← 유일한 호출부

$ grep -rn 'jg\["winner"\]\|\.get("winner")' app/
app/engine/form_card.py    render_search_card — 승자 줄
app/pipeline.py            _render_card_v3 — **판정 여부를 winner 로 센다**
app/engine/matchup.py      apply_winner 가 쓴다
```

🔴 **`_render_card_v3` 가 `winner` 로 판정 여부를 센다.** 무는 `winner` 가
   없으므로 그대로 두면 **"판정 실패"로 나간다** — SRCH-5 에서 고친 P0 와
   **똑같은 결함**이다. 그래서 카드도 같은 단위에서 고친다.

빌려 쓰는 원본:
| 무엇 | 원본 |
|---|---|
| 팀명 매칭 | `matchup._name_hits` (현지어 약칭 대응) |
| 확신 눈금 | `verdict.level` |
| 카드 렌더 | `form_card.render_search_card` |

## ② 만드는/바꾸는 상태

| 상태 | 성격 | 다른 곳이 다른 규칙으로 갱신하나 |
|---|---|---|
| `matchup["결과"]` | **새 키** (홈승·무·원정승) | 아니다. 2-way 경로에는 **안 생긴다**(계약) |
| `matchup["승자"]` | 무일 때 `None` | 🔴 아래 |
| `jg["winner"]` | 무일 때 `None` | 🔴 아래 |

🔴 **`winner=None` 이 "판정 실패"로 읽히면 안 된다.**
   지금 `_render_card_v3` 의 `judged` 가 `winner or matchup["승자"]` 로 센다.
   무는 둘 다 `None` 이라 미판정으로 빠진다. → `결과` 가 있으면 판정으로 센다.

🔴 **2-way 원장에 `결과` 키를 만들지 않는다.** 없던 키가 생기면 카드·L1 감사가
   그것을 읽기 시작한다. `결과` 로 온 경우에만 싣는다(`확신`·`서술` 과 같은 방식).

## ③ 리그·종목·경로 분기

**종목 분기를 만들지 않는다.** 입력의 모양으로 가른다:

```
verdict 에 "결과" 가 있으면   → 3-way 로 읽는다 (홈승·무·원정승)
없으면                      → 종전대로 "승자" 이름으로 읽는다
```

⚠️ 그래서 야구가 실수로 `결과: "무"` 를 보내면 **버려진다**(계약).
   야구에 무승부 판정은 없다 — 들어오면 그건 오류다.
⚠️ 축구가 `승자` 로 팀 이름을 보내도 종전 경로로 처리된다(호환).

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **2-way 동작이 바뀐다** ← 가장 큰 반대 위험 | 야구 승자·버리기·키 부재를 전부 단언 |
| 🔴 **무가 "판정 실패"로 나간다**(SRCH-5 P0 재발) | 카드가 무를 판정으로 세는지 단언. 경기별 카드가 "무승부"를 적는지도 |
| 지어낸 라벨이 통과한다 | `홈승·무·원정승` 외에는 전부 버린다(계약: `승`·`draw`·`""`·`None`·`홈`) |
| 경기에 없는 팀을 고쳐 쓴다 | 버리는 길을 그대로 둔다(실측 2026-09-11 전례) |
| 무인데 확신·서술이 사라진다 | 3-way 에서도 실리는지 단언 |

⚠️ **아직 못 재는 것**: 제미니가 축구에서 무를 얼마나 내는가. 오늘 수동
   예측에서는 4경기 중 1건이 무였는데 **재료 0인 경기**였다(나가사키전).
   재료가 있는데도 무가 나오는지는 실측이 필요하다.

## ⑤ 이미 있는 사실을 다시 적는가

- 팀명 매칭을 다시 쓰지 않는다 — `_name_hits` 를 그대로 부른다.
- 확신 눈금을 새로 만들지 않는다 — `verdict.level`.
- 카드 문구를 경기별/슬레이트 두 곳에 따로 적지 않는다 — 슬레이트는
  `render_game_easy` 를 부르고, 경기별 문구는 `form_card` 한 곳에만 있다.
- 라벨 문자열(`홈승·무·원정승`)은 **상수 한 곳**에 두고 프롬프트·판정·카드가
  그것을 쓴다.
