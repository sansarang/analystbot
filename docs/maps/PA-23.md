# PA-23 — 변수 원장에 `source`·`evidence` 가 없다 (지시문 5단계)

## 왜

지시문 5단계:
> 각 변수는 **(name, value, delta_pp, source, evidence)** 튜플로 원장에 남김.
> 예: `{"name":"rest_gap","delta":+2,"source":"api","evidence":"MUN last game 2026-09-10"}`

지금 `adj_pp` 는 `{변수명: %p}` 평면 dict 라 **delta 만 있고 근거가 없다.**
`adj_inputs` 에 원값이 있지만 **원장에 안 남고** source·evidence 도 없다.
그래서 "이 −2%p 가 어디서 왔나"를 원장만 보고 못 답하고, **10단계 변수별
채점이 무엇을 채점하는지 모른다.**

## 🔴 설계 변경 — `adj_pp` 모양은 안 바꾼다

지시문 문자대로 `adj_pp` 를 튜플 모양으로 바꾸면 **소비자 다섯이 조용히
깨진다.** 전수 조사 실측:
```
pipeline:2861        adj_json(adj) 로 쓴다
pick_ledger:1084     값들을 **합산**한다 (PA-16 adj_confirm)
pick_ledger:1260     analyze 입력 blk 에 싣는다
analyze:85           f"{k} {v:+g}" — v 가 **숫자라고 가정**한다
confidence:209       len(raw) — 조정 개수를 센다
```
→ `delta_pp` 는 `adj_pp` 가, 나머지(value·source·evidence)는 **새 칸**이
   맡는다. 지시문 요구는 둘을 합쳐 충족한다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
adjust.attach                      ← 근거를 만드는 곳(_ev 헬퍼)
  ├ 주전결장 → lineup_events
  ├ 필승조연투 → pitcher_appearances
  ├ 구속하락 → statcast (PA-18)
  └ 이동연전 → games
jg["adj_evidence"]                 ← 새 키
pick_ledger._row_from_game         ← 저장(INSERT 칸 +1)
db/schema.sql adj_evidence JSONB   ← 신규 칸
adj_pp 소비자 다섯                  ← **안 건드린다**(위 목록)
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **`adj_pp` 는 숫자 dict 그대로다.** 계약이 소비자 둘(analyze 렌더·
  confidence 카운트)을 직접 잰다.
- 🔴 **값이 없으면 근거도 없다.** `_ev` 가 `None` 을 걸러낸다 — 못 잰 변수를
  "0이었다"로 적으면 채점이 거짓이 된다.
- 🔴 **INSERT 자리표를 함께 늘렸다.** 칸만 늘리고 `$n` 을 안 늘리면 원장
  저장이 통째로 터진다 — 계약이 칸 수와 값 수를 센다.
- 🔴 **출처는 실재하는 테이블·소스 이름만** 쓴다(계약이 화이트리스트로 잰다).
  "api" 같은 뭉뚱그린 이름은 나중에 추적이 안 된다.
- ⚠️ 새 칸은 NULL 허용 — 기존 행은 그대로다.
- ⚠️ `evidence` 는 **사람이 읽는 한 줄**이다. LLM 에게 주는 문장이 아니라
  원장을 보는 사람을 위한 것이다.

## ③ 되돌리기

커밋 1개 revert. 칸은 NULL 허용. `_ev` 헬퍼와 호출 넷, INSERT 한 칸이
빠지면 종전과 같다.

## ④ 측정

①과 **같은 명령**이 통과한다. 실측:
```
adj_evidence = {'필승조연투': {'value': {...}, 'source': 'pitcher_appearances',
                'evidence': '직전 2일 연속 등판 · home 0명 · away 0명'},
                '이동연전': {'value': {...}, 'source': 'games',
                'evidence': '홈팀 직전 연속 원정 0경기 (문턱 3)'}}
```
