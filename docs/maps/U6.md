# U6 — 표적 수집. need 가 정한 것만 모으고, 8칸을 다 저장한다

## 왜

```
재현 8건:
  parse_lineup 이 marketValue·totalStarterMarketValue 를 안 읽는다
    (원자료엔 있다 — 실측: starters[].marketValue=1173408 ·
     totalStarterMarketValue 가시마 6,352,468 / 제츠 4,098,733)
  최근 5경기(matchFacts.teamForm)를 읽는 함수가 없다
  추출 스키마 4칸이 저장되지 않는다: doubt · last3 · midweek · notes
  수집이 need 와 무관하게 전부 돈다
  sources.yaml 에 tier0_primary 가 없다
  결장표 전용 파서가 없다 · snippet_level 이 없다
```
U5 가 need 를 만들었는데 **수집이 그것을 안 본다.** 그리고 8칸 중 4칸이
프롬프트에만 있고 저장되지 않아 U7(확인 판정)이 맞출 대상이 없다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
fotmob.parse_lineup   ← attach · match_lineup · _lineup_recheck · 진단
satellite.extract_game_facts / read_extract  ← gather._satellite → matchup v3
scout_config.rank / screen / rank_and_pick   ← satellite_soccer
config/sources.yaml   ← scout_config.SOURCES (tier1·2·3·blocked·js_only)
hypothesis.FIELDS     ← U5 가 정한 need 이름(= 저장 칸 이름이어야 한다)
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **need 한정이 수집을 굶기면 안 된다.** need 가 비었을 때(보드 고정)와
  need 를 못 받았을 때(호출부 미배선)는 다르다 — 후자는 **종전대로 전부**
  모은다. 계약이 둘을 가른다.
- 🔴 `parse_lineup` 반환 모양이 바뀐다. 읽는 곳이 넷이다 — **기존 키를 지우지
  않고 더하기만** 한다(`starters` 는 그대로, `players` 를 새로 둔다).
- 🔴 `tier0_primary` 를 넣으면 `rank()` 가 1 보다 앞선 등급을 알아야 한다.
  **`RANK_UNKNOWN`·`RANK_UNLISTED` 의 상대 순서가 깨지면 fetch 순위가 뒤집힌다.**
- ⚠️ 파서는 **도메인별**이다. 실패하면 LLM 추출로 되돌아간다(없는 것으로 치지
  않는다). 파서가 xi/out 을 채우면 그 경기 LLM 콜은 0이다.
- ⚠️ `tier0_primary` 값은 **사용자가 채운다**(구단 공식 도메인 추측 금지).
