# D38 — `is_recap` 이 예고 기사를 버린다 (영향 지도 5문)

사용자 지시 2026-09-21: "순서대로 해" (딥서치 배선 1순위 = DS-3 의 전제)

## ① 무엇이 틀렸나 — 실측

```
[AI프리뷰] 20일 잠실 LG-한화전, 한화 좌완 영건 황준서 선발 기회 살릴
   → 표지 `리뷰` 가 **`프리뷰`** 안에서 걸린다
【中日スタメン速報】ドラ1ルーキー…7月15日以来の勝利目指し先発 岡林勇希が
   → 표지 `勝利` 가 **`勝利目指し`**(승리를 **노린다**·미래) 안에서 걸린다
```
🔴 우리가 **가장 원하는 기사**(스타멘 발표·프리뷰)를 버리는 방향의 오탐이다.

## ② 왜 지금인가 — DS-3 의 전제다

```
운영 캐시(구글 RSS) 기준 오탐 후보   0건 (제목 137건 중 폐기 40건, 오탐 0)
Bing 결과 기준                     **실제로 터졌다**
```
지금은 규모가 0 이라 급하지 않다. 그런데 **DS-3 이 소스를 Bing 으로 바꾸는
순간** 위 두 제목이 들어오고 오탐이 살아난다. 그래서 배선보다 먼저 고친다.

## ③ 어디를 건드리나

| 파일 | 무엇 |
|---|---|
| `app/registry.py` | `RECAP_FUTURE_JA` — 미래형 꼬리말 **목록 1개** |
| `app/engine/situation.py` | `_recap_hits()` 추가 · `is_recap` 이 그것을 쓴다 |

**표지 목록은 안 건드린다** — `registry.RECAP_MARKERS` 가 원본이고 그대로다.

## ④ 사본이 생기나

🔴 **안 생기게 했다.** 표지는 `recap_markers()` 가 원본, 미래형 꼬리말도
`registry` 에 둔다(표지 옆). `situation.py` 에는 **낱말을 한 개도 적지 않는다** —
계약 `test_규칙을_코드에_박지_않았다` 가 `리뷰`·`勝利`·`beat`·`sweep` 이
그 파일에 없음을 확인한다.

## ⑤ 🔴 반대 위험을 함께 잠근다

새 필터의 규칙이다(CLAUDE.md): "반대 위험(정상 데이터 폐기)을 함께 측정한다."
여기서는 **거꾸로**다 — 느슨하게 고치면 **진짜 경기 후 기사가 샌다**.
`_REAL_RECAP` 6건(점수 표기·快勝·逆転勝ち·beat·highlights)이 여전히 버려지는지
계약이 확인한다. 운영 제목 137건으로 전후 분류를 대조한다.

## ⑥ 경계 규칙 — 언어마다 다르다

| 언어 | 규칙 | 이유 |
|---|---|---|
| 한국어 | 앞 글자가 **한글이면 표지가 아니다** | `프리뷰` 의 `리뷰` |
| 영어 | `\b` 낱말 경계 | `beats` vs `beat` 는 표지에 둘 다 있다 |
| 일본어 | **뒤에 붙는 말**로 가린다(`目指し`·`へ`·`に向け`…) | 띄어쓰기가 없어 경계가 없다 |

⚠️ 한국어 규칙의 대가: `역전승리` 같은 붙은 말이 통과할 수 있다.
   운영 137건으로 재서 실제로 새는지 확인한다.
