# DS-2P — 변화 감지에 파서를 붙인다 (영향 지도 5문)

사용자 지시 2026-09-21: "순서대로 전부 진행해라" (2번 = D42 파서)

## ① 🔴 지연이 실제로 문제였다 — 숫자로 확인했다

```
마린스 vs 세이부      시작 18:00 · 공지 08:30 · DB 반영 14:00  → **5시간 30분 늦음**
라쿠텐 vs 소프트뱅크  시작 13:00 · 중지 12:40 · DB 반영 14:00  → **시작을 지나서 알았다**
```
오늘 NPB 5행이 **전부 `updated_at` 14:00** 이다 — 배치 잡이라 사건이 아니라
시각에 맞춰 돈다. `watch_10m` 이면 08:40 경에 잡았을 것이다.

⚠️ 사실 자체는 DB 에 **있었다.** 없던 것은 **시각**이다. 그것이 이 단위의 값이다.

## ② 🔴 키워드로 짜려다 측정이 막았다

구단 공지 페이지의 `中止` 는 **메뉴 문구**다:
```
라쿠텐 공지  中止 9회 → 전부 「地方主催試合中止時の払い戻し」(환불 안내 메뉴)
마린스 공지  中止 0회 → 오늘 중지가 그 페이지에 아예 없다
NPB 공시     中止 2회 → 「*-* （楽天モバイル） 中止」  ← 진짜
```
진짜는 **npb.jp 의 스코어보드 띠**에 **구조로** 들어 있다:
```html
<div class="score_box"><a href="/scores/2026/0921/e-h-23/">
  <img alt="東北楽天ゴールデンイーグルス" class="logo_left">
  <img alt="福岡ソフトバンクホークス"   class="logo_right">
  <div class="score">*-*</div>
  <div class="state">（楽天モバイル）<br>中止</div>
</a></div>
```
→ 날짜(href) · 두 팀(alt) · 점수 · 경기장 · 상태를 **전부** 준다.

## ⑤ 사본이 생기나

- 팀명: `alt` 속성에서 읽는다 — **표를 만들지 않는다**(계약이 확인).
- 상태 사실: `watch.StatusFact` 가 원본(`as_of` 필수 · 최신이 이김 · stale).
- 요청: DS-1 런타임.

⚠️ **파서를 하나만 만들었다.** 지시문이 말한 다섯(npb.jp 공시 · 구단 공지 ×2 ·
   스포츠나비 경기 페이지)을 한 커밋에 넣으면 무엇이 틀렸는지 못 가린다.
   그리고 **구단 공지 둘은 이번 측정에서 쓸모가 없었다** — 값이 없거나 메뉴뿐이다.
