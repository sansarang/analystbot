# STR-2 영향 지도 — `starter_recent3` 가 교체 메모만 보고 있었다

## 1. 무엇이 틀렸나

변수 이름은 **"선발 최근 3등판"** 인데 ⑤의 처리는 이렇다:

```python
if var == "starter_recent3":
    notes = await _cache_starter_notes(state, ctx)   # 선발 '교체' 메모
    if notes: out.append(...)
    continue                                         # 없으면 증거 0
```

선발이 안 바뀐 경기는 언제나 `unknown` 이다 — 그게 대부분이다.
오늘 7경기 전부 그랬다.

자료는 DB 에 있다(실측 2026-09-20):

```
Hayden Wesneski 선발 등판 7행 · Michael McGreevy 6행 · Brandon Pfaadt 6행
```

내보내기는 이미 그 값을 쓴다(`_STARTER_SQL` · STR-1 의 `recent6`).

## 2. 어디를 고치나

`app/flow/nodes/n05_evidence.py` — `starter_recent3` 분기 + 상대 선발 선택 함수.

## 3. 영향 지도 5문

**① 누구의 최근 등판인가.**
🔴 **상대 선발**이다. 우리 픽이 원정이면 **홈 선발**이 우리를 막는 쪽이고,
그쪽 최근 등판이 우리 득점 전망을 바꾼다. 계약이 그 방향을 고정한다.

**② 선발 이름을 어디서 아나.**
`games.home_pitcher`·`away_pitcher` 다. ⑤가 이미 풀을 갖고 있으므로 한 번
조회한다. 없으면 **증거 0** 이고 지어내지 않는다.

**③ 교체 메모는 버리나.**
버리지 않는다. **둘은 다른 사실이다** — "선발이 바뀌었다"와 "그 선발이 최근
어떻게 던졌나". 둘 다 증거로 싣고, 출처(`source`)로 구분한다.

**④ 부호는 어디서 정하나.**
여기서 정하지 않는다. ⑤는 **사실만 싣고** `sides` 로 누구 쪽 사실인지만
적는다. 유불리(`pp`)는 ⑦(`n07_adjust`)의 몫이다 — 그 경계를 넘지 않는다.

**⑤ 무엇이 조용히 0이 되나.**
등판 기록이 0행이면 증거가 없다. 그건 사실이므로 `unknown` 이 맞다.
다만 DT-1 처럼 **조회가 실패해서** 0행인 것과 구분되어야 하므로 실패는
`warning` 으로 올린다(같은 커밋의 DT-1 과 같은 규약).

## 4. 안 하는 것

- ⑦의 가중치를 건드리지 않는다.
- 내보내기의 `recent6` 정의를 바꾸지 않는다(그쪽은 "우리가 본 등판 전부",
  여기는 "최근 3등판" — 창이 다르고 용도가 다르다).
