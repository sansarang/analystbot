# U7 — 확인 판정 H2. "자료가 많으면 픽"을 끝낸다

## 왜

`confirmed/refuted/unknown` 이 없어서 지금은 **자료가 많으면 픽**이 된다.
U5 가 need 를 만들고 U6 가 그것만 모으게 했는데, **모은 것이 가설을 세웠는지
무너뜨렸는지 판정하는 자리**가 비어 있다.
`unknown 과반 → 보드` 가 원칙 4·11 의 구현이다 — 모르는 것이 절반을 넘으면
픽을 내지 않는다.

```
재현:
  hypothesis.confirm 이 없다
  원장에 confirmed·refuted·unknown_axes 칸이 없다
  unknown 과반 → 보드 규칙의 상수가 없다
```

## 🔴 U6 가 만든 구분이 판정의 전제다

`fill_schema` 가 **`None`(모른다)** 과 **`[]`(없다)** 를 구분해 둔다:
```
값이 있다(truthy)   → confirmed   찾았다
값이 [] / False     → refuted     봤는데 없다
값이 None           → unknown     안 봤다 / 소스가 없다
```

## ① 이 함수/상태를 읽는 곳 **전부**

```
(신규) hypothesis.confirm   ← S5 직후(판정 연결은 U12)
                            ← 원장 confirmed · refuted · unknown_axes
hypothesis.Hypothesis       ← 입력(need · sufficient_count)
satellite.fill_schema       ← None/[] 구분의 원본
settings.unknown_board_ratio ← 과반 기준(U13 에서 rules.yaml 로 옮긴다)
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **`[]` 를 unknown 으로 읽으면 안 된다.** "결장 0명"은 정보다 — 그걸
  모른다고 치면 멀쩡한 경기가 보드로 간다. 계약이 셋을 각각 단언한다.
- 🔴 need 가 빈 목록(보드 고정)이면 `sufficient` 는 **False** 다. `0 >= 0` 으로
  통과시키면 아무것도 안 찾고 픽이 나간다.
- 🔴 상대편 칸을 내 것으로 읽으면 반대 방향 근거가 내 근거가 된다.
  `Need.side` 로만 본다 — 계약이 교차 확인한다.
- ⚠️ 과반 기준은 **상수**다. 지금은 `app/config.py` 에 두고 U13 에서
  `config/rules.yaml` 로 옮긴다(지시문 그대로).
- ⚠️ 이 U 는 **판정만** 한다. 서술·발송 연결은 U12 다.

## ③ 되돌리기

커밋 1개 revert 로 끝난다. 원장 칸은
`ALTER TABLE pick_ledger DROP COLUMN confirmed, refuted, unknown_axes` 로
지운다. `confirm` 은 순수 함수이고 아직 판정 경로에 연결돼 있지 않아
되돌려도 발송·채점에 영향이 없다.

## ④ 측정

오늘 4경기 S6 원문. 대전은 confirmed ≥ 2 예상.
