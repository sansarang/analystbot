# SRCH-4 — 게이트가 "없다"를 버린다. 그리고 퍼플렉시티를 같은 문으로 넣는다.

사용자 지시 2026-09-12: "퍼플릭스와 안트로픽"

## 왜 — SRCH-3 배선 증명에서 드러난 결함

```
[websearch] 받음 2 · 채택 0 · 폐기 2 (오래됨 0 · 날짜없음 2 · 미래 0)
```

강제 주입한 두 질문은
- "오늘 잠실에 우천 취소나 지연 가능성이 보도됐는가"
- "두산 마무리가 어제 연투해 오늘 등판이 어려운가"

**둘 다 답이 "없다"인 질문**이다. 부재를 확인한 답에는 **인용할 기사가
없으니** 근거일자를 못 적고, 게이트가 전부 버렸다.

누적 표본: **8문 중 3건(37.5%)이 `날짜없음` 으로 폐기.**
SRCH-2 가 "정당한 폐기인지 손실인지 이 회차만으로 못 가른다"고 남긴 것의
정체가 이것이다. **정당한 폐기가 아니라 손실이었다.**

"우천 취소 보도 없음"·"연투 기록 없음"은 갈림길을 실제로 가르는 답이다.
$0.12 를 쓰고 받아서 버렸다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "parse_answers\|websearch\." app/ tools/
app/collectors/websearch.py   (자기 자신)
app/engine/gather.py:  from app.collectors import websearch
                       jobs = {websearch.SOURCE: websearch.ask(...)}
app/engine/triage.py:  from app.collectors.websearch import MAX_ASKS
$ grep -rn "_ask_pplx" app/
app/engine/deepsearch.py:1045  (정의)
app/engine/deepsearch.py:1233  reinforce — ORDER_V2 경로. 운영에서 꺼져 있다
```

`parse_answers` 를 읽는 운영 코드는 `websearch.ask` 하나다(+테스트).
`gate_rows` 는 **새 함수**이고 `parse_answers` 와 `gather.search` 둘이 쓴다.

⚠️ `_ask_pplx` 는 ORDER_V2 의 `reinforce` 도 부른다. **그쪽 동작을 바꾸지
   않는다** — 게이트는 `gather.search` 안에서 반환값에 거는 것이지
   `_ask_pplx` 를 고치는 것이 아니다.

## ② 만드는/바꾸는 상태

| 상태 | 성격 | 다른 곳이 다른 규칙으로 갱신하나 |
|---|---|---|
| `근거유형` (프롬프트 필드) | 새 응답 칸 | 아니다 |
| `ABSENCE = "부재확인"` (행의 `소스유형`) | 기존 칸에 새 값 | 🔴 아래 |
| `계측["부재"]` | 새 카운터 | 아니다 |
| `gate_rows()` | 새 함수 | `parse_answers` 가 **이것을 쓰도록 바꾼다** — 문을 하나로 |

🔴 **`소스유형` 에 `부재확인` 을 넣는 것이 이 수정의 위험이다.**
   기존 값은 `공식|기록|뉴스` 이고, 판정 프롬프트는 그 문자열을 그대로
   읽는다(`verdict.fmt_kept` 가 `[출처]` 로 싣는다). 새 값이 섞이면
   판정이 "부재확인"을 **출처 이름으로** 읽게 된다.
   → 그게 **의도**다. 판정이 "기사로 확인된 사실"과 "찾아봤는데 없더라"를
     구분해야 한다. 구분 없이 섞는 쪽이 더 나쁘다.
   ⚠️ 다만 이 값이 카드 문구로 새면 안 된다. 카드는 `order_v3` 를 읽지
     `소스유형` 을 읽지 않으므로 경로가 없다 — 확인함.

## ③ 리그·종목·경로 분기

**생기지 않는다.** `gather.search` 는 종목 공통이고 두 채널 다 공통이다.

⚠️ 퍼플렉시티 스위치(`DEEPSEARCH_PPLX_ENABLED`)는 운영에서 **0** 이다.
   즉 배선해도 켜기 전까지 도는 채널은 Anthropic 하나다. 그 사실을
   여기 적어 둔다 — "붙였으니 돈다"고 읽으면 안 된다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **`부재확인` 으로 날짜 게이트를 우회한다** ← 가장 큰 반대 위험 | 긍정 주장(`근거유형` 미지정·`기사`)은 **여전히 날짜 필수**. 계약으로 단언. `부재` 를 따로 세어 남용을 잰다 |
| 부재확인이 "출처"로 둔갑해 판정이 사실로 읽는다 | 행의 `소스유형` 을 **`부재확인` 으로 덮어쓴다** — 모델이 `뉴스` 라 적어도 바뀐다(계약) |
| 게이트가 두 벌이 되어 한쪽만 고쳐진다 | `parse_answers` 가 `gate_rows` 를 **쓰도록** 바꾸고, 그 사실을 계약으로 단언 |
| 퍼플렉시티 행이 게이트를 안 지난다 | `gather.search` 의 pplx 갈래가 `gate_rows` 를 통과시키는지 단언 |
| 한 채널이 죽으면 둘 다 죽는다 | 이미 `asyncio.gather(return_exceptions=True)`. 계약 추가 |
| 퍼플렉시티가 꺼져 있는데 "붙였다"로 보인다 | `_ask_pplx` 가 스위치를 보고 빈손을 돌려준다(기존 동작). 로그에 채널별 건수가 남는다 |

🔴 **아직 못 재는 것**: 부재확인 답이 판정을 실제로 돕는가.
   이번 합격 기준은 "버리지 않는다 · 구분해서 싣는다"까지다.

## ⑤ 이미 있는 사실을 다시 적는가

- 게이트 규칙(`MAX_AGE_DAYS`·날짜 파서)은 `websearch` 한 곳. 퍼플렉시티는
  **그 함수를 부른다** — 규칙을 옮겨 적지 않는다.
- 퍼플렉시티 질문 프롬프트(`REINFORCE_ASK`)와 스위치는 `deepsearch`·`config`
  가 원본. 새로 만들지 않고 `_ask_pplx` 를 그대로 부른다.
- 질문 상한은 여전히 `websearch.MAX_ASKS` 하나.
