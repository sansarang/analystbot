# U9 — 시장 흐름 완성. 4분류 → 5분류 · 북 불일치 · 라인 환산

## 왜

```
재현 5건:
  steam 이 없다 — 4분류다: ['contra','money','news','none']
  book_disagree(북별 확률 SD > 2%p)가 없다
  라인 이동 환산(0.5=4%p · 1.0=8%p)이 없다 — U2 가 파생 시장을 저장하기
    시작했는데 읽는 규칙이 없다
  adj_confirm 플래그가 없다
  원장에 market_flow 칸이 없다
```
`steam`(3북 이상이 같은 방향으로 크게)을 `money` 와 구분 못 하면 **여러 북이
동시에 움직인 것**과 **한 북이 흔들린 것**이 같은 신호가 된다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
odds_move.classify · confirm · cancels · BASELINE_ORDER · MOVE_MIN_PP
  ← pick_ledger.record_move (유일 호출부)
  ← observer.py (move_class == "contra")
  ← scheduler 트리거(이름표)
odds_snapshots.market='spreads'|'totals'  ← U2 가 저장하기 시작했다
원장 move_class · move_reason             ← 기존 칸
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **`classify` 반환 계약을 깨지 않는다.** `Move(label, move_pp, reason)`
  그대로이고 `steam` 은 라벨 하나가 느는 것이다. `observer` 가 `"contra"` 를
  문자열로 비교하므로 **기존 라벨 값을 바꾸지 않는다.**
- 🔴 `steam` 은 **북 수를 아는 경우에만** 나온다. 모르면 종전대로 `money` 다 —
  없는 정보로 더 센 라벨을 붙이지 않는다.
- 🔴 `steam` 이 **뉴스 반대 방향**이면 `contra` 다(지시문 4-4). 순서를 뒤집으면
  취소 신호가 묻힌다.
- 🔴 라인 환산은 **핸디 라인**에만 쓴다. 토탈(U/O)에 같은 계수를 쓰면 의미가
  다르다 — 계약이 핸디만 받는 것을 본다.
- ⚠️ `book_disagree` 는 **표시**다. 확률을 바꾸지 않는다.

## ③ 되돌리기

커밋 1개 revert + `ALTER TABLE pick_ledger DROP COLUMN market_flow`.
`BASELINE_ORDER`·기존 4라벨은 건드리지 않았으므로 이동 분석이 종전으로 돌아간다.
