# MKT-4 — **요구 확률(1/배당)이 없다.** "값이 있나"를 못 답한다

## 왜

사용자가 준 목표 분석(2026-09-17):
> "마진 제거 시 KIA 62.3% — 내 판정 63%와 0.7%p 차로 **완전 동의**입니다.
> **문제는 가격: KIA 1.49는 요구 확률 67.1%라 내 63%로는 값이 없고**"

**두 숫자가 다른 일을 한다:**
```
디빅 확률 62.3%   → **방향**이 맞나   (우리 63% ≈ 시장 → 동의)
요구 확률 67.1%   → **값**이 있나     (1/1.49 · 마진 포함 · 우리 63% < 67.1% → 없다)
```

우리는 앞만 있다:
```
market_edge.implied_probs   ✅ 디빅
market_edge.classify        ✅ divergence_pp (우리 − 디빅)
요구 확률 · 가격 대비 엣지    🔴 없다
```
그래서 **"방향은 맞지만 가격이 엣지를 다 먹었다"를 코드가 말할 수 없다.**
지금 게이트는 `divergence_pp`(방향)만 보고 값을 안 본다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
market_edge.break_even       ← 신규. 1/배당
market_edge.price_edge_pp    ← 신규. (우리 − 요구) %p
market_edge.implied_probs    ← 그대로. **디빅은 다른 일이다**
market_edge.classify         ← **안 건드린다.** 게이트 동작을 안 바꾼다
pick_ledger.record_confirm_and_analysis ← blk 에 싣는다(odds 는 원장에 있다)
analyze.build_input          ← 숫자 줄에 요구 확률·가격 엣지
analyze.l1 숫자 검사          ← 입력 숫자가 늘어 인용 허용 범위가 는다(의도)
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **게이트·추천을 안 바꾼다.** `classify`·`gate` 는 그대로다 — 이 단위는
  **숫자를 만들어 보여줄 뿐**이다. 값으로 픽을 거르는 것은 별도 결정이다.
  계약이 `classify` 불변을 잰다.
- 🔴 **디빅과 섞지 않는다.** 요구 확률은 **마진 포함**이고 디빅은 제거한 값이다.
  둘을 한 이름으로 부르면 다시는 못 가른다.
- 🔴 **배당이 없으면 None.** 0 이나 0.5 로 채우지 않는다 — 야구는 1북이고
  그마저 없는 경기가 있다.
- 🔴 **1.0 이하 배당은 None.** `_implied_prob` 와 같은 규약(사본 금지 —
  그 함수를 쓴다).
- ⚠️ `l1` 의 숫자 검사 기준이 넓어진다 — 입력에 요구 확률이 들어가므로 모델이
  그것을 인용해도 통과한다. ANL-5·ANL-9 와 같은 판단이다.

## ③ 되돌리기

커밋 1개 revert. 함수 둘 · blk 두 칸 · 렌더 한 줄.

## ④ 측정

①과 **같은 명령**이 통과한다:
```
break_even(1.49) = 0.6711
price_edge_pp(0.63, 1.49) = -4.1   → 값 없음
```
그리고 오늘 밤 경기에 돌려 숫자 줄이 들어가는지 본다(⑨).

## ⑤ 계약

10건 — 요구 확률 계산 · 가격 엣지 부호 · 배당 없으면 None · 1.0 이하 None ·
디빅과 다른 값이다 · 입력 블록에 들어간다 · 없으면 줄이 안 난다 ·
**classify 불변** · `_implied_prob` 재사용 · 목표 분석 숫자 재현(1.49 → 67.1%).
