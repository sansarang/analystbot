# EXP-4 영향 지도 — 회수 파일 이름이 서버와 충돌한다

## 1. 무엇이 틀렸나 (재현 원문)

EXP-3 은 로컬에 같은 이름이 있으면 `_r2` 로 늘렸다. 그런데 **서버도** 재실행 때
`_r2` 를 붙인다(`for_fable.out_path`). 두 `_r2` 의 뜻이 다르다 —
로컬은 "두 번째로 받은 것", 서버는 "두 번째로 만든 것".

실측으로 잡았다. 로컬 `2026-09-19_mlb_slate_lineup_r2.md` 를 읽고 결장 표기가
옛 형식이라고 판단했는데, 서버 원본은 새 형식이었다:

```
로컬 _lineup_r2.md :  - 결장 홈 3명(confirmed) / 원정 10명(confirmed)
서버 _lineup_r2.md :  - 결장 홈 3명(IL 2 · 라인업제외 1)(confirmed) / 원정 10명(IL 6 · 라인업제외 4)(confirmed)
```

로컬 `_r2` 는 서버 `_lineup.md` 의 사본이었다. **같은 이름이 다른 내용을
가리켰고, 나는 그것을 읽고 잘못된 결론을 냈다.**

```
$ PYTHONPATH=. uv run pytest tests/export/test_exp4_pull_naming.py -q -x   exit=1
```

## 2. 어디를 고치나

`tools/pull_export.sh` 의 이름 결정부 한 군데.

## 3. 영향 지도 5문

**① 왜 서버 이름을 그대로 쓰나.**
산출물의 신원은 서버가 정한다. 받는 쪽이 이름을 바꾸면 그 순간 **대조할 수 없는
사본**이 된다. 지금 사고가 정확히 그것이었다.

**② 그러면 겹칠 때는.**
내용이 같으면 **받지 않는다**(같은 파일 두 벌은 어느 쪽이 최신인지 사람이
알 수 없게 만든다). 내용이 다르면 **서버 파일의 수정 시각**을 붙인다 —
`..._lineup_r2__1108.md` 처럼. 시각은 서버가 가진 사실이라 번호와 달리
어느 실행에서 나온 것인지 되짚을 수 있다.

**③ 비교를 어떻게 하나.**
바이트 비교(`cmp`)다. 해시를 따로 구하면 원격에서 한 번 더 읽어야 한다 —
어차피 받아서 비교하는 것이 요청 수가 같고 더 확실하다.

**④ 무엇이 조용히 0이 되나.**
"건너뜀"과 "실패"가 섞이면 안 된다. 건너뛴 것은 건너뛴 것으로 세고, 받은 것 +
건너뛴 것이 목록 수와 같은지 마지막 줄에 찍는다. 0건이면 여전히 1로 나간다.

**⑤ 기존 로컬 파일은.**
건드리지 않는다. 이번 사고로 만들어진 잘못된 `_r2` 세 개만 지웠고, 그 사실을
커밋 메시지에 적는다.

## 4. 안 하는 것

- 서버 쪽 `_r2` 규칙은 건드리지 않는다 — 거기서는 "덮지 않는다"가 맞다.
- 자동 회수를 만들지 않는다.
