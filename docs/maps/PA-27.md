# PA-27 — 딥서치 결장 명단이 **판정으로 돌아가지 않는다** (지시문 7단계)

## 왜

지시문 7단계: "추출된 결장 명단을 5단계 원장의 **결장 변수로 재계산**(LLM 이
문장으로 반영하는 게 아니라 **코드가 delta 를 다시 매김**). 재계산 후 gap
재판정. 등급이 바뀌면 원장에 `regraded_by=deepsearch` 기록."

실측 ①:
```
· 원장에 regraded_by 칸이 없다
· rejudge.reweigh 를 **부르는** 코드가 app/ 전체에 0건 — 만들어 놓고 안 이었다
· 확인 결과가 adj_after 로 재계산되지 않는다
```
딥서치가 결장자를 찾아내도 확률이 **1%p 도 안 움직였다.**
"만들고 안 이었다"의 **아홉 번째**다(analyze · gate.select · U9 · U10 ·
book_gap · 예산 · adj_confirm · velo_drop 에 이어).

## ① 이 함수/상태를 읽는 곳 **전부**

```
pick_ledger.record_confirm_and_analysis   ← 잇는 곳 (U12 · 게이트 대상만)
rejudge.reweigh                           ← 부르는 대상 (순수 함수, 호출 0건이었다)
scout_config.EXTRACT_SCHEMA["out"]        ← 결장 명단 칸의 **원본**
pick_ledger._REJUDGE_SAVE                 ← 새 저장 SQL
pick_ledger.REGRADE_DEEPSEARCH            ← 출처 상수
db/schema.sql: adj_after · p_code_after · grade_after (U11, 비어 있었다)
db/schema.sql: regraded_by (신규)
`*_after` 칸을 읽는 곳                     ← **0건** (카드·발송 모두 안 읽는다)
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **저장 전용이다. 원래 값을 덮지 않는다.** `p_code`·`confidence`·`adj_pp`
  는 그대로 두고 `*_after` 에만 쓴다 — 덮으면 "판정이 어떻게 바뀌었나"를
  잃는다. 계약이 `SET` 절을 읽어 잰다.
- 🔴 **발송·카드를 건드리지 않는다.** PA-14 와 같은 순서다 — 먼저 값을 쌓고
  표를 봐야 교체가 옳은지 안다.
- 🔴 **게이트 대상(OVER·DOUBT)만.** 전 경기에 돌면 무료 한도가 터진다 —
  기존 함수의 조기 반환을 그대로 쓴다(새 게이트를 만들지 않는다).
- 🔴 **실패해도 분석을 막지 않는다** — CLV·이동과 같은 규약. 계약이
  `reweigh` 를 일부러 터뜨려 잰다.
- 🔴 **결장자가 없으면 아무것도 안 쓴다.** 빈 값을 쓰면 "안 봤다"와 "없다"가
  같아진다.
- 🔴 **칸 이름을 손으로 안 적는다.** `out` 은 `EXTRACT_SCHEMA` 의 키다.
- ⚠️ **선수 시장가치가 없다.** 추출은 이름만 준다 — `importance` 가 1.0
  중립이고 한 명당 1.5%p 로 세어진다. **가치를 지어내지 않는다.**
- ⚠️ **축 이름이 `라인업결장` 으로 찍힌다**(`reweigh` 의 `KEY_OUT`). 출처가
  T-60 라인업이 아니라 딥서치라는 것은 `regraded_by` 가 말한다. 이름을 새로
  만들면 원장에 뜻이 둘 생긴다 — 만들지 않았다.
- ⚠️ **권위 문제는 남는다.** `주전결장` 은 오늘 타순 전체를 세고 딥서치 `out`
  은 기사에 나온 이름만 센다. PA-27-b 규칙대로 뒤가 앞을 **대체**하는데,
  기사가 일부만 말하면 덜 세게 된다. `*_after` 를 아무도 안 읽으므로 지금은
  해가 없고, **표를 보고 결정할 일**이다(사용자 몫).

## ③ 되돌리기

커밋 1개 revert. `regraded_by` 칸은 `IF NOT EXISTS` 라 남아도 무해하다.
