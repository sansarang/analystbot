# DS-1S — 런타임을 공유한다 (영향 지도 5문)

## ① 🔴 내가 DS-1W(`55b46de`)에서 만든 결함이다

`_fetch_article_body` 가 호출마다 `Runtime()` 을 새로 만든다. 도메인 상태
(마지막 요청 시각 · 일일 카운터 · 서킷 · robots 캐시)가 **인스턴스 안에**
있으므로 매번 초기화된다.

실측 2026-09-21 (같은 도메인 3회 요청):
```
호출마다 새 인스턴스   대기 **0회**   · robots 재조회 **6회**
인스턴스 공유         대기 2회(2초씩) · robots 재조회 4회
```

🔴 **두 가지가 동시에 나쁘다:**
1. 간격·일일 상한·서킷이 **전혀 안 걸린다** — 런타임을 만든 이유가 사라진다.
2. **요청이 2배가 된다** — 매 요청마다 robots.txt 를 다시 받는다.
   robots 를 지키겠다고 만든 것이 남의 서버에 요청을 늘린 꼴이다.

| 파일 | 무엇 |
|---|---|
| `app/deepsearch/runtime.py` | `default_runtime()` — **이벤트 루프별** 하나 |

| `app/deepsearch/search.py` · `watch.py` | 기본값을 `default_runtime()` 으로 |

## ④ ⚠️ 왜 단순 싱글턴이 아닌가

`asyncio.Semaphore` 는 **처음 쓸 때 실행 중인 루프에 묶인다.** 모듈 수준
싱글턴 하나를 두면 루프가 바뀌는 자리(테스트 · `asyncio.run` 여러 번)에서
`got Future attached to a different loop` 가 난다.
→ **실행 중인 루프별로** 하나를 둔다. 루프가 없으면 그때만 새로 만든다.

## ⑤ 되돌릴 수 있나

함수 하나 추가 + 기본값 교체다. 스위치를 두지 않았다 — "예절을 끄는 스위치"는
두면 안 된다.
