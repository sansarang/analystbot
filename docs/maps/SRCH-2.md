# SRCH-2 — Anthropic 웹 검색 채널. 날짜는 코드가 검사한다.

사용자 지시 2026-09-12: "x seach 삭제....그자리에 안트로픽 서치로" ·
"퍼플릭스와 안트로픽" · "경기당 1회 질문 3개로 해라"

## 왜 — SRCH-1 실측이 남긴 숙제

게이트 없이 던진 같은 질문에서 **인용까지 붙은 오답**이 나왔다.

```
질문   "삼성 구자욱의 최근 결장 사유가 부상인가 컨디션 관리인가"
답     "좌측 가슴뼈 미세골절 — 2루 슬라이딩 역동작"   ← 2026년 4월 기사
실제   훈련 중 등 담 증세로 긴급 제외 (2026-09-12) · 김헌곤 9번 좌익수
```

날짜를 박으니 **정답 3/3**, 비용은 $0.098 → $0.102 로 거의 그대로였다.
그러나 같은 날 `grok-4.20` 은 "2026-09-10 이후만"이라는 지시를 받고도
**9월 8일 기사를 근거일자로 적었다.** → 프롬프트는 부탁이고, **코드가 검사**한다.

## ① 이 함수/상태를 읽는 곳 **전부**

**새 모듈이다. 지금 읽는 곳은 0 이다.**

```
$ grep -rn "websearch" app/ tools/ tests/
tests/test_websearch.py   (SRCH-2 가 방금 쓴 계약)
```

배선은 **SRCH-3 이 한다**(2단계 선별 → 검색 → 3단계 판정). SRCH-2 는 모듈과 계약만
만들고 **아무도 부르지 않는 상태로 끝난다** — 그 사실을 여기 적어 둔다.
"만들었는데 안 불린다"는 이 저장소가 이미 당한 결함이다(PGP-2: 존재하는 것과
불리는 것은 다르다). SRCH-3 의 합격 기준에 **호출 여부 계약**을 넣는다.

빌려 쓰는 원본 — 새로 만들지 않는다:
| 무엇 | 원본 |
|---|---|
| 행 모양 `{질문,답,소스,소스유형,시점,계정,url}` | `engine/gather._row` (계약 테스트가 대조) |
| 잔액 차단기 | `engine/credit_guard.trip_credit` |
| 오늘(KST) | `engine/deepsearch._today_kst` |
| Anthropic 호출 인자 | `engine/team_form.message_kwargs` (SDK 1.0 이 `temperature` 를 뺐다) |

## ② 만드는/바꾸는 상태

| 상태 | 성격 | 다른 곳이 갱신하나 |
|---|---|---|
| `WEBSEARCH_ENABLED` (env, 기본 False) | 새 스위치 | 아니다 |
| `websearch_model` (env, 기본 `claude-sonnet-5`) | 새 설정 | 아니다. `matchup_model` 과 **별개** |
| — | **DB·Redis 를 건드리지 않는다** | 캐시도 만들지 않는다 |

🔴 캐시를 일부러 안 만든다. 이 채널은 "오늘 바뀐 것"을 묻는 자리라 캐시가
   곧 **오래된 답**이다. 그게 정확히 이 수정이 막으려는 것이다.
   대신 호출 자체를 **SRCH-3 이 경기당 1회로 묶는다**.

⚠️ Anthropic 크레딧을 쓴다. `credit_guard` 는 **프로세스 안의 플래그**라
   재시작하면 풀린다(`api_guard.trip_credit` 의 영구 차단과 다르다 —
   `credit_guard.py` 머리말이 원본). 판정 경로와 같은 차단기를 공유한다.

## ③ 리그·종목·경로 분기

**생기지 않는다.** 질문 문자열만 받는다 — 종목을 모른다.
경기 이름·리그는 프롬프트에 넣지만 **분기하지 않는다**(한 경로).

⚠️ 언어: 질문은 들어온 그대로 던진다. ORD-8 의 "영어 우선 → 모국어" 규칙은
   **질문을 만드는 쪽(SRCH-3 의 triage)**의 몫이다. 여기서 번역하지 않는다 —
   두 곳에서 언어를 정하면 그게 사본이다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| **게이트가 멀쩡한 답을 버린다** ← 가장 큰 반대 위험 | 폐기를 **사유별로 세어 돌려주고** 로그에 남긴다. `{받음,채택,모름,폐기,폐기_오래됨,폐기_날짜없음,폐기_미래}` |
| 전량 폐기인데 "검색했다"로 보인다 | `받음`·`채택`을 따로 센다. 채택 0 도 숫자로 남는다 |
| 200 OK 산문이 재료 0을 만든다 | `parse_answers` 가 JSON 이 아니면 `받음=0`. 전례가 있다 |
| "모름"을 폐기로 세어 게이트를 억울하게 만든다 | **`모름` 은 폐기가 아니다.** 별도 칸 |
| 모델이 번호를 지어내 엉뚱한 질문에 붙는다 | 범위 밖 번호는 `질문=""`. 창작보다 공란이 낫다 |
| 만들어 놓고 아무도 안 부른다 | **SRCH-2 의 알려진 상태다.** SRCH-3 계약이 호출을 못 박는다 |
| 비용이 새는데 모른다 | 호출마다 입력·출력·검색수·$ 를 한 줄로. x_search 가 그래서 숨었다 |

🔴 **허용 범위 3일의 근거는 약하다.** "오늘 바뀐 것"을 묻는 자리라 짧아야
   한다는 것 말고 실측이 없다. 상수로 빼고(`MAX_AGE_DAYS`), 폐기 사유별
   집계가 쌓이면 조정한다. **지금 이 값이 정답이라고 주장하지 않는다.**

## ⑤ 이미 있는 사실을 다시 적는가

- 행 모양·오늘(KST)·차단기·호출 인자는 위 표대로 **원본을 부른다**.
- 단가($2/$10 per MTok · 검색 $10/1,000)는 **외부 사실**이라 원본이 우리
  코드에 없다. 한 곳(`PRICE_*`)에만 적고 **출처 URL 과 확인 날짜**를 붙인다.
  계약 테스트가 그 둘의 존재를 검사한다.
- 질문 상한 3은 사용자 결정이다. `MAX_ASKS` 한 곳에 두고 **API 의
  `max_uses` 가 같은 상수를 쓴다** — 프롬프트에 숫자를 또 적지 않는다.
