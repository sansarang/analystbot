# BUD-1 영향 지도 — 검색 예산이 뒤 경기를 굶겼다 (STEP 1-a)

## 0. 재현 (실측 2026-09-20 KBO 5경기 · 슬레이트 예산 10)

```
[flow:n05] game=1763 캐시 결장 6건 · 요청 3개 → evidence 2건
[flow:n05] game=1767 캐시 결장 3건 · 요청 3개 → evidence 2건
[flow:n05] game=1765 캐시 결장 3건 · 슬레이트 예산 소진 — 나머지는 미상 · 요청 6개 → evidence 2건
[flow:n05] game=1766 캐시 결장 3건 · 슬레이트 예산 소진 — 나머지는 미상 · 요청 6개 → evidence 0건
[flow]     슬레이트 5경기 … (예산 10/10)
```

두산@KT(g1766)는 **`캐시 결장 3건` 이 손에 있었는데** 한 변수도 열지 못했다.
"여섯 변수 전부 미상"은 자료가 없어서가 아니라 **예산이 없어서**였다.

## 1. 원인 — 예산을 쓸 자리가 아니다

`n05_evidence.py:354` 가 변수 루프 **맨 앞**에서 `ctx.take_search(1)` 을 부른다.
그런데 이 노드에는 **기사 fetch 가 없다.** 바깥 호출 전수:

```
:88   await ctx.redis.get(f"analysis:{sport}:{day}")   판정 캐시 읽기
:138  await read_extract(ctx.redis, …)                 위성 추출 읽기
:236  await ctx.pool.fetchrow(…)                       DB
:249  await ctx.pool.fetch(_STARTER3_SQL, …)           DB
:287  await ctx.pool.fetch(_BULLPEN_SQL, …)            DB
:308  await ctx.pool.fetch(_LAST3_SQL, …)              DB
```

`httpx`·`aiohttp`·`requests` **0건.** 기사를 긁는 것은 별도 잡
`satellite_15m` 이고 ⑤는 그 결과를 **읽기만** 한다.

→ **기사 예산을 읽기에 쓰고 있었다.** 지시문 STEP 1-a 의 "예산은 기사 fetch
에만 차감. DB·공식 API 조회는 0" 이 정확히 이 자리다.

## 2. 영향 지도 5문

**① 어디를 고치나.** `app/flow/nodes/n05_evidence.py` 한 파일.
변수 루프의 `take_search(1)` 을 **뺀다.** `Ctx.take_search` 자체는 남긴다 —
기사 수집이 ⑤에 붙을 때(STEP 7-4) 그 자리에서 쓴다.

**② 경기당 상한(`per_game_cap`)은 어떻게 하나.**
남긴다. 그것은 예산이 아니라 **증거 행 수 상한**이고, 6변수 경기에서 5행까지만
만드는 것은 카드 길이 문제다. ⚠️ 다만 이제 상한에 걸려도 **앞 경기 때문에**
걸리는 일은 없다.

**③ "경기별 예약"(지시문 1-a 후반)은 왜 지금 안 하나.**
🔴 예약은 **기사 fetch 가 ⑤에 있을 때** 의미가 있다. 지금 ⑤는 한 건도 긁지
않으므로 예약 구조를 만들면 **쓰이지 않는 코드**가 된다 — 이 저장소가 반복해
겪은 "만들어 놓고 안 이음" 이다. 기사 수집이 들어오는 **STEP 7-4 에서**
`select.py`(STEP 6)의 depth 와 함께 만든다. 여기서는 그 사실을 적고 넘긴다.

**④ 무엇이 깨질 수 있나.**
⑤가 여는 변수가 늘어 **DB 질의가 는다**(경기당 최대 6 → 현재도 같음, 다만
뒤 경기가 이제 실제로 돈다). 슬레이트 32경기면 질의가 늘지만 전부 인덱스
조회다. 🔴 반대 위험은 **없다** — 굶던 것을 안 굶기는 방향뿐이고, 없는 자료를
만들어내지 않는다(증거는 여전히 소스가 있을 때만 생긴다).

**⑤ 틀렸을 때 알려줄 테스트.**
`tests/pipeline/test_bud1_search_budget.py` 3건 —
(a) ⑤에 기사 fetch 가 **생기지 않았는가**(생기면 예산을 다시 걸어야 한다),
(b) ⑤ 본문이 예산을 차감하지 않는가,
(c) **예산을 0 으로 묶어도** DB·캐시 변수가 나오는가.

## 3. 넘기는 것

- **STEP 7-4** 기사 수집이 ⑤에 붙을 때 `take_search` 를 **그 자리에서만** 쓰고,
  STEP 6 `select.py` 의 depth(shallow 0 · normal 2 · deep 5)로 **경기별 예약**을
  한다. 남은 예약은 다른 경기로 넘기지 않는다.
