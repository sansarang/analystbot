# SOC-8 — Flashscore 라인업(층1). 킥오프 1시간 전에 전 경기 제공.

사용자 지시 2026-09-12: "라인업은 굳이 딥서치 안해도 된다 .. 공식 url 에서
한시간 전에 모두 제공한다" → "flashscore 써라"

## 왜

판정 서술이 매 경기 "확정 선발 라인업을 확인하지 못했다"고 쓴다. 검색으로
걸린 라인업 기사는 경기마다 올 수도 안 올 수도 있다.

실측 2026-09-12 23:30 (운영):
```
피드            global.flashscore.ninja/2/x/feed  (x-fsign: SW9D1eZo) · 당일 3166경기
경기 매칭        우리 31경기 → FS 31건 · 실패 0   (양 팀 슬러그 + 킥오프 ±1시간)
라인업 제공      킥오프 1시간 안 13경기 = 포메이션·선발 수신 / 먼 경기 = 0명
구조            LB÷선발/교체/감독 · LC÷1|2(홈/원정) · LH÷순번 · LI÷이름 · LJ÷등번호
```

⚠️ **첫 시도에서 내가 틀렸다.** `NU÷` 슬러그만 정규식으로 긁어 "남의 팀 선수가
섞였다"고 보고했는데, 그 목록은 **알파벳순**이었다(블록과 무관하게 긁은 탓).
그리고 낯선 이름을 내 기억으로 "다른 팀"이라 단정했다 — 2026 이적을 모른다.
→ **블록 단위로 파싱하고, 선수 소속은 피드의 구조로만 정한다.**

## ① 이 함수/상태를 읽는 곳 **전부**

```
새 모듈 app/collectors/flashscore.py  — 읽는 곳은 satellite_soccer 하나
satellite_soccer.gather_soccer        — 층1 부상표 옆에 나란히 붙는다
```
빌려 쓰는 원본: `satellite._article`(기사 모양) · `satellite_soccer.tm_key`(팀 정규화)

## ② 만드는/바꾸는 상태

| 상태 | 성격 | 비고 |
|---|---|---|
| `flashscore.parse_fixtures/parse_lineup` | 새 순수 함수 | 시험 가능하게 HTTP 와 분리 |
| `_FS_CACHE` | 당일 피드 캐시 | 슬레이트당 1회 |
| 기사 `age_h` | `0.0` | 층1 규약(SAT-S4)과 같다 |

🔴 **경기 매칭은 양 팀 + 시각 3중 조건이다.** 한쪽만 맞으면 버린다 —
   남의 경기 라인업을 붙이는 것은 빈손보다 나쁘다(SAT-S4 AC밀란 전례).

## ③ 리그·종목 분기

없음. 축구 전용 모듈이고 리그 구분 없이 경기 id 로만 움직인다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **남의 경기/팀 명단을 붙인다** | 양 팀+시각 3중 매칭 · 홈/원정을 `LC÷` 로만 가른다. 계약 |
| 🔴 이름과 등번호가 어긋난다 | **블록 단위** 파싱(한 블록 = 한 선수). 계약이 뒤섞인 입력으로 단언 |
| 킥오프 전이라 빈손인데 "없다"고 단정 | 0명이면 **기사를 만들지 않는다**. 계약 |
| 피드가 죽어 위성이 통째로 실패 | try/except + 경고 1줄. 뉴스·부상표는 그대로 |
| 응답 로케일이 바뀌어 섹션명이 달라진다 | 섹션은 **순서**(첫 그룹=선발)로 가른다. 러시아어 문자열에 의존하지 않는다 |

⚠️ 못 잰 것: 킥오프 60~90분 전 구간에서 몇 %가 채워지는가. 다음 슬레이트에서 잰다.

## ⑤ 사본

- 팀 정규화를 새로 만들지 않는다 — `tm_key`.
- 기사 모양을 새로 만들지 않는다 — `_article`.
