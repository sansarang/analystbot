# PA-2 — 판정이 났는데 "판정 0"으로 센다. 기준이 세 벌이다

## 왜

PART A 실측(2026-09-16 09:50 KST · 커밋 `9ca4ef8` · `ORDER_V3=1`):

```
[v3] Seattle Mariners@Los Angeles Angels 승자 Seattle Mariners · 확신 중 · 채택17
[v3] Miami Marlins@Arizona Diamondbacks  승자 Arizona Diamondbacks · 확신 중 · 채택19
같은 실행:
🔴 게이트·발송 0/2경기 — 데이터 없음 (판정 0 · 추천 0 · 예정 2)
원장:  8312 p_home 0.46 · 8313 p_home 0.52   ← 판정은 남아 있다
```

"판정이 있는가"가 저장소에 **세 벌** 있고 서로 다르다:

| 어디 | 규칙 | v3 경기 판정 |
|---|---|---|
| `pregame_push._judged` | `p_claude` 가 숫자인가 | **있음** ← 발송이 실제로 쓴다 |
| `matchup.has_verdict` | (위와 **본문까지 같은 사본**) | 있음 |
| `pipeline` 게이트·발송 집계 | `matchup.p_home` **그리고** `jg.model` | **없음** ← 혼자 다르다 |

v3 는 `matchup` 에 `p_home` 을 넣지 않고 `jg["model"]` 도 세팅하지 않는다
(`matchup.py:618` 은 승자·model 만 넣고, `jg["model"] = model` 은 v2 경로
751행만 한다). 그래서 파이프라인 집계만 0 으로 센다.

🔴 **결과: "봇이 죽었나"와 "판정이 없나"를 사람이 구분할 수 없다.** 발송 규율이
   "조용한 0은 결함이다"라고 적은 그 상황이다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
pregame_push._judged            ← 발송 경로가 쓴다. **이것이 사실상 원본**
matchup.has_verdict             ← 같은 본문의 사본. matchup.py:1297 이 쓴다
pipeline.py:2418~2432 인라인     ← 자기만의 규칙. 부를 수도 없다
pick_ledger._row_from_game      ← ORD-3: `p_home 또는 승자` — **다른 질문**이다
   (원장에 남길 판정인가 ≠ 발송할 판정인가. 여기서 합치지 않는다)
matchup.py:618 / :606           ← v3 가 matchup 을 만드는 곳
matchup.py:751                  ← v2 만 jg["model"] 을 세팅
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **발송 동작을 바꾸지 않는다.** 고치는 것은 **세는 방법**뿐이다.
  `_judged` 의 규칙 자체는 그대로 둔다 — 규칙을 바꾸면 카드가 달라진다.
- 🔴 **원장 기준(ORD-3)과 합치지 않는다.** "원장에 남길 판정"과 "발송할
  판정"은 다른 질문이다. ORD-3 는 승자만 있는 판정도 일부러 남긴다.
  합치면 확률 없는 판정이 발송 대상이 되거나, 반대로 원장이 비게 된다.
- 🔴 **사본을 하나로 줄인다** — `matchup.has_verdict` 가 공개 이름이므로
  그쪽을 원본으로 두고 `_judged` 가 위임한다. 두 곳에 같은 규칙을 두면
  한쪽이 바뀔 때 다른 쪽이 안 따라간다(실사고 2026-09-02).
- ⚠️ 집계가 달라지면 **알림도 달라진다** — 종전에는 매 슬레이트 🔴 가 떴다.
  고치면 정상 슬레이트에서 조용해진다. 그게 목적이다.
- ⚠️ `jg["model"]` 을 v3 에서도 세팅할지는 **이 단위에서 건드리지 않는다**
  (판정 경로 변경이다). 집계가 그것에 의존하지 않게 하는 것으로 충분하다.

## ③ 되돌리기

커밋 1개 revert. 바뀌는 것은 (a) `_judged` 가 위임하는 한 줄, (b) 파이프라인
집계가 공용 술어를 부르는 한 줄뿐이다. 발송·판정·원장 경로는 안 건드린다.
