# SEND-1 — 카드가 `p_code` 를 읽는다 (사용자 결정 B-1)

## 왜

`p_code` 는 원장에만 쌓이고 **사용자에게 가는 숫자에는 닿지 않았다.** 실측
2026-09-13 롯데@KT: 원장 `p_code = 0.6481`, 카드에 찍힌 건 **62%** — 서로 다른
숫자다. 카드는 제미나이 판정 확률을 쓴다.

사용자가 B-1(교체)을 택했다. 함께 정한 것 둘:
- **딥서치 이동을 `p_code` 에 더한다** — 호출 비용을 이미 썼으므로 버리지 않는다.
- **소비 지점에서 갈아끼운다** — 판정·딥서치 로직은 안 건드리고, 원장에는
  제미나이 확률·`p_code`·`p_model` 이 전부 남아 사후 대조가 된다.

## 조사로 확인한 순서 (이 수정의 전제)

```
2145  판정                 → matchup["p_home"] = 제미나이 확률
2963  _attach_market_spine → p_code = 시장 + Σadj      (딥서치 앞이다)
2167  딥서치 run_for_slate  → apply_findings 가 m["p_home"] 을 덮어쓴다
3776  p_final 블록          → 보드·자격 게이트가 쓰는 확률
5314  카드 렌더
5480  원장 기록
```
🔴 그래서 **`p_code` 를 판정 직후에 갈아끼우면 딥서치가 되돌린다.**
   갈아끼우는 자리는 딥서치 **뒤**여야 한다 → `p_final` 블록(3776).

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "favored_side_and_p" app/
app/engine/form_card.py   정의 · 카드 안 3회
   → 우세 %·별표·신호등·가치·추천/보드만 이 전부 이 함수에서 나온다

$ grep -rn "p_final\[" app/pipeline.py
   → markets 후보의 h2h `p` → 자격 게이트(승률 58%) → 보드 별점
```
🔴 **게이트가 둘이다** — 카드의 `추천/보드만`(favored_side_and_p)과 보드의
   `자격 통과`(p_final). 한쪽만 바꾸면 **한 카드가 두 말을 한다**
   (실사고 2026-09-05: "우리 53% — 시장 동의" 와 "시장 이견 47% vs 54%").
   그래서 **둘 다** 같은 값을 보게 한다.

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `prob.p_send(jg)` | 새 순수 함수. 시장+Σadj+딥서치, 절사 |
| `jg["p_send"]` | 새 키. `p_final` 블록에서 한 번 세운다 |
| `form_card.favored_side_and_p` | `p_send` 우선, 없으면 종전 |
| `p_final[home/away]` | h2h 는 `p_send` 로 덮는다 |
| 원장 `p_code` 칸 | **실제 나간 값**(`p_send`)을 적는다 |

🔴 **원장의 `p_home`(= `p_claude`)은 그대로 둔다.** 제미나이 확률이 사후
   대조의 재료다 — 여기까지 갈아끼우면 비교할 것이 사라진다. 계약이 잠근다.
🔴 **사용자에게 보이는 숫자가 바뀐다.** 오늘 슬레이트 기준 8경기 중 **2건에서
   승자가 뒤집히고**(NC@두산·LG@삼성), 자격 통과가 1건 → 3건이 된다.
⚠️ 새 컬럼을 만들지 않는다 — 기존 `p_code` 칸의 의미를 "실제 나간 값"으로 좁힌다.

## ③ 리그·종목·경로 분기

없다. `p_market_spine` 이 있는 경기만 갈아끼우고, 없으면 **종전 경로 그대로**다
(축구·배당 미수집 경기). 분기가 아니라 폴백이다.

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **카드와 보드가 다른 값** ← 2026-09-05 재발 | 두 자리 모두 `p_send` · 게이트에 `p_claude` 를 넘기던 자리 부재를 계약이 단언 |
| 🔴 원장이 제미나이 확률을 잃는다 | `p_home: jg.get("p_claude")` 존치를 계약이 단언 |
| 배당이 없는 경기가 조용히 0.5 | `p_market_spine` 이 없으면 **None** → 종전 값으로 폴백. 계약 |
| 딥서치가 확률을 크게 흔든다 | `ADJ_SUM_CAP`(±6%p) 안으로 절사. 계약 |
| 승률 상한(0.68)이 풀린다 | `cap_probability` 그대로. 계약 |
| 원정 우세에서 방향이 뒤집힌다 | `우세 == "away"` 면 `1−p`. 계약 |

⚠️ **아직 못 잰 것**: 어느 쪽이 더 맞는가. 과거 178경기 AUC(시장 0.64 vs 판정
   0.51)는 **위성·v3 이전**의 숫자다. 지금 제미나이와 대조한 적이 없다.
   원장에 둘이 나란히 쌓이므로 채점이 붙으면 며칠 안에 답이 나온다.
   **그때까지 이 교체는 되돌릴 수 있어야 한다** — 그래서 소비 지점만 건드린다.

## ⑤ 사본

조정 표·상한·승률 절사를 다시 적지 않는다 — `ADJ_RULES`·`ADJ_SUM_CAP`·
`cap_probability` 가 원본이다. 딥서치 이동값도 다시 계산하지 않고
`jg["deepsearch"]["이동_pp"]` 를 읽는다.
