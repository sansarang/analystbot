# U4 — 게이트 4분류. **코드는 이미 있었다. 계약이 없었다**

## 왜 — 그리고 내 감사표가 틀렸다

지시문은 "게이트가 3분류라 시장 없음/사전값 없음 경기가 동의로 섞인다"고
했고, 그 근거는 **내 감사표**였다. 다시 재보니 **틀렸다**:
```
app/engine/gate.py
  21: AGREE = "동의"      22: OVER = "시장 과대"
  23: DOUBT = "가치 의심"  24: BOARD = "보드 고정"      ← 있었다
```
감사할 때 21~23행만 grep 하고 24행을 놓쳤다. 실동작도 정확하다:
```
사전값 없음 → 보드 고정 · gap=None · "없는 것을 0 이나 0.5 로 읽지 않는다"
시장 없음   → 보드 고정
둘 다 없음  → 보드 고정
```

**그래서 U4 에서 코드를 더하지 않는다.** 없는 것은 **계약**이다 — U3 이
`p_prior=None` 을 만들기 시작했으므로, 그 None 이 보드 고정으로 간다는 사실을
잠그는 테스트가 필요하다. 지금은 `BOARD`·`보드 고정` 을 단언하는 테스트가
**저장소 전체에 0건**이다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
gate.classify   ← pick_ledger.record_prior (유일 호출부)
gate.BOARD      ← (계약 0건 — 이번에 붙인다)
gate.select     ← 예산 30%(2~8)
p_prior=None    ← U3 이 만든다 → classify(None, …) → BOARD
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **코드를 안 고친다.** 고칠 것이 없는데 손대면 그 자체가 위험이다.
  이번 U 는 계약만 더한다.
- ⚠️ U3 가 `record_prior` 에서 티어 미기입이면 **`classify` 를 부르기 전에**
  끝낸다(`return None`). 그러니 실제 운영에서 `classify(None, …)` 경로를 타는
  것은 **시장이 없을 때**다. 계약이 두 경로를 다 본다.

## ③ 되돌리기

계약 파일(`tests/test_u4_gate_board.py`) 1개를 지우면 끝난다. 운영 코드는
한 줄도 바뀌지 않았으므로 되돌릴 동작이 없다 — 이 U 의 산출물은 **잠금**이지
기능이 아니다. 스키마·설정·데이터 변경도 없다.
