# PRM-1 — 선발 등판 칸이 홈/원정만 적어 원정이 눈에 안 띈다

## 왜

실측 2026-09-13 (운영, Seattle Mariners @ Athletics, game 6003). 제미니가
"원정 선발 Bryan Woo의 최근 등판 기록이 확인되지 않았다"고 썼는데 **있었다**:

```
선발 최근 등판 원본 1331자 · ITEM_MAX 2600 · 잘림 없음
"away" 포함 True · 경기 10건(홈 5 + 원정 5)
DB본것 에 '선발 최근 등판' 을 적었다 — 보고도 홈만 읽었다
```

칸이 `{"home": {...}, "away": {...}}` 뿐이라 **블록 안에 어느 팀·어느 투수인지
없다.** 이름을 넣어 원정이 건너뛰어지지 않게 한다.

## ① 읽는 곳 전부
```
app/engine/dbref.py:35        ITEMS — 프롬프트 JSON
app/engine/matchup.py:867     또 다른 프롬프트 JSON
tests/test_lineup_season.py:202 · tests/test_matchup.py:454
```
넷 다 `out["home"]["선발등판"]` 모양에 의존한다 → **키를 바꾸지 않는다.**

## ② 상태
| 상태 | 성격 |
|---|---|
| `팀`·`선발` 키 추가 | **덧붙이기만** 한다 |
| `home`·`away`·`선발등판`·`구원등판` | 그대로 |

## ③ 분기
없음. 야구 전용 함수이고 종목 분기가 없다.

## ④ 조용히 실패하는가
| 위험 | 대응 |
|---|---|
| 🔴 읽는 넷 중 하나가 깨진다 | 기존 키 전수를 계약으로 고정 |
| 이름이 없는 경기에서 터진다 | 빈 문자열로 채운다. 계약 |
| 길이가 늘어 잘린다 | 1331 → 약 1400자, ITEM_MAX 2600 안. 여유 확인됨 |

⚠️ 못 잰 것: 이름을 붙이면 제미니가 원정을 읽는가. **재분석으로 잰다.**
   프롬프트 제시를 바꾸는 것이라 효과는 확률적이다 — 안 되면 그렇게 보고한다.

## ⑤ 사본
- 팀명을 새로 만들지 않는다 — `jg["home"]·["away"]` 그대로.
