# DEC-3 — 추출 조건 규칙 개정 (영향 지도 5문)

사용자 결정 2026-09-21: "결정 3: **규칙 개정으로 처리.** 새 계약 '관련 문단
≥1 일 때만 추출, 0 이면 `reason=no_relevant_paragraph` 로 미상'."

## ① DS-5 때와 무엇이 다른가

DS-5(커밋 `615a462`)에서 나는 **같은 변경을 만들었다가 되돌렸다.** 그때 적었다:

> "내 변경을 통과시키려고 계약 16개를 고치는 것은 **회귀를 숨기는 수**다."

🔴 **지금은 다르다. 사용자가 규칙을 바꾸기로 결정했다.**
   계약을 고치는 것이 아니라 **규칙이 바뀐 것**이고, 그 차이를 문서에 남긴다.

## ② 개정 전/후 — 운영 실측 (최근 2일 · 기사 있는 경기 11개)

```
전   LLM 호출 **11회**   ← 기사가 1건이라도 있으면 부른다
       그중 증거 문단 0 인 경기 **2**
후   LLM 호출  **9회**   (2회 절약 · 18%)
       미상 2경기 — 세이부@롯데(기사 6건) · 오릭스@니혼햄(기사 6건)
```

그 두 경기의 기사 6건에는 **그 경기 이야기가 아예 없었다**
(아시안게임 식사 문제 · 다른 팀 투수). 지금은 그 3,600자를 통째로 넣는다.

⚠️ 추출 **카드 수**는 전/후가 같다 — 그 두 경기는 전에도 쓸 만한 카드를
   못 만들었다(HYC-1 신뢰 관문이 근거 없는 카드를 이미 버린다).
   달라지는 것은 **호출 수**와 **사유의 이름**이다.

## ③ 🔴 깨지는 계약 — **실측 19건**(지시문은 16개라 했다)

임시로 개정안을 켜고 전체를 돌려 **정확히 무엇이 깨지는지** 셌다.
19건 중 **2건은 내가 이번에 쓴 새 테스트**이므로 기존 계약은 **17건**이다.
목록은 `docs/DEC3_CONTRACT_CHANGE_2026-09-21.md` 에 이전/새 의미와 함께 적는다.

## ④ 어디를 건드리나

| 파일 | 무엇 |
|---|---|
| `app/collectors/satellite.py` | 증거 0 → `{"reason": "no_relevant_paragraph"}` 반환 |
| `config/deepsearch.yaml` | `rerank.require_relevant` **스위치** |
| 기존 테스트 17건 | 새 규칙에 맞게 픽스처에 **증거를 넣는다** |

⚠️ 테스트를 **느슨하게 바꾸지 않는다.** 그 17건이 시험하던 것(호출 1회 ·
   캐시 · 등급 순 · JSON 정본 · 게이트 무관)은 **그대로 둔다.** 바꾸는 것은
   **픽스처의 본문**뿐이다 — 전에는 `"본문 1"` 같은 증거 없는 글이었다.

## ⑤ 되돌릴 수 있나

`config/deepsearch.yaml` 의 `rerank.require_relevant: false` 한 줄.
배포 없이 종전 규칙으로 돌아간다. 계약이 그것을 확인한다.

## ⑥ 틀렸을 때 누가 알려주나

계약 5건: 증거 0 이면 호출 0 인가 · **사유가 이름으로 남나**(`articles` 수도
함께) · 증거가 있으면 전과 같이 부르나 · 스위치를 끄면 종전인가 ·
**문서에 17건 목록과 이전/새 의미가 있나**.
