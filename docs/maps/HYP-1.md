# HYP-1 — **가설이 수집을 지휘하지 않는다** (페이블 순서의 핵심)

## 왜

`hypothesis.py` 머리말이 스스로 적었다:
> 🔴 **이것이 페이블 순서의 핵심이다.** 지금까지는 수집이 need 와 무관하게
> 전부 돌았고, 그래서 S6(확인 판정)이 "무엇을 확인해야 하는가"를 몰랐고
> S9(구조 픽)가 "무엇이 충족됐나"로 고를 수 없었다.
> 게이트가 방향을 정하고, **방향이 need 를 정한다.**

실측 2026-09-17 — **그 배선이 통째로 없다:**
```
hypothesis.need_keys()       운영 호출 0건 (테스트만)
satellite.apply_need()       운영 호출 0건 (테스트만)
extract_game_facts(need=…)   인자는 있는데 **본문에서 안 쓴다**
유일한 운영 호출부(:842)      need 를 안 넘긴다
_DUE_SQL                     hypothesis 칸을 안 읽는다
```
그 함수 머리말이 예고까지 해 뒀다 — *"`need` 를 못 받으면 종전대로 전부 쓴다.
need 가 빈 목록인 것과 **안 받은 것**은 다르다."* 지금이 "안 받은 것"이다.

가설은 만들어져 원장에 저장까지 된다(오늘 13/13). **수집만 그것을 안 본다.**

## 🔴 설계 결정 — `apply_need`(칸 비우기)는 **안 잇는다**

U6 의 `apply_need` 는 need 밖 칸을 `None` 으로 만든다. 그런데:
- `confirm` 은 need 칸만 읽으므로 **판정 결과가 안 바뀐다**(무의미)
- `record_confirm_and_analysis` → `blk["home_facts"]` → 분석 프롬프트는
  **바뀐다** — `notes` 가 need 에 없어서 **오늘 ANL-5 로 넣은
  "고종욱 1군 말소."가 다시 사라진다.**

→ **지휘는 "무엇을 찾을지 말해 주는 것"이지 "찾은 것을 버리는 것"이 아니다.**
   need 를 **추출 프롬프트에 넣어** 방향을 주고, 뽑힌 사실은 그대로 둔다.
   `apply_need` 는 그대로 둔다(나중에 필요하면 그때 결정).

## ① 이 함수/상태를 읽는 곳 **전부**

```
satellite._DUE_SQL            ← l.hypothesis 를 함께 읽는다
satellite.run(루프)            ← jg["hypothesis"] 로 싣는다 (gate_label 과 같은 방식)
satellite.gather              ← need_keys 를 만들어 넘긴다
satellite.extract_game_facts  ← need 를 **프롬프트로** 넘긴다
satellite._extract_prompt     ← "우선 이 칸" 한 줄
hypothesis.need_keys / Need.key ← 키 모양의 **원본**. 손으로 안 적는다
satellite.apply_need          ← **안 건드린다**(위 결정)
```

## ② 깨뜨릴 수 있는 기존 동작

- 🔴 **가설이 없으면 종전 그대로다.** 판정 전 경기·보드 고정·옛 행에서
  `hypothesis` 가 비면 `need=None` 이고 프롬프트도 종전과 **글자 하나 안 다르다.**
  계약이 잰다.
- 🔴 **뽑힌 사실을 버리지 않는다.** 스키마 8칸은 그대로 다 돌려받는다 —
  ANL-5 가 넣은 `notes`·`doubt` 가 살아 있어야 한다. 계약이 잰다.
- 🔴 **키 모양을 손으로 안 적는다.** `"home.out"` 은 `Need.key` 가 원본이다.
- 🔴 **`.get` 으로 읽는다.** 스키마 미적용 컨테이너·옛 가짜 행에서 KeyError 로
  수집 사이클이 통째로 죽지 않게(gate_label 이 같은 이유로 그렇게 한다).
- 🔴 **LLM 콜 수가 안 는다.** 프롬프트에 한 줄 더할 뿐이다.
- ⚠️ 추출 캐시 키는 URL 묶음 해시다 — need 가 바뀌어도 같은 URL 이면 다시
  안 묻는다. **이번에는 안 건드린다**(콜이 늘어난다). 그래서 need 의 효과는
  **새 URL 묶음이 생길 때부터** 나타난다. 그 사실을 로그로 남긴다.
