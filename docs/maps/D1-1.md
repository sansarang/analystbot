# D1-1 — 북별 배당 저장 + sharp_proxy (Phase D1 착수, 사용자 지시)

## 왜

"시장 과대"를 사설 배당 **한 곳**만 보고 판단하고 있었다. 오즈포털 응답에는
**북별 값이 이미 들어 있다**(실측 2026-09-14):
```
"positionsWithProviders":{"0":{"549":{"odds":[5.25],"highestPayout":94.4},
                               "851":{"odds":[5.25],"highestPayout":95},
                               "1133":{"odds":[5.4], "highestPayout":92.9},
                               "1205":{"odds":[5],   "highestPayout":92.3}}, …}
avgOdds 5.23 · cntActive 4 · maxOddsProviderId 1133
JS 전용 아님(__NEXT_DATA__·hydration 표식 없음)
```
그런데 우리는 **평균 한 줄**(`book='oddsportal-avg'`)만 저장하고 있었다.

🔴 **피나클을 이름으로 특정할 수 없다.** 북메이커 페이지를 1회 크롤했으나
   id↔이름 표가 없었다(이름은 링크 슬러그에만, "Pinnacle" 문자열 0건).
   그래서 사용자 지시대로 **`sharp_proxy`** 를 쓴다 — 그 스냅샷에서
   `highestPayout`(환급률)이 가장 높은 id. **피나클이라 단정하지 않는다.**

재현:
```
PYTHONPATH=. .venv/bin/python <scratchpad>/repro_d1.py
  → ImportError: cannot import name 'parse_books'
```

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "parse_odds\|to_rows\|store_rows" app/ tests/
app/collectors/oddsportal.py      parse_odds · to_rows (정의)
app/collectors/odds_free.py       collect(야구) · collect_soccer(축구) — 둘 다 호출
tests/test_oddsportal*.py         계약
```
🔴 **야구 경로가 같은 함수를 쓴다.** `three_way` 기본값이 False 인 것처럼,
   북별 파싱도 **추가**이고 기존 반환은 건드리지 않는다. `to_rows` 의
   `books` 인자는 선택이라 안 넘기면 종전과 같은 한 줄이 나온다.

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `odds_snapshots` 행 | **행이 는다.** `book='op-{id}'` 북별 + `'sharp_proxy'` + 기존 `'oddsportal-avg'` |

컬럼은 만들지 않는다 — `book` 컬럼이 이미 있다(실측).
요청 수는 **늘지 않는다**(같은 응답을 더 파싱할 뿐, 문서 예산과 일치).

🔴 **평균 줄을 지우지 않는다**(사용자 지시 — 비교용).
🔴 **활성 북이 3 미만이면 `sharp_proxy` 를 만들지 않는다**(표본 부족).
   없는 것을 만들지 않는다는 이 저장소 규칙과 같다.

## ③ 리그·종목·경로 분기가 생기는가

생기지 않는다. 야구(2-way)·축구(3-way) 모두 같은 파서를 쓰고,
`three_way` 가 칸 수를 정한다(기존 규약 그대로).

## ④ 실패하면 "시끄럽게" 실패하는가

- 북별 블록이 없으면 `books` 가 비고, 그때는 **평균 줄만** 저장된다 —
  종전 동작이라 회귀가 아니다. 건수는 수집 로그에 그대로 남는다.
- `sharp_proxy` 가 안 서면(활성 북 < 3) 그 사실이 로그에 남는다.
  NULL 을 평균으로 대체하지 않는다(문서의 "하지 말 것").

## ⑤ 시스템에 이미 있는 사실을 다시 적고 있지 않은가

- 결과 위치(0=홈·1=무·2=원정)는 `parse_odds` 가 이미 정한 관례를 따른다.
  두 벌로 적지 않고 같은 규칙을 쓴다.
- 마진 제거(디빅)는 `market_edge.implied_probs` 원본이 할 일이다 — 이
  단위는 **저장까지**다.
