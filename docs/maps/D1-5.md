# D1-5 — ESPN 축구 배당(DraftKings) · 게이트 대상만 (사용자 지시)

## 왜

축구 사설 값이 없어 `pinnacle_gap` 이 NULL 이었다. 사용자가 ESPN 축구를
허용했고, **어느 주소가 열리는지는 실측으로 갈렸다**:
```
site.api.espn.com/apis/site/v2/... → 403 Access Denied (ita.1·esp.1·eng.1)
sports.core.api.espn.com/v2/...    → 200
   events?dates=20260914  → 3경기
   events/{id}            → competitions[0].odds.$ref
   .../odds               → DraftKings(id 100) home -500 · away 1100 · draw 500
                            Bet 365(id 2000) 은 fractional
   경기당 요청 2 (events 목록은 리그·날짜당 1회로 상각)
```

🔴 **ESPN 축구는 미국식 배당만 준다.** 야구는 `moneyLine.decimal` 이 오는데
   축구는 `moneyLine: -500` 뿐이다. 기존 `_decimal` 은 "미국식에서 환산하지
   않는다"가 규약이라 축구에서는 늘 None 이다 — 그래서 **축구 전용 파서**를
   따로 둔다. 야구 경로는 건드리지 않는다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
app/collectors/espn_odds.py   parse_odds(야구) · _decimal · is_live_book · started
app/collectors/odds_free.py   야구 수집 경로가 espn 을 부른다
```
새 함수(`parse_soccer_odds`·`fetch_soccer`)의 호출부는 **이번에 만들지
않는다** — 예산 규칙(게이트 대상만)을 지키려면 "게이트 대상"을 넘겨줄 쪽이
정해져야 하고, 그 자리는 배당 스냅샷 잡이다(다음 단위).

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `odds_snapshots` `book='draftkings'` (축구) | 행이 는다. 야구와 **같은 이름** |

새 컬럼 없다. `pinnacle_gap_dk` 는 계산값이라 `book_gap` 이 돌려준다.

🔴 **예산**: 게이트 대상(슬레이트 30%)만. 경기당 스냅샷 5시점 × 1~2 =
   **최대 10요청**. 게이트 밖 경기는 **안 친다** — 함수가 `only_names` 를
   받고, 비면 **아무 요청도 하지 않는다**.

## ③ 리그·종목·경로 분기가 생기는가

생긴다. 축구는 **미국식 환산 + 무승부 칸**이 있고 야구는 아니다.
리그 코드는 사용자가 준 여덟(eng.1 esp.1 ita.1 ger.1 fra.1 ned.1 kor.1 jpn.1).

## ④ 실패하면 "시끄럽게" 실패하는가

- 라이브 북은 기존 `is_live_book` 으로 **버린다**(실사고 이력: 7:0 앞선
  경기의 라이브 배당이 섞였다).
- 환산 불가·칸 없음은 **행을 만들지 않는다**. 0 으로 채우지 않는다.
- 요청 수를 로그에 찍는다 — 예산이 지켜지는지 다음 사이클에서 바로 보인다.

## ⑤ 시스템에 이미 있는 사실을 다시 적고 있지 않은가

- UA·타임아웃·라이브 판정·시작 여부는 `espn_odds` 의 기존 것을 쓴다.
- 적재는 `odds_free.store_rows` 원본.
