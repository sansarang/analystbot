# EXT-1 — 추출을 경기당 1콜로 (창 ±300자 + URL 해시 캐시). 사용자 지시

## 왜

groq 무료 한도가 저녁마다 걸린다(실측 2026-09-14: `429` 백오프 340·382·467초).
원인은 호출 수와 입력 크기다 — 추출이 **팀별 기사 3건 = 경기당 6콜**이었고
기사 **전문 4000자**를 넣었다. 같은 URL 을 다시 열어도 매번 다시 물었다.

사용자 지시: 경기당 1콜 · 관련 문단 ±300자 창 · URL 해시 캐시. (그 뒤에
로컬 llama.cpp 사슬을 올린다 — 입력이 작아야 CPU 추론이 현실적이다.)

재현:
```
PYTHONPATH=. .venv/bin/python <scratchpad>/repro_ext1.py
  → AttributeError: module 'app.collectors.satellite' has no attribute 'extract_game_facts'
```

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "extract_facts\|extract_game_facts" app/ tests/
app/collectors/satellite.py  정의 + gather (유일한 호출부)
tests/test_scout_extract.py  계약
```
`extract_facts`(팀 단위)는 **사라지고** `extract_game_facts`(경기 단위)가 됐다.
호출부가 한 곳뿐이라 서명 교체가 안전하다.

## ② 만드는/바꾸는 상태

| 무엇 | 성격 |
|---|---|
| Redis `scout:x:{sha1(url묶음+두 팀)[:16]}` | **새 키.** 추출 결과 캐시, TTL 은 기존 `CACHE_TTL` |

`scout:{sport}:{game_id}`(경기별 결과)와 **다른 키**다 — 하나는 "이 경기의
사실", 하나는 "이 기사 묶음에 대한 답"이다. 기사 묶음이 바뀌면 키가 바뀌고
자동으로 다시 묻는다.

## ③ 리그·종목·경로 분기가 생기는가

**생기지 않는다.** 축구만 추출하는 것은 그대로다(SCT-5). 창을 잡는 단서는
팀 이름 + 만국 공통 표기(`out·injur·infortun·formazion·lineup·결장…`)이고,
리그별 현지어 목록을 새로 만들지 않았다 — 그건 `search_terms` 의 일이다.

## ④ 실패하면 "시끄럽게" 실패하는가

- 본문 있는 기사가 없으면 부르지 않고 그 사실을 남긴다.
- 창이 비면 **머리 600자**를 준다 — 빈손으로 부르면 "읽었는데 없다"와
  "안 읽었다"가 같아진다.
- 성공하면 한 줄: `추출 1콜 — 기사 N건 · 창 M자 · 홈 out X · 원정 out Y`.
  호출 수·입력 크기가 로그에 남아야 이 단위의 효과를 다음에 잴 수 있다.
- 캐시 적중도 로그로 남긴다(`캐시 적중(scout:x:…), 묻지 않는다`).

🔴 **반대 위험**: 창을 좁혀 결장 문단을 놓칠 수 있다. 그래서 단서를 팀 이름
**과** 공통 표기 양쪽으로 잡고, 겹치는 창은 합친다. 효과는 `out` 건수로
바로 드러난다(전: 토리노 5 · 로마 0).

## ⑤ 시스템에 이미 있는 사실을 다시 적고 있지 않은가

- 스키마·상한(3건)·등급·검증·병합 전부 `scout_config` 원본.
- TTL·캐시 키 형식은 위성의 기존 상수를 따른다.
- 무료 사슬은 `judge_route.chain("form")` — 모델 목록을 여기 적지 않는다.
