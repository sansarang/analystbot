# ADJ-4 — 주전결장을 `lineup_events` 에 배선한다. 포지션은 떼고 읽는다.

## 왜 (실측 2026-09-13)

가장 센 조정 변수(−1.5/명, 상한 ±5%p)가 **9/9 경기 미계산**이었다.
원인은 셋이고 전부 잰 것이다:

**① 타순이 그 테이블에 없다.**
```
lineups 최근 5일   mlb 8·68·38·24·76 · soccer 19·19 · npb 2(어제) · kbo ─ 전무
lineup_events      kbo 매일 8행/4경기 · npb 8~12행 · mlb 4~47행   ← 여기 있다
```
`games.lineup_status = 'confirmed'` 는 찍히는데 본문은 `lineup_events` 에 간다.

**② 팀이 아니라 `side` 로 조회했다.**
```sql
WHERE l.side = $1 ... AND (g.home = $4 OR g.away = $4)
```
우리 팀이 **원정이었던 경기의 `side='home'` 행**은 상대 팀 라인업이다.
주전 집계에 상대 선수가 절반쯤 섞여 들어간다. `lineup_events.team` 으로 바꾼다.

**③ 포지션이 붙어 있다.** 원소가 `"양의지(포수)"` 형태다. 실측:
```
포지션이 2가지 이상인 선수   KBO 48/161 (30%) · NPB 38/211 (18%)
7회 이상 선발(주전 판정)      원문 67명 → 이름만 78명   (11명이 분산으로 누락)
예: 양의지 → [양의지(포수), 양의지(지명타자)] · 坂倉 将吾 → [(一), (三)]
```
🔴 **반대 위험이 여기 있다.** 안 떼면 오늘 포지션이 바뀐 주전이
   **결장으로 오인**된다 — 멀쩡한 팀에 −1.5%p 씩 벌점이 붙는다.

## ① 이 함수/상태를 읽는 곳 **전부**

```
$ grep -rn "_REGULARS\|_TODAY_ORDER\|out_starters" app/
app/engine/adjust.py   정의 · attach 안 각 1회        ← 유일한 사용처
app/engine/prob.py     ADJ_RULES[*]["주전결장"] = ("out_starters", -1.5, ±5)
                       → adjustments() 가 jg["out_starters"] 를 읽는다
app/engine/adjust.py   out_starters_away              ← **아무도 안 읽는다**(죽은 키)
```
`lineup_events` 를 읽는 다른 곳은 이 수정과 무관하다(쓰기만 한다).

## ② 만드는/바꾸는 상태

| 상태 | 성격 |
|---|---|
| `_REGULARS` · `_TODAY_ORDER` | 대상 테이블 `lineups` → `lineup_events`, 조회키 `side` → `team` |
| `_arr` | 포지션 접미사 제거 |
| `jg["out_starters"]` | `max(0, h−a)` → **부호 있는 `h−a`** |
| `out_starters_away` | **삭제**(죽은 키) |

🔴 **`out_starters` 부호를 여는 것은 ADJ-3 과 같은 결함이다.** 안 열면 원정
   결장이 영원히 0 이라 **변수가 반쪽만 산다** — 배선의 일부로 함께 고친다.
   상한 양쪽 절사는 ADJ-3 에서 이미 열렸다.
⚠️ `gate()` 는 그대로 `games.lineup_status == confirmed` 를 본다. 바꾸지 않는다.
⚠️ 새 테이블·새 컬럼을 만들지 않는다. 이미 쌓이는 것을 읽을 뿐이다.

## ③ 리그·종목·경로 분기

없다. `lineup_events` 는 종목 구분 없이 같은 모양이다(kbo·npb·mlb 실측).
축구는 `ADJ_RULES["soccer"]["주전결장"]` 을 쓰는데 `lineup_events` 에 축구
행이 없다 → 종전처럼 미계산으로 남는다(퇴행 아님).

## ④ 조용히 실패하는가

| 위험 | 대응 |
|---|---|
| 🔴 **포지션 변경을 결장으로 오인** ← 가장 큰 반대 위험 | `_arr` 접미사 제거 + "포지션 바뀐 주전은 결장 아님" 계약 |
| 🔴 상대 팀 라인업이 주전에 섞인다 | 가짜 풀이 **팀 인자**로 다른 타순을 준다. 홈 2명 결장이 정확히 잡히는지 단언 |
| 옛 테이블을 계속 읽는다 | 실행된 SQL 에 `lineup_events` 포함을 단언(문자열이 아니라 **실제 넘어간 쿼리**) |
| 원정 결장이 0 으로 죽는다 | `out_starters == -3` · 조정 `+4.5` 단언 |
| 죽은 키가 남는다 | `out_starters_away is None` 단언 |
| 오늘 타순이 없는데 0 으로 센다 | `count_out` 의 None 경로 유지(기존 계약) |

⚠️ **아직 못 잰 것**: 실제 슬레이트에서 결장이 몇 명이나 잡히는가.
   오늘은 0/9 였다(미계산). 배포 후 첫 사이클에서
   `adj_inputs.주전결장` 분포를 본다 — **0 이 아니라 실수가 나와야 한다.**
⚠️ 이름 표기가 날마다 흔들리면(별명·한자/가나) 여전히 오탐이 난다.
   14일 표본에서는 팀별 이름 집합이 안정적이었으나 장기 관찰이 필요하다.

## ⑤ 사본

주전 창(10경기)·기준(7선발)을 다시 적지 않는다 — `ADJ_DEFS` 가 원본이다.
상태 상수도 손으로 적지 않는다.
