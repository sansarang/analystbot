**축구는 v3 경로를 타지 않는다.** 구 Judge 와 `soccer_trial` 둘 다 꺼져 있다.

### 🔴 코드가 꼬이는 자리 — 여기가 핵심

v3 엔진은 **모양은 공통인데 내용이 야구 전용**이다. 그대로 축구를 끼우면
`if sport == "soccer"` 분기가 엔진 전체에 번진다.

| 자리 | 지금 (야구 전용) | 축구에 필요한 것 |
|---|---|---|
| `gather.collect` 의 `jobs` | `satellite` · `라인업`(크롤러) · `크롤러`(불펜) | 라인업 소스가 다르고 **불펜이 없다** |
| `gather._bullpen` | `pitcher_appearances` | 축구엔 해당 없음 |
| `gather._lineup` | 크롤러 스냅샷 `lineup_home/away` | 축구 라인업 소스 미정 |
| `dbref.ITEMS` 9종 | 전부 `matchup.*_payload` (선발등판·타순·불펜) | 부상/출전정지·최근 폼·일정 밀집·홈원정 |
| `prompts.TRIAGE`·`JUDGE2` | "선발투수·타순·불펜·이닝" 어휘 | 축구 어휘 |
| `verdict` | 2-way 승자 | **3-way (승/무/패)** ← 가장 큰 구조 차이 |

⚠️ **3-way 가 진짜 난점이다.** `verdict.decide` 는 `승자` 한 팀을 받는다.
   무승부를 어떻게 낼지는 **설계 결정**이고, 야구 코드를 건드리지 않고
   확장할 수 있는지가 갈린다.

### 권장 순서 (제안이지 결정이 아니다)

1. **분류 먼저** — 종목별로 달라지는 것을 `registry.py` **표**로 뺀다
   (수집 채널 목록 · DB 항목 목록 · 프롬프트 어휘). 그러면 축구는
   **새 행**이지 새 분기가 아니다.
2. 그 표로 **야구가 그대로 도는지** 먼저 확인한다(회귀 0).
3. 축구 행을 채운다.
4. 3-way 를 어떻게 낼지 별도 수정 단위로.
