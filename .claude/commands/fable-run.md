`docs/fable/inbox/` 의 지시문을 **파일명 순으로** 실행한다.
지시문 하나 = 보고서 하나 (`docs/fable/reports/<이름>_report.md`).

## 규율

- CLAUDE.md 전부 + 지시문 본문. 둘이 충돌하면 **멈추고 묻는다.**
- 🔴 **갈림길이면 고르지 않는다.** 두 갈래로 갈리면 `docs/fable/questions/<날짜>_<주제>.md`
  에 질문을 쓰고 **그 자리에서 종료**한다. 추측으로 고른 것은 측정이 아니라 취향이다.
- 🔴 **완료 조건 원문 없이 다음 지시문으로 가지 않는다.** 보고서의
  `## 완료 조건 원문` 절에 지시문 문장을 **그대로** 옮긴다. 요약하면 기준이 사라진다.
- 커밋 전 `contract-reviewer` 에이전트 PASS 필수. FAIL 이면 커밋하지 않는다.
- 배포 창·발송·컨테이너 쓰기·force push 는 훅이 막는다. **우회하지 않는다.**

## 순서

1. `ls docs/fable/inbox/*.md` — 없으면 "미처리 없음"으로 끝낸다.
2. 첫 파일을 읽는다. 지시문이 인용한 **코드·행 번호를 먼저 대조한다**
   (CLAUDE.md ⚠️추측 금지). 어긋나면 고치기 전에 보고한다.
3. 3파일 이상을 건드리면 계획을 먼저 말한다.
4. 구현 → 계약 테스트 → 전체 스위트 → `contract-reviewer` → 커밋.
5. 보고서를 `docs/fable/reports/<이름>_report.md` 에 **다섯 절 형식**으로 쓴다
   (형식 원본: `docs/fable/README.md` · 계약: `tests/meta/test_fable_report_format.py`).
6. 지시문을 `docs/fable/done/` 으로 옮긴다.
7. 다음 파일로. 갈림길에서 멈췄으면 옮기지 **않는다**.

## 하지 말 것

- inbox 밖에서 받은 지시문을 바로 실행하지 않는다 — 먼저 파일로 저장한다.
- 보고서에 "완료"를 쓰려면 증거 3요소(테스트 수치·실행 시각·커밋 해시)가 있어야 한다.
